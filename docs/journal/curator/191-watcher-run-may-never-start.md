## 1. Самопропуск круга ревью мерится на merge-ref, а НЕ на голове PR

**Замер, 2026-09-14.** Метка `review` на #413 была перевешена на ту же голову
`80b8f39f2674afc75cf2ca6ed67e7950ba4c3e2f` (голова не двигалась — сверено до и после). Круг
[`34836883802`](https://github.com/language-learning-ecosystem-lle/agent-crew-orchestrator/actions/runs/34836883802)
кончился `completed/success` за **40 секунд** против обычных 4–5 минут, `verdict.md` не создан, все
три доставки погасли. Предупреждение прогона дословно: `Skipping action due to workflow validation:
… identical content to the version on the repository's default branch`.

Три `rev-parse` называют причину точно:

```
claude-review.yml, блоб:
  origin/main (970957c3)            d7c5c84aa870c2754968adea99a4eb918dcaa561
  refs/pull/413/merge               37770131d0a70820515d26aa2dfbcf969fdeb6d0   ← ИМ шёл прогон
  refs/pull/413/head  (80b8f39f)    0f98404d09ee2955d289798710872f86874b71b1
```

`refs/pull/413/merge` собран в `09:21:47Z` против базы `c21c1940f` (это #418). После него в `main`
сели пять коммитов, среди них #417 (`efd461c2f`, `10:53:38Z`), правивший ровно `claude-review.yml`.
**GitHub merge-ref с тех пор не пересобрал.** Гард действия против промпт-инъекции увидел
расхождение и самопропустился; круг зелен, вердикта нет.

**Что здесь ново по сравнению с уже известным.** Что раннер для `pull_request` берёт воркфлоу с
merge-ref, я вывела раньше (msg-013) и назвала выводом, а не замером. Круг его подтвердил, но убил
следствие, которое я из него вывела: «кнопка на #417/#418 разблокирует ВСЮ стоячую очередь,
достаточно перевесить метку». **merge-ref ОТСТАЁТ:** он пересобирается на движение ГОЛОВЫ PR, а не
на каждый merge в `main`. Перевешивание метки на стоячем PR поднимает круг СО СТАРЫМ воркфлоу.

**Подтверждение механизма — прямое, а не по намерению.** После `git merge origin/main` в ветку
(рука `dev-core`, голова `80b8f39f` → `b36abc10`) merge-ref пересобрался:
`b849218a4ffd7cfc770e13ab47d14d8a1c8a607c`, родители `970957c3` (текущий `main`) + `b36abc10`, блоб
`claude-review.yml` = `d7c5c84a` — тождествен `main`. Следующий круг (`34837984835`) прошёл
настоящим и дал вердикт.

**Цена ошибки измерена: один круг (~$1) без вердикта плюс такт.** Даровая проверка ПЕРЕД меткой,
одна команда на PR:

```
git rev-parse refs/pull/<N>/merge:.github/workflows/claude-review.yml
git rev-parse origin/main:.github/workflows/claude-review.yml
```

Совпали — метку вешать можно. Не совпали — сперва двигать голову (`git merge origin/main` в ветку,
push выходит fast-forward, force не нужен). Второй даровой признак, уже постфактум: **длительность
круга** — 40 с против 4–5 минут.

**Класс шире #413.** На 14.09 блоб расходится с `main` у #410, #406, #388, #411 — #417 сел позже их
утренних кругов. Вешать им метку вслепую значит купить ещё три-четыре пустых круга; каждый из них —
долг своего треда (`197`, `180`, `155`), не тихий хвост этого.

**Шагом маршрута это пока НЕ объявлено.** Обязательная проверка перед меткой — новый шаг, то есть
норма, а норма — слово john; здесь она записана как замер и как моя практика.

## 2. Нота двери о переезде базы гасится ЗАМЕРОМ, а не ребейзом — и пустого пересечения файлов мало

`merge-gate` печатает ноту, когда база уехала после старта зачтённых чеков. На #413 она стояла:
8 коммитов, `6312dfbf..970957c3`. Чем я её гасила:

1. **пересечение файловых множеств** PR и базы — пустое;
2. **целость слияния:** `git merge-tree --write-tree origin/main 80b8f39f` → exit 0, дерево
   `a13d532dc2fe462fc1faf595d26fae1a01b30cf9`; `git diff --name-status origin/main <дерево>` — ровно
   один путь PR, удалений ноль;
3. **и этого НЕ ХВАТИЛО.** `notifier-watch.yml` — ВХОД трёх сканирующих тестов, читающих
   `.github/workflows/**` текстом (`roles/workflow-run-names.test.ts`,
   `roles/standing-address.test.ts`, `roles/workflow-signatures.test.ts`). «Дифф только
   комментарный» в таком классе от прогона не освобождает: пустое пересечение имён файлов говорит о
   конфликте слияния, а не о поведении тестов. Прогон на СЛИТОМ дереве (стенд — `git diff --binary
   origin/main <дерево> | git apply --index` в своём чекауте, `TMPDIR=/tmp pnpm --filter
   agent-protocol exec vitest run` трёх файлов) → 3 файла / 17 тестов, ноль красных, 344 мс; возврат
   `git reset --hard HEAD`, контрольный `git status --porcelain` пуст;
4. **отдельный класс — «база тронула воркфлоу ЗАЧТЁННОГО прогона»** — проверен и не применился:
   `git log 6312dfbf..origin/main -- .github/workflows/checks.yml` пуст.

Вывод: переезд базы инертен ЗАМЕРЕНО. Полную сюиту не гоняла и называю это прямо — перекрыт ровно
стык сканирующих тестов. Нормой протокола это не объявлено: в `PROTOCOL.md` о движении базы нет ни
слова, и это моя практика, а не правило.

## 3. Записанный предел живёт в трёх местах, и находит их греп ОБЕЩАНИЯ, а не файла

Постановка называла ОДНО место записи — шапку воркфлоу. Сколько мест повторяют само обещание, не
мерил никто, пока `dev-core` в такте приёмки не грепнул обещание: нашлись ещё два — таблица почтовых
воркфлоу в корневом `README.md` (безусловное «отказ любого из четырёх уведомителей звонит письмом»
на первой странице репозитория) и `docs/install-notes.md` §2 («класс молчания закрыт не
внимательностью, а событием»). Первое погашено #428 рукой `dev-core`, второе — этим же PR моей
рукой, вместе с записью-ссылкой в `docs/protocol-reference.md`.

**Правило, меняющее поведение роли на приёмке:** записала предел обещания — грепни САМО ОБЕЩАНИЕ, а
не файл, который правился. Дешевле всего это стоит в такте приёмки: дифф уже смёржен, критерий
формулируется одной строкой грепа, а цена пропуска — первая страница репозитория, продолжающая
обещать ровно ту безусловность, ложность которой тред и доказал.
