# Круг ревью самопропустился на PR, который правит ДРУГОЙ воркфлоу: гард меряет один файл, а прописанное лечение читает каталог

**Тред:** `191-watcher-run-may-never-start`. **Дата:** 2026-09-14. **Предмет:** PR #413 (запись
предела гарантии в шапке `notifier-watch.yml`).

Находка родилась не в предмете треда, а на его доставке: #413 нёс запись и стоял под кнопкой john,
а круг ревью на нём не состоялся дважды подряд по двум РАЗНЫМ причинам. Вторая из них и есть запись.

## Что случилось

Круг `34836883802` (голова `80b8f39f`, событие `pull_request`) закончился **зелёным** за **40 секунд**
и не создал `verdict.md` — погасли разом все три доставки. Причина названа предупреждением самого
прогона, дословно:

```
##[warning]Skipping action due to workflow validation: Workflow validation failed. The workflow
file must exist and have identical content to the version on the repository's default branch.
```

То есть `claude-code-action` пропустил сам себя — гард против промпт-инъекции правкой воркфлоу.
Класс известен и записан раньше; новым здесь оказалось **опознание случая**.

## Почему прописанное лечение увело бы в ложную сторону

Коммент ревьюера называет два исхода: «подтянуть `main` и повесить метку заново; **если воркфлоу
правит сам этот PR — ревью человеческое**». Проверка, которой этот выбор делается по памяти роли, —
дифф от базы слияния по каталогу:

```
git diff --name-only $(git merge-base origin/main 80b8f39f) 80b8f39f -- .github/workflows/
→ .github/workflows/notifier-watch.yml
```

**Не пуст.** Прочитанное буквально, это «PR правит воркфлоу» → человеческое ревью навсегда, потому
что версии не совпадут до merge по построению. И это неверно: **гард сверяет ОДИН файл —
`claude-review.yml`, а не каталог `.github/workflows/`.** #413 правит `notifier-watch.yml` и
`claude-review.yml` не трогает вовсе.

Прямой замер — тождество блоба, и он говорит обратное:

| ревизия | блоб `claude-review.yml` |
| --- | --- |
| голова `80b8f39f` | `0f98404d` |
| `origin/main` | `d7c5c84a` |

Ветка просто ОТСТАЛА: под ней сели два PR, правивших этот файл, — #418 (`09:21:40Z`, блоб
`37770131`) и #417 (`10:53:38Z`, блоб `d7c5c84a`). Лечение — влитие `main`, а не человеческое ревью.

## Что сделано

`git merge origin/main` в ветку + ff-push (без force, номер PR цел): `80b8f39f` → `b36abc10`, блоб
`claude-review.yml` стал `d7c5c84a` с обеих сторон. Слияние чистое, вклад цел — проверено патчем
вклада против КАЖДОГО родителя, а не диффом деревьев:

- против `80b8f39f` — пусто (вклад не тронут);
- против `970957c3` (`main`) — `42 0` по `notifier-watch.yml`.

Все три машинные посылки шапки #413 перемерены против НОВОЙ базы и уцелели: ровно один путь в
`git diff --name-only origin/main`, `--numstat 42 0` (удалений ноль), `yaml.safe_load` головы равен
`yaml.safe_load` `origin/main`. Тело PR править не пришлось — и это само по себе доказательство, что
влитие базы написанного о базе не обнулило.

Метка `review` снята: голова уехала, и доставленный 13.09 `approve` ею осиротел. Вешать заново — по
зелёному `checks` на `b36abc10`, не раньше.

## Правило, которое отсюда следует

Случай «ветка отстала» от случая «PR правит воркфлоу» различается **блобом `claude-review.yml`**, и
только им:

```
git rev-parse <голова>:.github/workflows/claude-review.yml
git rev-parse origin/main:.github/workflows/claude-review.yml
```

Разошлись → спрашивать, трогает ли ЭТОТ PR ИМЕННО `claude-review.yml`
(`git diff --name-only $(git merge-base origin/main <голова>) <голова> -- .github/workflows/claude-review.yml`).
Пусто → отстал, влить `main`. Не пусто → ревью человеческое. Эвристика по КАТАЛОГУ
`.github/workflows/` не годится ни в одну сторону: на #413 она дала ложное «правит».

Второе следствие, и оно про порядок: **перевешивание метки на стоящей голове этот класс не лечит** —
гард сработает снова, голова обязана двинуться. Это прямо противоположно указанию, действовавшему в
треде до сих пор («головы должны стоять смирно, достаточно перевесить метку»): оно верно для
красноты от запасной учётки и НЕВЕРНО для самопропуска по валидации воркфлоу. Две разные болезни с
одним симптомом «одобрен, но вердикта нет».

## Названное неизвестным

Модель «блоб разошёлся → самопропуск» **не объясняет одно наблюдение**, и я его не сглаживаю:
круги на #388 (`34828011351`, `09:26:59Z`, 5 мин 33 с), #411 (`34829936500`, 5 мин 17 с) и #410
(`34830276558`, 4 мин 21 с) шли ПОЛНУЮ длительность, то есть настоящими, хотя блоб их голов и тогда
не был равен блобу `main`. Длительность круга — первый признак самопропуска (40 с против 4–5 мин), и
по нему те круги самопропуском не были.

Значит критерий гарда мной измерен НЕ полностью: возможно, сверяется содержимое ref'а слияния, а не
чекаута ветки, и тогда решает, правит ли файл сам PR, а не отстала ли ветка. Замер #413 этим не
отменяется — предупреждение прогона названо дословно, влитие `main` его сняло, — но **вывод «любая
отставшая ветка самопропустится» из него не следует, и переносить его на #406/#410/#411/#388 без
их собственного замера нельзя.** Проверяется даром: первым же кругом на каждой из тех голов.

## Почему запись едет своим PR

Исключение из правила «запись едет попутным диффом той работы, из которой родилась» (карточка роли),
и причина называется вслух: работа, из которой запись родилась, — это #413, а вся его доказательная
сила держится на посылке **«ровно один изменённый путь, `42 0`, разобранный YAML равен»**, записанной
в теле PR и перемеренной дверью. Второй путь в том же диффе эту посылку уничтожает — и уничтожает её
у PR, который стои́т под кнопкой john по гарду 4 с уже потраченным кругом ревью. Дифф этой записи
целиком журнальный, круга не требует (слово john 2026-09-11, тред `187`), и кнопка на нём — curator.
