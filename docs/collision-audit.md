# Замер столкновений — сколько раз две работы контура реально помешали друг другу

Замер по треду `074-parallelism-and-domains` (постановка curator по слову john 2026-09-02, msg-002:
«пока что просто нужен замер»). Считает `scripts/collision-audit.mjs`; повторить — той же командой:

```
git fetch origin '+refs/pull/*/head:refs/remotes/pull/*'
node scripts/collision-audit.mjs --repo <корень репозитория> --since 2026-08-18
```

**Что этой командой НЕ считается — и это граница, а не пробел.** Скрипт читает `git`, `gh` и
`.orchestrator/journal.jsonl`. Всё, что взято из ЛЕНТ СЕССИЙ (строки `listen EINVAL` ниже —
классы 4), считается отдельным грепом по корпусу лент, и скрипт о нём не знает вовсе; метод назван
поимённо в разделе «Поимённо: общее рабочее место». Ленты лежат вне репозитория и в CI
недоступны — воспроизводится это только на ящике контура.

**Журнал у скрипта обязателен для класса 4.** Нет `.orchestrator/journal.jsonl` — скрипт печатает
`журнал не найден … класс не измерен`, а не «отказов нет»: пустой результат и непрочитанный
источник в отчёте не сливаются. Если в чужой среде вывод несёт эту строку, число «0 отказов
подъёма» из настоящего отчёта в нём НЕ воспроизведено.

## Как считалось

- **Выборка** — 180 влитых PR с 2026-08-18 (первая запись `.orchestrator/journal.jsonl`) по
  2026-09-02T14:00Z. Окно работы — от создания PR до merge; тред — из шапки описания
  (`thread: NNN-slug`); пути — из squash-коммита на `main`.
- **Пара** — два PR, чьи окна пересеклись по времени. Это и есть «две живые работы рядом».
- **Столкновение по путям** — диффы пересеклись хотя бы одним файлом. Само по себе НЕ конфликт:
  два дописывания в разные разделы `README.md` git сливает молча.
- **Текстовое столкновение** — головы веток (`refs/pull/<N>/head`, притянуты целиком) не сливаются
  друг с другом чисто: `git merge-tree --write-tree A B` отказывает. Здесь две работы стояли в
  одном тексте, а не просто в одном файле.
- **Перебазировка** — squash-коммит того PR, что влит первым, оказался предком головы второго:
  вторую ветку двигали поверх первой уже после её мержа.
- **Исключительный ресурс** — номер схемы (`schema/version.ts`, `schema/migrate.ts`),
  `agent-protocol.json`, `.github/workflows/**`, `pnpm-lock.yaml`, `package.json` пакета.
  Пересечение здесь считается конфликтом независимо от текста.

**Границы утверждений.**

- **«Текстовое столкновение» — это факт о ДВУХ ГОЛОВАХ, а не протокол разрешения конфликта
  руками.** Голова второго PR уже перебазирована; замер говорит «эти две работы занимали один
  текст», а не «человек разводил конфликт в редакторе». Что цена была уплачена, видно по другому
  признаку — перебазировке (ниже: она есть у всех 62 пар);
- **и это не артефакт самой перебазировки** — рассуждение, на котором держится число 62, названо
  здесь целиком, потому что оно неочевидно. У всех 62 пар второй PR перебазирован поверх первого,
  то есть его голова УЖЕ несёт содержимое первого (squash-коммитом). Трёхсторонний слив таких голов
  видит одинаковую правку с обеих сторон и разводит её молча: одинаковое изменение конфликтом не
  становится. Конфликт остаётся ровно там, где ВТОРАЯ работа тронула те самые строки, которые
  трогала первая, и тронула их ИНАЧЕ. Поэтому 62 — не «шум от squash», а **нижняя** оценка
  настоящего пересечения по строкам: случай, где второй при разведении принял строки первого как
  есть, здесь не считается;
- **окно работы начинается с создания PR, а не с первой строки кода**: ветка, которую вели два часа
  до открытия PR, засчитана короче, чем была. Число пересечений — **нижняя** оценка;
- **пути берутся из squash-коммита**, то есть уже ПОСЛЕ перебазировки. Файл, который был в ветке и
  ушёл при разведении конфликта, в замер не попал;
- **класс «одна работа сделана дважды» машинно не измерим** и взят из следа: PR, закрытые без
  merge, плюс поимённые случаи из тредов;
- **соседний контур сюда не входит** — его PR живут в другом репозитории, у этой сессии его
  журнала нет.

1. **Столкновения есть, и они не редкость: 62 пары за две недели** — то есть примерно четыре в
   сутки. Память чатного curator («два-три случая») занижает счёт на порядок.
2. **Но цена одного столкновения — не разведение конфликта, а перебазировка: у всех 62 пар второй PR
   двигали поверх первого.** По карточке роли перебазировка стоит нового зелёного прогона CI и
   ПЕРЕВЕШЕННОЙ метки ревью (круг поднимает событие метки, а не её наличие). Это и есть измеренная
   цена параллельности, и она уже платится сегодня — при ОДНОМ слоте на роль.
3. **Столкновения концентрируются в трёх файлах.** В общих путях 217 пар доминируют
   `packages/agent-protocol/src/cli.ts`, `packages/agent-protocol/README.md` и
   `docs/protocol-reference.md`: это не «две работы про одно», а три общих реестра, куда дописывает
   каждый PR по дисциплине («правишь команду — правишь README тем же коммитом»).
4. **Исключительный ресурс сталкивался четыре раза, и трижды — на номере схемы.** Это единственный
   класс, где столкновение — не неудобство, а падение: два пакета взяли один номер версии.
5. **Класс «грязь общего рабочего места» в журнале не проявился ни разу**: за период нет ни одного
   `launch-refused` по грязному дереву — все 13 отказов про бюджет и квоту. Общий ресурс ящика при
   этом не безобиден: `listen EINVAL` (слишком длинный путь `TMPDIR` под сокет теста) встречается в
   23 лентах сессий за 08-31 и 09-02. Он стоит красного прогона, а не сорванного подъёма.

## Поимённо: общее рабочее место (класс 4)

- **`launch-refused` по грязному дереву — 0 за период.** Ни в `journal.jsonl`, ни в `daemon.log`
  нет ни одного отказа подъёма из-за чужого следа в рабочем месте: R17 в поле не срабатывал.
  Механизм при этом реальный и найденный — `packages/agent-protocol/tsconfig.tsbuildinfo` не назван
  в `.gitignore`, и любая роль, собравшая пакет, пачкает своё дерево (находка тредов `035`/`047`);
  но **до отказа подъёма это ни разу не дошло**;
- **общее «временное» ящика стоило прогонов, и это видно поимённо**: строка `listen EINVAL` (тест
  поднимает сокет по слишком длинному пути `TMPDIR`) встречается в **23 лентах сессий** — 12 за
  08-31 и 11 за 09-02, то есть ПОСЛЕ того, как #172 (тред `056`) дал каждой сессии свой `TMPDIR`.
  **Считает это не скрипт, а греп по корпусу лент на ящике контура**, и метод здесь весь:
  `grep -rl 'listen EINVAL' ~/.claude/projects ~/.claude-lle-second/projects`, счёт файлов и
  группировка по дате их последней записи (`ls --time-style=+%m-%d`). Число — СНИМОК: корпус
  пополняется живыми сессиями, и повтор позже даёт больше (повтор 2026-09-02T16:36Z: 44 ленты,
  14 за 08-31 и 30 за 09-02). Растёт оно потому, что предмет ЖИВОЙ, а не потому, что метод плывёт;
  сравнивать эти числа между собой можно только на одну дату снятия.
  Это не «одна пара помешала другой», а общий ресурс ящика против прогона роли, и цена — красный
  прогон и повторный заход, а не сорванный подъём;
- **потолок и квота — вот что реально отказывало**: 11 отказов `run-budget` (08-18, тред 004) и
  2 отказа `quota` (08-30, треды 047 и 042).

## Что из этого следует (рекомендация, решение не моё)

1. **Механизм против столкновений нужен не «вообще», а против ОДНОГО класса — исключительных
   ресурсов.** 4 случая за две недели, из них один стоил пропущенного ревью. Это дешёвый жёсткий
   замок: номер схемы, `agent-protocol.json`, воркфлоу. Проверять можно без всяких зон — по путям
   диффа, машинно, дверью.
2. **Против текстовых столкновений (62) доменные зоны не помогут**: они концентрируются в `cli.ts`,
   README и справочнике — файлах, куда по дисциплине пишет КАЖДЫЙ предмет. Зона «смысловых соседей»
   их не разведёт, потому что предметы разные, а файл один. Разводит их либо дробление реестров,
   либо принятие перебазировки как нормальной цены.
3. **Столкновение сегодня стоит перебазировки, а перебазировка стоит нового круга ревью.** Если
   параллельность будет расти, дорожает не merge, а ревью: метку надо перевешивать. Это довод
   считать цену параллельности в кругах ревьюера, а не в минутах ожидания.
