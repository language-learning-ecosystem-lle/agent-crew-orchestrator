## 3. Ловушка, которую стоит знать всем ролям: `env -u GH_TOKEN` роняет push с правкой воркфлоу

Первый push отказал `! [remote rejected] … (Internal Server Error)`, ретрай — дословно так же.
Текст зовёт читать это как сбой GitHub, и это **ложь о причине**: без `GH_TOKEN` git уходит к
сохранённому кредиталу ящика, у которого нет права на пути `.github/workflows/**`, а слияние несло
`claude-review.yml` из `#445`. Тот же push без `env -u` прошёл с первого раза. Разводится двумя
шагами: `git ls-remote origin <ветка>` (ссылка равна старой → квитанция НЕ потеряна, push правда не
состоялся), затем снять `env -u` и повторить.
