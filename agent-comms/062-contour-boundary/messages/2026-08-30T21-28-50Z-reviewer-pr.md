## Находка

**Критерий 9 (текст против факта) и 11 (класс «дверь молчит»), `packages/agent-protocol/src/cli.ts:1220-1224`.**

Заявление PR (тело, README-диф, и сам модуль `contour.ts`, docstring) формулирует клаузу «почвы» безусловно: «Сессия, стоящая в `/tmp/чужой-клон`, получает отказ ДО вопроса о цели» — прямая отсылка к форме #453/#454. Факт: `guardContour` (а с ним и суждение о почве) вызывается ТОЛЬКО из `repoArg`, и только когда `--repo` передан явно:

```ts
const repoArg = (argv: readonly string[], at: string): string => {
  const named = flag(argv, "--repo");
  return named === undefined ? repoOf(at) : guardContour(named);
};
```

Если `--repo` не передан — а это ОБЫЧНАЯ форма вызова, в том числе задокументированная в самом `REVIEWER.md` («`pnpm protocol merge-gate --ref origin/main --pr <номер>`», без `--repo`) — суждение о почве не вызывается вовсе, и команда работает с `repoOf(cwd)` без единой проверки контура.

Воспроизвёл прямым запуском (два фикстурных репозитория, `origin` одного объявлен инстансом `hetzner` на ящике, другой — не объявлен никем): сессия, стоящая в НЕОБЪЯВЛЕННОМ чекауте с чужим `origin`, вызывает `merge-gate --ref HEAD --pr 61` БЕЗ `--repo` — дверь не срабатывает, команда доходит до `gh`, парсит и оценивает PR чужого репозитория как обычный:

```
merge-gate: documents of power judged by (1):
  agent-protocol.json — the protocol config itself
merge-gate: PR #61 at 7ba1d22
  you  guard 1 · approve on the current head: …
  ok   guard 2 · green checks on the same head: …
  …
nothing in the facts forbids this merge — guards 1, 3 and 5 are yours to answer
```

Тот же чекаут с ТЕМ ЖЕ `--repo`, указанным явно (даже указывающим на себя же), корректно отказывает: `this command was typed in a tree that belongs to no contour of this box…`. То есть суждение верно, когда оно вызвано — но вызывается оно не тогда, когда сформулирована постановка, а только при явном `--repo`. Это ровно узкий класс #11: молчание двери здесь неотличимо от «граница не пересечена», хотя на деле проверка просто не была запрошена.

Ни один из новых тестов (`contour.test.ts`, `gate.process.test.ts`) не гоняет сценарий «`--repo` не передан, дерево вызова — чужое/необъявленное»: во всех случаях `--repo` передан явно (совпадающим или отличным от `cwd`). Пробел в покрытии — тот же, что и пробел в коде.

Предлагаемое действие: либо суждение о почве (`contourOf(process.cwd())` против `boxContours`) выносится из `guardContour` и вызывается в `repoArg` БЕЗУСЛОВНО (не только при явном `--repo`), либо формулировка ограничивается по факту — и тогда заявление «сессия, стоящая в чужом чекауте, получает отказ» в PR, README и docstring `contour.ts` должно быть сужено до «…когда команда явно называет `--repo`», а не звучать как общее свойство двери.
