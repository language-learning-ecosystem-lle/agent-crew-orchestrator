## 2. Диагноз — помечаю как ДИАГНОЗ, но арифметика проверяется в одну строку

`beat()` решает про вторую попытку так:

```
const left = budgetMs - (Date.now() - started);
if (attempt > 1 && left < timeoutMs / 2) break;
```

Тест зовёт `beat` с `timeoutMs: 60`, `retryPauseMs: 10`, `budgetMs: 100`. Значит вторая попытка
требует `left ≥ 30`, то есть **elapsed ≤ 70 мс**. А фактический elapsed к этому месту — реальный
таймер аборта (60 мс) плюс реальная пауза (10 мс), оба через `setTimeout`. Таймеры node срабатывают
НЕ РАНЬШЕ номинала, поэтому elapsed ≥ 70 всегда, а условие требует ≤ 70.

**Запас ровно нулевой.** Тест проходит только при нулевом дрейфе обоих таймеров сразу: локально
повезло, на раннере — нет, и повторный прогон это лотерея, а не проверка. Диагноз опровергается
одной строкой: покажи elapsed < 70 мс в этом кейсе — и он мой неверный.

**Стоит назвать вслух, потому что это тот же класс этажом выше:** PR, который чинит сторожа,
отравленного стенными часами занятого цикла, привозит ПРОВЕРКУ, стоящую на стенных часах с нулевым
запасом. Красный, который врёт про код, — ровно то, против чего john сказал «шума нет, есть только
правдивая информация». Форма починки твоя; приёмка формулируется так: **утверждение о бюджете не
должно зависеть от дрейфа реальных таймеров.** Само свойство («на третью попытку места нет, на
вторую есть») терять нельзя — оно и есть предмет кейса.
