## 2. Пакет два, §2.3: закрыты обе оставшиеся слитности — PR **#190**, голова `c56ba71d`

Ветка `feat/mode-park-not-a-question`, база `origin/main` (`a945e56f`), два коммита.

**Строка третья — «заморожен вопросом» против «заморожен режимом».** Сделано по рецепту, который я назвала в прошлом письме, и он не менялся при встрече с кодом: `modeParks` (`thread/index-doc.ts`) — множество тредов, чья стоящая парковка просит нуля (`expects: none` объявившего сообщения, тот же `Parking.asks`, по которому звонит курьер и ставит `❓` реестр). **Множество рядом с картой `parkedThreads`, а не богатое значение внутри неё:** значение той карты — сырой `parked-on`, на нём стоят четыре читателя и каждая фикстура `new Map([[id, "john"]])`. Читатель, которому множество не передали, читает ровно как раньше — **кадр не угадывает, какую из двух парковок держит в руках**. Две фразы: `PARKED as a MODE set by john … asks NOBODY for anything` против `PARKED behind a decision of john`, и то же на стороне тика (`describeSkip`). Лифт назван в обеих: механика не менялась, менялось чтение. Событийная парковка режимом не бывает никогда — она не зовёт никого по построению.

**Строка вторая — «занята другим тредом» против «стоит без причины».** Одна роль — одна сессия, поэтому пара, чья роль работает на другом треде, не будет поднята, как бы высоко она ни стояла в очереди. Демон это говорит строкой пропуска (`role-busy`); **в кадре оператора строк пропуска нет вовсе** — там такая пара выглядит обычной строкой очереди, обещающей подъём. Метка `⛔ ROLE BUSY` едет на самой строке, которая обещает; живая сессия и ручной холд названы порознь (первая кончается сама, второй — когда человек вернёт роль), холд считается только живой. Факт берётся из **двух секций самого кадра** (`parallelism.live`, `holds`), а не новым полем от вызывающего: три секции одного кадра не разойдутся, если читают одно место. Метка стоит **рядом с парковкой, а не вместо неё** — припаркованную пару с занятой ролью держат две разные вещи.

**Граница, названная явно:** в потоке демона метка на строке очереди не печатается — там на каждого пропущенного кандидата уже идёт `describeSkip`, называющая `role-busy` по имени. Метка заведена ровно для кадра, у которого такой строки нет. Записано в доке, а не оставлено на догадку.
