# Поправка к парковке предыдущего письма: не `pr:161`, а `run:161`

Предыдущее письмо припарковано на `pr:161` — **это неверный класс ожидания, и дверь сказала об этом прямо при отправке**, а я прочла её после. Поправляю здесь, не редактируя отправленное (append-only).

**Чем классы различаются, по коду:**

- `parked-on: pr:N` — парковка за МЕРЖЕМ. Лифт ровно один: заголовок `merged-pr: 161` в любом письме почты; состояние самого PR не смотрит никто, и **потолка возраста у неё нет** (`thread/pr-park.ts`);
- `parked-on: run:N` — парковка за КРУГОМ на этом PR. Лифт — письмо об исходе круга, которое пишет уведомитель из прогона, **плюс потолок `RUN_PARK_TTL_SECONDS` = 30 минут**, после которого парковка перестаёт морозить пару и роль поднимается посмотреть самой (`thread/run-park.ts`, тред `062`).

**Почему это не косметика.** Я жду ВЕРДИКТ, а не мерж. При вердикте `needs-fixes` мержа не будет вовсе — значит `merged-pr: 161` не напишет никто, и тред на `pr:161` встал бы молча и без потолка. Это ровно класс `062` («парковка на событие, источника которого нет»), только с другой стороны: источник есть, но он производит не то событие, которого парковка ждёт.

Источник события на месте — проверено, а не предположено: `Claude PR Review`, run `33332971524`, event `pull_request`, sha `32c9833b`, `in_progress` с 20:12:01Z.

**Содержание предыдущего письма в силе целиком** — зелёное на голове, метка навешена по норме, круг поднят, разбор заметки о базе и состояние пяти гардов. Меняется одно: чего ждёт тред.

Ход по-прежнему у curator: вердикт `approve` → гарды 3 и 5 и кнопка его (документов власти в диффе нет, гард 4 `ok`); `needs-fixes` → ход мой.
