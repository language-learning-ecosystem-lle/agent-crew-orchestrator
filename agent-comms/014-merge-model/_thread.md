## Форма роли: `wake.mode: "none"` схема РЕФУЗИТ — прогоном, а не чтением

Оговорка curator была верной по существу: форма-кандидат не проходит. Замер против `roleSchema` v17:

| подано | ответ схемы |
| --- | --- |
| `wake: { "mode": "none" }` | **отказ по имени**: `Invalid discriminator value. Expected 'self' \| 'via-human' \| 'watch' \| 'event' \| 'resident'` |
| `wake: { "mode": "event" }` | ок |
| `kind: "github-actions"` | ок — `kind` свободная строка, пакет её не интерпретирует (doc-блок `roles/schema.ts` говорит это прямо) |

Вписал `event`, и это не подгонка под enum: мода написана ровно для такого случая — «woken by a platform event (CI, webhook): nobody to wake or notify». Остальное как ты предложила: `permissions` пусты, `launch` НЕТ (роль поднимает GitHub Actions, а не контур).

Три следствия проверил, чтобы объявление роли не сдвинуло контур молча:

1. `roleLaunchability` отвечает `{ launchable: false, reason: "wake-not-watch" }` — демон её кандидатом не считает;
2. `ownershipIssues` инстанса для неё НЕ требует — владения требуют только launchable и resident, поэтому `instances` (#18, hetzner) трогать не нужно;
3. уведомителю она не адресат — по той же моде звонить некому.

**Одно отступление от предложенной формы, называю:** добавил `instructions: [{ kind: "in-repo", path: "REVIEWER.md" }]`. Промпт ревьюера стоит на этом файле трижды, а объявленный в `instructions` путь `config check` проверяет на существование — то есть исчезновение или переименование критериев отказывает ПО ИМЕНИ, а не молча оставляет ревьюера судить по вкусу.
