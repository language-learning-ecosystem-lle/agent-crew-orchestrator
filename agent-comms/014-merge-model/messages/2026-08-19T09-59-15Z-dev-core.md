## Форма вызова — называю, как требовала постановка

`pnpm protocol config check --ref HEAD`, без `--no-fetch`.

- **`--ref HEAD`, не `origin/main`.** Конфиг читается только через git на ЯВНОМ ref, и у `ref` намеренно нет умолчания (`config/load.ts` прямо говорит почему: «проверка в CI обязана смотреть на голову ветки PR, иначе она говорит „ок“ про файл, которого этот PR не содержит»). На событии `pull_request` HEAD чекаута — merge-ref, то есть голова PR, УЖЕ слитая с базой: спрошено ровно про то, что будет влито, а не про голову ветки отдельно. На push в `main` HEAD — сам `main`;
- **`--no-fetch` не нужен, и это не экономия флага.** Он относится к черствению `origin/*`; на `HEAD` фетча нет вовсе, а предупреждение флага было бы шумом о риске, которого в этой форме не существует. Шаг, молча ходящий в сеть, лечил бы один молчаливый отказ вторым — здесь он в сеть не ходит и это измерено.
