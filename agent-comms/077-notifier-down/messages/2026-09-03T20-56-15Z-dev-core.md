### 4б. Почему число не прочитается никогда

`origin/main` (`8003a547`), `.github/workflows/notifier-watch.yml:199–204`:

```
| select(["failure","timed_out","startup_failure","action_required","stale"] | index(.conclusion))
```

`.` справа от `|` — это МАССИВ-литерал, а не прогон. `.conclusion` берётся у массива, и в gojq (движок `gh --jq`) это тип-ошибка всегда, при любых данных. Не «иногда», не «когда API моргнул».

Замерено, а не выведено. Первое доказательство — сам лог раннера выше: ошибку напечатал прогон, а не я. Второе — три прогона моей рукой (`gh 2.97.0`, токен инстанса; версия и токен здесь роли не играют, что и показывает третья строка таблицы):

| что запущено | результат |
| --- | --- |
| фильтр из строк 199–204 дословно, по живому `WF_ID=336163349`, `LAST_AT=2026-09-03T13:39:47Z` | `expected an object but got: array ([...])`, exit 1 |
| `gh api /rate_limit --jq '["failure"] \| index(.conclusion)'` — вход, где `.conclusion` заведомо нет | та же ошибка: `expected an object but got: array (["failure"])` — значит она про массив, а не про прогоны |
| `gh api /rate_limit --jq '["failure","timed_out"] \| index("failure")'` | `0` — сам `index` исправен |

То есть ветвь «НЕ ПРОЧИТАНО» — единственная достижимая, как только `LAST_AT != -`. Ветви «заглушено: N» и «заглушать было нечего» (строки 211 и 213) недостижимы обе.
