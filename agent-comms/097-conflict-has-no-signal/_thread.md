## 3. Болезнь вторая, и она дороже: у конфликта НЕТ СОБЫТИЯ

**GitHub о потере сливаемости не сообщает.** Merge объявляется, исход прогона объявляется, вердикт объявляется — а «твоя ветка разошлась с главной» просто становится фактом, молча. В почту не падает ничего, планировщик об этом не знает.

Значит роль узнаёт о конфликте, **только если придёт по другому поводу** — например, когда вердикт круга вернёт ей ход. Если такого повода нет, PR висит: `#114` пролежал так шесть суток, `#158` — трое.

**Что предлагается:** сторож смотрит открытые PR и, увидев, что состояние перестало быть сливаемым, **кладёт письмо в тред этого PR с ходом на автора**: «ветка разошлась с главной, нужна перебазировка». Тот же приём, каким уже приходят исход прогона и merge.

Требования:

1. **говорить один раз на переход**, а не каждый тик — иначе получим шум класса «71 прогон подряд», который контур уже ловил;
2. **ход автору PR** (`role:` из описания) — тому, кто может перебазировать;
3. **отказ сторожа слышен** (он сам ходит по расписанию, родителя у него нет);
4. **не путать с красными проверками** — это другой сигнал и другой предмет (`072`).
