## Что означает `--host` — решение названо

Постановка просила назвать выбор, а не выводить его из правки.

**`--host` сохраняет своё имя и означает ровно то, как называется: ХОСТ GitHub** — значение строки `HostName`, по умолчанию `github.com`. **Алиас приходит своим аргументом — новый `--alias`**: строка `Host`, `git@<alias>`, remote чекаута и адрес пробы `ssh -T`. `--alias` по умолчанию равен `--host`.

Дефолт верен **по смыслу**, а не по совпадению: когда различать нечего, набираемое имя и есть хост. Обратный вариант (`--host` = алиас, новый `--hostname` = хост со значением по умолчанию `github.com`) рассматривался и отвергнут: он заводит новый тихий дефолт ровно того класса, что чинится, — ящик GitHub Enterprise, набравший `--host ghe.corp`, молча получил бы `HostName github.com`.

## Отступление от постановки, доложенное: расщепления мало

Постановка просила расщепить два значения. Этого достаточно для блока и недостаточно для того нажатия, которое породило дефект: `--host github-crew` — по-прежнему утверждение «GitHub живёт на `github-crew`», и под расщеплением оно даёт `Host github-crew` / `HostName github-crew` — тот же нерезолвимый блок, только теперь по явному указанию человека.

Поэтому в PR есть **дверь**, которой постановка не заказывала: `--host` без точки отказывается ПО ИМЕНИ, до генерации ключа, и отказ называет **оба** выхода — `--alias <это>` для локального алиаса, полный домен для GHES. Отдельно отказывается алиас с пробелом: строка `Host` берёт СПИСОК имён, и такой алиас молча объявил бы несколько. Если дверь избыточна — скажи, снимается одним коммитом; логика расщепления от неё не зависит.

Второе, найденное по дороге: `hasHostEntry` спрашивали о ХОСТЕ. На ящике с двумя identity два блока несут `HostName github.com`, и вопрос по хосту прочёл бы чужой блок как «этот уже есть» — то есть второй identity молча не записался бы. Теперь спрашивают об алиасе, с юнитом на это.
