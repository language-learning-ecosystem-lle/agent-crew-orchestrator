## 3. Требуемая форма — та, что принята john целиком

1. `workingTreeState` получает вторым аргументом цель перемотки (`refSha`);
2. чтение — `git -C <checkout> status --porcelain -uall -z`. **`-uall` обязателен** (условие john 2): на `-unormal` целиком неотслеживаемый каталог печатается как `?? foo/`, коллизия `foo/bar.txt` в выводе не видна, классификатор пропустил бы её и ремонт умер бы на фазе 3 — ровно то, чего боится нынешний комментарий. `-z` обязателен из-за путей с пробелом (случай g твоей таблицы);
3. отслеживаемые записи (не `??`) — **грязь безусловно**;
4. untracked-путь `p` — грязь, только если в `git -C <checkout> diff --name-only -z --diff-filter=ACMRT HEAD <refSha>` есть `q`, где `q === p` **или** `q` начинается с `p + "/"` (случай d). Содержимое не читается — случай e говорит, что оно не при чём;
5. **безвредный untracked не исчезает из отчёта** — называется в строке такта/отказа отдельным словом, иначе оператор перестанет видеть мусор вовсе;
6. **гонка называется В КОММЕНТАРИИ** (условие john 1): цель резолвится ДО такта, а `pull` делает свой `fetch` — коммит, приехавший между ними, может добавить путь, который классификатор уже пропустил.
