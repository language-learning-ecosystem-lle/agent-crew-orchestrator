## 3. ВОПРОС ПЕРВЫЙ — сужение (рекомендация curator: ДА)

Форма, предложенная dev-core: `workingTreeState` получает вторым аргументом цель перемотки (`refSha`, оба вызывающих её уже держат); отслеживаемые правки остаются грязью безусловно; untracked-путь `p` — грязь, только если входящий дифф добавляет `q`, где `q === p` или `q` начинается с `p + "/"`; чтение — `status --porcelain -uall -z`; безвредный untracked всё равно называется в отчёте, чтобы оператор не перестал видеть мусор.

**Рекомендация — принять, и это рекомендация, а не решение.** Основание: отказ сегодня стоит суток простоя ВСЕЙ коробки за файл, который git спокойно переживает; а половина проверки, которая держит настоящую причину (отслеживаемая несохранённая работа — единственный необратимый шаг цепи), правкой не трогается.

Два условия, которые я считаю частью «да», если оно будет:

1. **Гонку назвать в комментарии, а не в треде.** Цель резолвится ДО такта, а `pull` делает свой `fetch`: коммит, приехавший между ними, может добавить путь, который классификатор уже пропустил. Ветка «ремонт не удался», потолок `attempts` и код 2 остаются несущими — правка делает `stand` РЕЖЕ, а не `pull` безотказным. Сегодня комментарий 1079–1085 заявляет больше, чем проверяет код; чинить надо ОБА, иначе через полгода тот же разбор поедет по второму кругу;
2. **`-uall` обязателен.** На дефолтном `-unormal` целиком неотслеживаемый каталог печатается как `?? foo/`, и коллизия `foo/bar.txt` в выводе НЕ ВИДНА — классификатор пропустил бы её и ремонт умер бы на фазе 3, ровно чего боится нынешний комментарий.

Цена по оценке dev-core: ~60–90 строк в `self-restart.ts`, ~150 строк тестов, один лишний вызов git за такт и только при измеренном дрейфе с untracked в дереве.

## 4. ВОПРОС ВТОРОЙ — производитель мусора (рекомендация curator: ДА, но ОТДЕЛЬНЫМ предметом)

Норма «тело сообщения/PR кладётся ВНЕ чекаута» объявлена и у почты исполнена дверью (`deliver.ts` выше). У `pr open` двери нет, а `.pr278-body.md` — тело PR #278, то есть ровно артефакт этой команды. Класс распознан пакетом давно и покрыт один чекаут из трёх.

Предлагаемая форма (dev-core назвал вариантом, не правкой): `pr open` отказывает, когда `--body-file` лежит внутри git-чекаута — та же форма, что у `deliver.ts`, цена порядка функции с тестом. Ограничение честное: дверь ловит честную ошибку и обходится набором `gh pr create` рукой.
