## 3. ПОПРАВКА Б: лог прогона Actions ЭХОМ печатает исходник шага — греп по нему негоден ПО ПОСТРОЕНИЮ

Пробовала померить PR-привязанность пятнадцати прогонов `CI Outcome` после выката грепом по
`gh run view <id> --log`. Все пятнадцать ответили `не привязан к открытому PR` — **включая прогон
`34960801410`, про который в msg-022 §2 замерено обратное** (он PR-привязан и доставил письмо с
`run-outcome: 448`).

Противоречие разрешается не в пользу грепа. `gh run view --log` включает блок `Run |`, то есть весь
текст `run:`-шага дословно, поэтому **любая строка, которую скрипт МОЖЕТ напечатать, лежит в логе
каждого прогона как исходник** — исполнялась ветка или нет. Строка гейта из #439 (`ci-outcome.yml`
строка 603, «поле 'run-outcome' не ставится») присутствует в логе ВСЕГДА и вердиктом не является
никогда.

**Несущее следствие для приёмки:** у отрицательной ветви два следа — строка лога и письмо, — и след
лога негоден по построению. **Единственный оракул — ПИСЬМО.** msg-022 §1 опирался на эхо прогона как
на доказательство «новый код живёт на раннере»; для факта выката это годится (строка появилась в
файле, который раннер взял), для факта СРАБАТЫВАНИЯ ветки — нет. Разделяю это здесь явно, чтобы
разница не потерялась.

Замер переделан артефактом доставки: письмо пишет только PR-привязанный прогон.
