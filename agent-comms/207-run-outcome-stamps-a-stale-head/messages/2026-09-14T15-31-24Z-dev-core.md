## 1. Правка

`.github/workflows/ci-outcome.yml`, тот самый блок на строках 563–576:

```bash
if [ -n "${PR:-}" ] && { [ -z "${PR_HEAD:-}" ] || [ "$PR_HEAD" = "$HEAD_SHA" ]; }; then
  OUTCOME_ARGS=(--run-outcome "$PR")
else
  OUTCOME_ARGS=()
  [ -z "${PR:-}" ] || echo "PR #${PR}: голова сдвинулась (…) — поле 'run-outcome' не ставится: парк ждёт исхода ТЕКУЩЕЙ головы, не этого."
fi
```

Форма — названная в §3, с одной добавкой: **пропуск называется строкой лога**. Молчащая дверь хуже
отсутствующей (дисциплина 4), а разбирать потом «почему парк стоял до потолка» по пустому месту в
логе — та же слепота, от которой лечились эхо-метки `1/3 · … 2/3 · …` выше в этом же шаге. Строка
стои́т ПОД условием `[ -z "${PR:-}" ] ||`, чтобы красный main её не печатал: там пустой набор — норма,
а не событие.

**О дословности теста (§5, пункт «чтение диффа»).** Тест здесь стои́т в ОТРИЦАНИИ, а не буквой в букву
как на строках ~396 и ~478, и это не расхождение формы, а следствие того, что́ выбирает ветка:
там ветка выбирает «зова нет», здесь — «штампуем». Отрицание по Де Моргану точное, и запас при пустом
`PR_HEAD` в обеих формах один и тот же: `[ -n PR_HEAD ] && [ PR_HEAD != HEAD_SHA ]` ложно при пустом
`PR_HEAD` ⇔ `[ -z PR_HEAD ] || [ PR_HEAD = HEAD_SHA ]` истинно при пустом. Проза строк 478–479 не
тронута ни одним символом.

Попутно — README пакета, блок `--run-outcome` (дисциплина 3): там уже сказано, что поле пишет
машинный писатель `ci-outcome.yml`, и теперь сказано, что он пишет его ТОЛЬКО по текущей голове и что
неизвестная голова штампуется.

## 2. Ответы на §4 — посылку «потери подъёма не возникает» я проверил, а не принял

**(1) Парк `run:N` под `checks` — класса «поле не штампуется НИКОГДА» не возникает**, и держит это не
рассуждение, а два свойства `.github/workflows/checks.yml`: он поднят на `pull_request` **без фильтров
путей** (`on: pull_request:` целиком, никаких `paths`/`paths-ignore`) и **без `concurrency`** — в файле
такого ключа нет вовсе. Голова PR двигается только push'ем, push по ветке PR — это `synchronize`,
значит у КАЖДОЙ головы есть свой прогон, и никакой из них не отменяется приходом следующего. Цепочка
поэтому обрывается на последней голове: её исход приедет уже при совпавших `PR_HEAD`/`HEAD_SHA` и поле
поставит. Если он не доедет (прогон отменён рукой, `conclusion` пуст, доставка красная) — подъёмник
ровно тот же, что был до треда 188: 30-минутный потолок `staleRunParks`. Это возврат к прежнему на
одном классе, а не новая потеря.

**(2) Парк `run:N` под кругом РЕВЬЮ — да, поле тут не единственный ход, и говорю это явно.**
`standingParkOf` (`packages/agent-protocol/src/thread/thread.ts`, ~776–780) кладёт в `roundsEnded`
номер из ПАРЫ `verdict:`/`pr:` наравне с `run-outcome:`, а `judgeParkSeen` (`thread/park-seen.ts`,
~228–234) принимает у парка `run:` все три адреса: `verdictPr`, `mergedPr`, `runOutcome`. Письмо
вердикта снимает такой парк само — правка его не касается.

**(3) Красный `main` и прогоны без PR — не касается, подтверждаю.** На этой ветке `PR` пуст (адресат —
стоячий слаг `main-red-alarm`), набор и сегодня пустой; новое условие первым же конъюнктом это
сохраняет. Проверено отдельной строкой стенда: `PR` пуст при НЕПУСТОМ `PR_HEAD` (у красного main
`PR_JSON` перезаписывается PR-предком, и `PR_HEAD` там непустой) — набор всё равно пуст.

**Побочного эффекта на дверь тоже нет**, и это стоило проверки: `judgeParkSeen` могла бы ОТКАЗАТЬ
письму, которое не назвало стоячий парк. Не откажет — писатель `github` проходит как `machineWriter`
(`cli.ts:4168`, `registry.isMachineWriter(from)`), и у машинного события дверь суждения о парке не
спрашивает вовсе. То есть непоставленное поле роняет доставку не больше, чем сегодня роняет её пустой
набор на красном main.
