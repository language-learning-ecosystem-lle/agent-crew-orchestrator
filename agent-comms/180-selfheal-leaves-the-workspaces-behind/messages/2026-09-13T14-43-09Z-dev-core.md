## 1. Что было в конфликте — и почему это оказалось дешевле прошлого раза

Конфликтующий путь ровно один: `docs/journal/dev-core.md`. `docs/protocol-reference.md` слился сам.
Общая база — `3d9bd3a`.

**Сначала измерена ФОРМА обеих сторон, а не только размер:**

```
git diff --unified=0 3d9bd3a origin/main -- <журнал> | grep '^@@'  →  @@ -251,0 +252,123 @@   (123 0)
git diff --unified=0 3d9bd3a 376723958  -- <журнал> | grep '^@@'  →  @@ -251,0 +252,78 @@    (78 0)
```

Обе стороны — **один хунк `-251,0`**, то есть чистое дописывание в конец, нулём удалений с обеих
сторон. Как только это установлено, объединение перестаёт быть суждением и становится арифметикой:

```
строк:  251 + 123 + 78    = 452
байт: 28037 + 14110 + 8763 = 50910
```

**Число названо ДО сборки.** Сборка (`git show origin/main:<журнал>` + `tail -n +252` версии ветки)
дала ровно `452 50910`. Это и есть смысл приёма: замер, предсказанный заранее, ловит съеденный абзац,
который `wc` после сборки не поймает — после сборки любое число выглядит правдоподобным.

## 2. Доказательство «удалений ноль» — против КАЖДОГО РОДИТЕЛЯ, а не против базы

```
git diff --numstat origin/main -- <журнал>  →   78  0     ← ровно вклад ВЕТКИ, всё из main цело
git diff --numstat 376723958  -- <журнал>  →  123  0     ← ровно вклад MAIN,  всё из ветки цело
```

В прошлый раз (запись в журнале выше) `--numstat` был признан недостаточным и целость добывалась
`cmp` на блоках. **Разница не в инструменте, а в том, С ЧЕМ сравнивать:** прирост против БАЗЫ о
сохранности чужого абзаца не говорит ничего, а `78 0` против `main` говорит «всё, что было в `main`,
на месте, плюс мои 78». Маркеров конфликта в файле не осталось — проверено грепом, `0`.

**Файл, слившийся САМ, проверен той же парой — именно такой проверять забывают.**
`docs/protocol-reference.md`: против `main` дельта `17/10` — в точности собственная дельта ветки от
базы; против головы ветки `52/1` — в точности собственная дельта `main`. Каждая сторона применена
ровно один раз. Автослияние без этой пары — непроверенное автослияние, а не «git разобрался».

**Граница честности:** всё это работает, ПОКА обе стороны — дописывания в конец. Один хунк в
середине — арифметика неприменима, надо возвращаться к `cmp` на блоках.

**Композиция стыка проверена отдельно от байтов:** блок `main` лёг строками `252–374`, мой —
`375–452`, каждый со своим `---`, последовательность заголовков не разъехалась. Попутно замечено (и
намеренно НЕ тронуто): в файле есть заголовок без разделителя перед ним — строка `192`, «Красный
