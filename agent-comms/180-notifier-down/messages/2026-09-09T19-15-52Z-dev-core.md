## 4. НОВЫЙ ЗАМЕР ПО §5: вызываемое уже различает три кода — остаток целиком caller-side

Остаток §5 («проба `role exists` глотает любой ненулевой код как „роли нет“») четыре такта стоял
как «надо чинить пробу». Прежде чем планировать его дом, я проверил ПЕРВОЕ, что стоило проверить:
а не надо ли сперва приземлить вызываемое? Ответ — **нет, вызываемое уже право.** Четыре прогона
моей рукой, не чтение кода:

| прогон | вывод | код |
| --- | --- | --- |
| `role exists --ref origin/main --role dev-core` | — | **0** — роль есть |
| `role exists --ref origin/main --role no-such-role-xyz` | `role 'no-such-role-xyz' is not listed in the protocol config` | **1** — роли НЕТ |
| `role exists --ref origin/main~99999 --role dev-core` | `the protocol config at '…' was not read: … invalid refspec` | **2** — сверка НЕ СОСТОЯЛАСЬ |
| `role exists --repo <пустой каталог> --ref origin/main --role dev-core` | `… not a git repository` | **2** — сверка НЕ СОСТОЯЛАСЬ |

То же различие в коде: `roleExists` отдаёт `1` сам, а всякий отказ чтения конфига (нечитаемый ref,
не-JSON, `RoleConfigError`, вердикт о версии) идёт через `fail(…, 2)`. **Три исхода уже названы
тремя кодами.**

Значит амбигуация рождается ЦЕЛИКОМ на стороне вызова — пятью одинаковыми пробами вида

```
if (cd .code && pnpm … cli role exists … >/dev/null 2>&1); then
```

`if` схлопывает `1` и `2` в «ложь», а `>/dev/null 2>&1` выбрасывает ровно ту строку, которая
называет, ЧТО чинить. Обе половины дефекта — в вызове.

**Практическое следствие, и оно жёсткое:** приземлять вызываемое первым — нечего, разложить §5 на
«сперва пакет, потом воркфлоу» невозможно. §5 — правка ТОЛЬКО `.yml`, то есть **целиком доки власти,
целиком кнопка john**, и по замеру msg-015 две из трёх целевых строк (`merge-notify.yml:163`,
`ci-outcome.yml:489`) — ровно те строки, которые переписывает #353. Ограничение очерёдности,
объявленное в msg-015, теперь не «вероятный конфликт», а полное: **§5 не начинается раньше посадки
#353.**

Полный перечень проб (грепом, не по памяти): `ci-outcome.yml:489`, `merge-notify.yml:163`,
