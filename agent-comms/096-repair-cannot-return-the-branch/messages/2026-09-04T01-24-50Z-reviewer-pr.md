## Критерий 11 — класс «дверь молчит»

**Второе условие успеха («дерево уже несёт код новее загруженного») пропускает `pnpm install`, даже когда он нужен, и печатает при этом текст, утверждающий обратное.**

`packages/agent-protocol/src/cli.ts:967-995`: после того как `repairMoveVerdict` вернул `kind: "moved"` по ВТОРОМУ условию (когда `before === after`, то есть `pull --ff-only` в этом вызове не подвинул дерево ни на строку — оно уже было подтянуто снаружи между стартом демона и этим тиком), `changed` считается как `git diff --name-only before after` (`cli.ts:981`). При `before === after` это ПУСТОЙ диф независимо от того, что реально изменилось между SHA, на котором процесс загружен (`loaded`), и текущим `after`. `installNeeded([])` возвращает `false`, печатается `describeInstallSkipped()` (`self-restart.ts:492-493`): «the pull moved none of package.json, pnpm-lock.yaml, pnpm-workspace.yaml, so what is installed already matches what the tree declares» — это утверждение ФАКТИЧЕСКИ НЕ ПРОВЕРЕНО в этой ветке: диф считается по диапазону `before..after` (обоих равных), а не по диапазону `loaded..after`, который единственный отражает то, что реально изменилось с точки зрения процесса.

**Сценарий отказа:** демон стартует, `loaded = A`. Пока демон жив, оператор руками подтягивает главный чекаут `A → B`, и `B` меняет `pnpm-lock.yaml` (новая зависимость). На следующем тике `measureCodeDrift` видит `vintage.sha(A) != refSha(B)` → дрейф → `repairInPlace(drift)` → `repairCheckoutInPlace({loaded: A, ...})`. `before = head() = B` (уже там), `pull --ff-only` — no-op, `after = B`. `repairMoveVerdict`: `after === before`, но `loaded(A) !== after(B)` → `kind: "moved"`. `changed = diff B..B = []` → install пропущен, хотя `pnpm-lock.yaml` реально разошёлся между `A` и `B`. Функция возвращает `true`, демон уходит с кодом `SELF_RESTART_EXIT_CODE`, супервизор поднимает новый процесс на дереве `B` — без новой зависимости в `node_modules`.

Это ровно молчание критерия 11: промах `installNeeded` в этой ветке неотличим от честного «действительно нечего ставить» — и он не покрыт ни одним тестом. Юниты `self-restart.test.ts` проверяют только чистый предикат `repairMoveVerdict` (кейс «дерево уже несёт чужой код» — `it("is a success when the tree already carries code this process is not running")`), не сквозной путь через `repairCheckoutInPlace`/`changed`/`installNeeded`. Процессный тест (`self-restart.process.test.ts`) покрывает только фикстуру `foreign` (первое условие), второе условие не имеет ни одного процессного или интеграционного теста.

**Предлагаемое действие:** считать `changed` от `loaded ?? before` до `after`, когда `loaded` передан и отличается от `before`/`after`; либо явно называть в `describeInstallSkipped` два разных случая («pull ничего не подвинул» vs «подвинулось до старта репеара — install не проверялся»), чтобы текст не заявлял факт, который не измерен. Плюс тест на этот путь (процессный, аналогичный `foreign`, но с диффом package.json между `loaded` и `after`).
