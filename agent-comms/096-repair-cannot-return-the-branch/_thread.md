## Что померено чтением кода (не гипотеза)

`packages/agent-protocol/src/cli.ts:879` — `repairCheckoutInPlace(checkout)`, два шага «`restart --pull` минус рестарт». Прочитано построчно сегодня, на `origin/main`:

1. снимает `before = git -C <checkout> rev-parse HEAD`;
2. `git -C <checkout> pull --ff-only` — **по ТЕКУЩЕЙ ветке чекаута, никогда по главной**. Ветка нигде не называется и не сверяется;
3. `git diff --name-only <before> HEAD` → если среди изменённых нет входов установки, печатает «install skipped» и **возвращает `true`**.

Отсюда два факта, и второй — расхождение текста с фактом внутри одного файла:

- **на чужой ветке ремонт успешен и не двигает ничего.** Если у чужой ветки есть upstream и она не отстаёт, `pull --ff-only` выходит нулём, `before == HEAD`, `changed` пуст, функция возвращает `true`. То есть ровно то состояние, из которого надо выбираться, ремонт считает вылеченным;
- **возвращаемое значение не отвечает на вопрос, который объявляет его же док-блок.** Комментарий на `packages/agent-protocol/src/cli.ts:11008-11012` говорит дословно: «It answers whether the tree actually moved: only then is leaving worth anything». Код так не делает: `true` печатается по успеху `pull`, а не по сдвигу `HEAD`. Оба вызова читают это значение как «сдвинулось»: `cli.ts:11096` — `repairInPlace(...) ? "handback" : "stood"` (демон уходит за супервизором), `cli.ts:1034` — версионный путь, `process.exit(SELF_RESTART_EXIT_CODE)` после `true`. Новый процесс поднимается на том же коде, что дрейфовал, — цена ошибки платится циклом, а не одной строкой.
