# Журнал роли dev-core — тред `206-journal-writes-without-a-pr`

## 2026-09-14 · Запись роли легла в ветку почты командой — этот абзац и есть приёмка

**Что сделано.** `journal write` — четвёртая отправляющая команда пакета рядом с `new-message`,
`new-thread` и `thread status`: файл, коммит и push — одно действие, тем же `deliverMessage`, с тем
же замком на чекаут, той же проверкой грязи, тем же перепланированием при гонке и тем же откатом.
Ни ветки, ни PR, ни прогона, ни кнопки. Этот текст написан ею самой — из невлитой ветки
`feat/206-journal-write`, ещё до того, как её код куда-либо приземлился.

**Где живёт запись.** `<mail.dir>/journal/<role>/<NNN-slug>.md` в ветке почты. Форма «файл на тред»
(#408, решение john 13.09) переехала целиком — сменилась только ветка. Путь зеркалит память роли
(`<mail.dir>/memory/<role>`) намеренно: память и журнал — две вещи, которыми роль владеет внутри
ветки почты, и читатель, выучивший один путь, знает второй.

**Что НЕ переехало и это факт, а не недоделка.** Старые записи в `docs/journal/**` главной ветки
остались там же — то же правило, под которым переезжали на файл-на-тред. Значит исключение
`merge-gate --journals` **выпиливать нельзя**, пока эти пути живы: дифф по ним всё ещё бывает, и без
исключения он потребует круга. Назвал это фактом в README и в тексте `usage`.

**Почему повторная запись — дозапись, а не замена.** Тред живёт несколько тактов, и находка третьего
такта лежит рядом с находкой первого. Дважды один и тот же текст — отказ ПО ИМЕНИ: файл
append-only, руками его потом не поправишь, а сессия, потерявшая свой вывод, отличает «написано» от
«не написано» только спросив.

**Чем доказано.** Юниты на планировщик (`src/journal/write.test.ts`) и процессный тест на СТЫК
(`src/journal/journal-write.process.test.ts`) — с настоящим bare-ремоутом: «закоммичено и
запушено» читается из ветки ремоута, а не из строки вывода. Мутация `JOURNAL_DIR = "journals"`
покраснила 6 тестов в обоих файлах.
