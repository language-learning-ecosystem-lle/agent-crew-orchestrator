# Журнал роли curator — тред `214-restart-advisory-misses-read-once-keys`

## Приёмка прозы двери берётся на СМЁРЖЕННОМ PR — и потому не требует заводить PR ради срабатывания

Дата: 2026-09-16. Тред `214-restart-advisory-misses-read-once-keys`, PR #456 (`d8e9aa00e`).

**Случай.** Предмет треда — текст предупреждения `merge-gate` о диффе `agent-protocol.json`: к условному
`protocolVersion` добавлены четыре ключа, которые демон читает ОДИН раз при старте (`parallelism.*`,
`roles[]`, `instances`, `orchestrator.env`). Приёмкой постановка назвала живое срабатывание строки, и
dev-core снял его ДО мёржа — на сборке ветки, позвав дверь на PR #453 (его дифф трогает
`agent-protocol.json`). Исход второго рода: дверь ОТКАЗАЛА на гарде 4, а строка напечаталась, потому что
печатается ПОСЛЕ вердикта и безусловно.

**Что я сделала сверх доклада и зачем.** Смёржённое ≠ работающее: сборка ветки — не то дерево, которое
теперь стои́т на `main`. После кнопки перевела своё дерево на squash-коммит и повторила ту же команду:

```
git checkout d8e9aa00ecd3c58f853cb1e59327db0a25b1f4e3
node --import tsx packages/agent-protocol/src/cli.ts merge-gate --ref origin/main --pr 453 --review-workflow 'Claude PR Review'
```

Строка напечаталась дословно с четырьмя ключами. Приёмка снята на СЛИТОМ дереве, а не на обещании мёржа.

**Находка, ради которой запись.** PR #453 на момент этого прогона был УЖЕ СМЁРЖЕН (15.09, `9756d13`) — и
дверь отработала на нём как на живом: прочитала голову, гарды 1 и 2 зелёными, гард 4 — `STOP`,
`mergeability` — `UNKNOWN` (GitHub на закрытом PR его не считает), и напечатала предупреждение. То есть:

> **Смёрженный PR с нужным диффом — это даровой полигон для приёмки ЛЮБОЙ прозы `merge-gate`.**

Практическое следствие для постановок: приёмка «дверь печатает такую-то строку на таком-то классе диффа»
**не требует ни открытого PR, ни заведения PR ради срабатывания, ни ожидания редкого условия**. Достаточно
найти в истории смёрженный PR, чей дифф трогает нужный путь, и позвать дверь на его номер с нужной сборки.
Раньше такая приёмка в постановке выглядела дорого («срабатывание заказывается рукой — само оно у редкого
условия может не прийти сутками») и толкала к тому, чтобы либо ждать попутного PR, либо заводить PR ради
одного запуска. Теперь она стоит одну команду и берётся и ДО мёржа (сборка ветки), и ПОСЛЕ него (слитое
дерево) — то есть обе половины «новый путь принимается первым срабатыванием» закрываются в один такт.

**Границы находки, чтобы она не обещала лишнего.** Это верно для прозы, которую дверь печатает БЕЗУСЛОВНО
по имени изменённого пути, после вердикта и не касаясь кода возврата. Как только исход строки зависит от
гардов (печатается только при `exit 0`, только на открытом PR, только при зелёном гарде 2) — смёрженный PR
перестаёт быть годным полигоном, потому что его гарды уже не те, что были у кнопки. Проверять надо не
«строка напечаталась», а «строка напечаталась НЕСМОТРЯ на отказ» — ровно так исход и читался в этом треде.

**Гард 3 у самого #456** закрылся классом «полевой измеренный дефект, новой нормы не вводит», все три
условия поимённо в следе merge (msg-009): первоисточник — тред `211`, msg-011 §4; слово исполнителя о
своём диффе — msg-002; подтверждение ревьюера чтением диффа — msg-008, критерий 12, где он отдельно
перечислил сигнатуру, литералы, формат массива, права и шаги маршрута. Условие 3 я объявила берущимся из
ТЕКСТА вердикта ДО круга (msg-004, msg-007), а не у кнопки — и вердикт его действительно закрыл.
