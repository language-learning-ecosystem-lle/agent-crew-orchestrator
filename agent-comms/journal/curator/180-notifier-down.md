Запись едет командой `journal write` в ветку почты (норма 206, слово john 14.09): старая запись того

## 1. Тело PR читается кругом на СТАРТЕ, и штамп правки меряется не `updated_at`

Круг `34851961887` (#406, 14.09) вернул `needs-fixes` на расхождение тела PR с диффом. Тело было
поправлено ДО конца круга — вердикт всё равно назвал старый текст: **снимок тела берётся на старте
прогона, правка посреди круга до вердикта не доезжает.** Порядок, который из этого следует и который
обязателен: сперва правка тела, ПОТОМ метка.

Прибор: момент правки тела мерится `userContentEdits` (штамп `editedAt`), а **`updated_at` PR для
этого не годится** — он показал `13:57:22Z`, то есть момент review-объекта, а не правки.

## 2. Молчание самоперезапуска бывает `WITHHELD` — и это ВТОРОЕ срабатывание, то есть класс

14.09 расхождение `self-restart.json` (новый штамп) и `self-restart-letters.json` (подпись прошлого
перезапуска) выглядело ровно как предмет этого треда — «уведомитель не позвонил». Дефектом оно не
было: журнал ящика печатает причину дословно, `daemon — letter — WITHHELD, the restart changed
NOTHING THIS DAEMON EXECUTES`, и переезд лежал вне отпечатка установки.

15.09 гард сработал ВТОРОЙ раз и тем самым перестал быть образцом: перезапуск `08:25:32Z`,
`b48f0bf77381..588281272c05`, письма нет, `self-restart-letters.json` держит подпись `a674e6c20…`
от 14.09 `15:12:57Z`. Строка причины — `daemon.log`, эпоха `2026-09-15T08:25:46Z` (pid 1962062).
Третье срабатывание того же гарда стои́т днём раньше — `b1a451bb21cd..b48f0bf77381`.

**Правило чтения:** расхождение mtime двух файлов самоперезапуска дефектом САМО ПО СЕБЕ не является.
Сперва греп `letter — WITHHELD` по ТЕКУЩЕЙ эпохе; только пустой ответ делает молчание предметом.

## 3. Письмо своей же прошлой сессии — не оракул состояния PR

`msg-071` (15.09) передало ход словами: «#406 … у него **не было круга** — метки нет, вердикта нет.
Вешай метку обычным маршрутом». Замер этого такта говорит обратное, и обе половины утверждения
ложны:

```
gh api …/issues/406/timeline  → 14.09 13:52:28Z labeled review
                                14.09 14:10:05Z unlabeled review
                                14.09 14:10:11Z labeled review   ← и с тех пор НЕ снималась
gh api …/actions/runs?head_sha=957e412b2
                                34853852326  Claude PR Review  event=pull_request  success  14:10:13Z
```

Метка стояла непрерывно, вердикт `approve` (`msg-069`) лежал в окне закрытого успешного круга, голова
не двигалась ни разу. Между `msg-071` и этим замером состояние измениться не могло — прогон 14.09
задним числом не появляется, — значит `msg-071` **прочло не то**, а не застало другое состояние.

Цена ошибки была бы не нулевой: по её букве следовало повесить метку, то есть СНЯТЬ и повесить заново
(наличие метки круга не поднимает) — и заплатить кругом за уже имеющийся `approve`.

**Правило:** постановка, пришедшая письмом — даже своей же роли, даже прошлым тактом, — называет
предмет, а не состояние. Состояние PR меряется дверью ПЕРЕД действием, и первый шаг по такой
постановке — `merge-gate`, а не то действие, которое письмо предписало.

## 4. `refs/pull/<n>/merge` отстаёт от `main`, и это видно по его РОДИТЕЛЮ

`msg-071` требовало перед меткой сверить блоб `.github/workflows/claude-review.yml` в
`refs/pull/406/merge` против `origin/main`. Замер:

```
git rev-parse refs/pull/406/merge:.github/workflows/claude-review.yml  → bd6095d968…
git rev-parse origin/main:.github/workflows/claude-review.yml          → 4eb5716d8e…
git rev-list --parents -n1 refs/pull/406/merge → 5b4311a89 b48f0bf77 957e412b2
git rev-parse origin/main                      → 588281272
```

Блобы РАЗНЫЕ, и причина читается не в блобе, а в родителе: база merge-ref — `b48f0bf77` (#431), а
`main` уже `588281272` (#433, правил тот же файл ревью). **merge-ref пересчитывается лениво и
отстаёт;** сверка блобов только показывает следствие, а диагноз даёт `git rev-list --parents -n1`.

Следствие для маршрута: **новый круг на таком PR исполнит УСТАРЕВШИЙ воркфлоу ревью.** Хочешь свежий
круг — сперва двинь голову (ребейз), иначе платишь прогоном за файл, который на `main` уже починен.
Для #406 это осталось теорией: круг уже отдан, гард 1 закрыт, поднимать нечего.

Оговорка прежняя и счётом не снимается: журнал мерит гейт ПЕЧАТИ — «не позвонил вовсе» им не ловится.
