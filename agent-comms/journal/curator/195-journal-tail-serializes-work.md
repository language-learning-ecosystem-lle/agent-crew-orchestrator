# Журнал роли curator — тред `195-journal-tail-serializes-work`

## Полевая приёмка #408: форма «файл на тред» держится — 54 пары из 54 без конфликта журнала

**Замер 2026-09-14 ~15:45Z**, тред `195-journal-tail-serializes-work`. Критерий объявлен мной же
в этой ленте письмом `2026-09-14T~11:00Z` (msg-002, п. 3): «следующая пара одновременно живущих PR
с записями в журналы не должна разъезжаться; первый же случай назвать фактом». Случай наступил не
парой, а полем из одиннадцати.

### Что мерилось

Открытых PR — **14**, и **все 14 `MERGEABLE`** против `origin/main`. Сутками раньше семь из
четырнадцати были `CONFLICTING`, и у всех семи конфликт был **один и тот же путь** —
`docs/journal/dev-core.md` (замер в msg-001, п. 5).

Записи журнала несут **11 PR из 14**, и все одиннадцать — в новой форме
`docs/journal/<роль>/<NNN-slug>.md`. **Ни один открытый PR не трогает старые хвосты**
(`docs/journal/curator.md`, `docs/journal/dev-core.md`).

### Счёт пар

`git merge-tree --write-tree <голова A> <голова B>` по всем парам одиннадцати:

| | |
| --- | --- |
| пар всего | 55 |
| из них вырожденных (стопка) | 1 |
| **годных к счёту** | **54** |
| конфликтов по любому пути `docs/journal/**` | **0** |

Оба конфликта — **по коду, а не по журналу**:

- `#433 × #436` — `.github/scripts/review-delivery.integration.sh`, `.github/workflows/claude-review.yml`;
- `#431 × #433` — `.github/scripts/review-delivery.integration.sh`.

Это ровно тот класс, который #408 чинить и не обещал: три PR треда `205`/`201` правят один скрипт
доставки вердикта. Разъезд по коду — работа, разъезд по хвосту журнала — налог.

### Вырожденная пара: чистый `merge-tree` бывает ничем не доказан

**`#431 × #436` — единственная пара, у которой ОДИН И ТОТ ЖЕ файл журнала**
(`docs/journal/dev-core/201-notifier-down.md`, оба PR треда `201`). Соблазн засчитать её как
сильнейшее свидетельство («даже общий файл слился сам») — и он ложный:

```
git merge-base refs/pull/431/head refs/pull/436/head → 3cd64e45… = ГОЛОВА #431
```

#436 стои́т НА #431 стопкой. Слияние здесь — перемотка, а не трёхсторонний мёрж, и ноль конфликтов
в нём не значит ничего. Пара выброшена из счёта.

**Метод, который отсюда следует и стоит дороже самого замера:** прежде чем засчитать чистый
`merge-tree` за свидетельство, сверь `merge-base` с ОБЕИМИ головами. Совпала с любой — пара
вырождена, и «конфликта нет» в ней — свойство топологии, а не формы файлов.

**Класс остаётся неизмеренным:** «два НЕЗАВИСИМЫХ PR одного треда пишут в ОДИН файл журнала» в
сегодняшнем поле не представлен вовсе. Форма «файл на тред» этот класс по построению не разводит —
норма разделяет треды, а не ходы внутри треда. Ждать его замера, а не объявлять закрытым.

После мержа #408 (`~10:51Z`) в старые хвосты село **два** коммита: `970957c37` (#421, тред 180,

### Форма пережила второй переезд

Тем же днём решение john (тред `206`) увело запись роли из PR в ветку почты командой
`journal write`. **«Файл на тред» переезд пережил — сменилась только ветка**: запись ложится в
`<mail.dir>/journal/<роль>/<тред>.md`, старые файлы в `docs/journal/**` остаются и остаются верными.
Эта запись — первая по треду `195`, уехавшая новой командой: ни ветки, ни PR, ни круга, ни кнопки.
