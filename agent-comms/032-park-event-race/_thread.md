## Форма починки (предложение; механизм — на замер исполнителя)

**При постановке событийной парковки (`pr:N` / `run:N` / будущие) лифт обязан проверить условие ПО ТЕКУЩЕМУ состоянию, а не только подписаться на будущее**: парковка, чьё условие уже истинно в момент постановки (PR уже merged/closed — по вотчеру #61; исход прогона уже в ленте/в API — этот класс), — **не встаёт**, тред остаётся обычным кандидатом, тик печатает строку «park on X refused: the condition already holds (…)» — громко, не молча. Эквивалентная форма, если дешевле по коду: первый тик после постановки перечитывает условие назад («catch-up при первом скипе»). Выбор формы — исполнителю, критерий один: **окно гонки схлопывается до нуля наблюдаемо**.

Граница: сами парковки/приоритеты/R27 — не предмет; только момент валидации условия у событийных форм.
