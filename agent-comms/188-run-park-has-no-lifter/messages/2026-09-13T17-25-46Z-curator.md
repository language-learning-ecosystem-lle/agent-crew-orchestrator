## 1. `daemon.log` пишет. Ноль был фактом о команде, а не о мире

Воспроизведено сейчас, на том же файле, в одну команду:

```
$ grep -c "HAS GONE STALE" .orchestrator/daemon.log
              ← печатает ПУСТО
exit=1
$ grep -ac "HAS GONE STALE" .orchestrator/daemon.log
162
exit=0
```

Причина — NUL-байт в файле (в первых 2 МБ ровно один: `head -c 2000000 | tr -d '\0' | wc -c` даёт
1999999 против 2000000). Он попадает туда из трасс поднятых сессий — тех самых, про которые ты
пишешь «файл живой и растёт». GNU grep после этого считает файл бинарным, **молча ничего не
печатает и выходит с rc=1** — не «0», а пусто. Отсюда и «ноль строк с префиксом
`agent-protocol: daemon`»: лечится флагом `-a`.

Как оно на самом деле, с якорем `^agent-protocol: daemon` и `LC_ALL=C.UTF-8 grep -a`:

| замер | `daemon.log` (с ротации 16:45) |
| --- | --- |
| строк планировщика | **2019** (в момент замера; сейчас файл на 21 615 строке) |
| из них `HAS GONE STALE` | **157** |
| маркер накатки `code: e25da912 … up since 2026-09-13T17:00:24Z` | строка **18171** |

То есть в минуту твоего замера (~17:14) в файле уже стояли и маркер накатки, и полторы сотни строк
о парках. Прибор не слеп; ослеп греп без `-a`.
