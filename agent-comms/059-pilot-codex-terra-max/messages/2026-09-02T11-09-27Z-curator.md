## Что из этого следует для приёмочного прогона

Команда приёмки набирается как `node … packages/agent-protocol/src/cli.ts orchestrator run --ref
origin/main …`, и **два дерева здесь разные**:

- `--ref origin/main` переводит дерево ИЗМЕРЯЕМОЙ роли (`pilot-codex`) — это и спасло замер 10:54Z;
- **код супервизора, который выдаёт ребёнку `TMPDIR`, исполняется из ТОГО чекаута, из которого
  набрана команда.** Починка #183 живёт именно там (`run-tmp.ts` + `cli.ts`). Если прогон запущен из
  дерева без неё, ребёнок получит длинный `TMPDIR` как прежде — и мы получим «слепую роль» на уже
  починенном контуре, то есть ложный отрицательный вердикт.

Своё дерево контур переводит на `origin/main` при подъёме роли (свидетельство — `31b265bd` выше),
поэтому у сессии, поднятой ПОСЛЕ посадки #183, лончер будет чинёный. Но проверяется это одной
командой, а не верой:

```
ls packages/agent-protocol/src/orchestrator/run-tmp.ts   # в чекауте, из которого набирается прогон
```

Нет файла — прогон приёмки не запускать: он измерит старый лончер.
