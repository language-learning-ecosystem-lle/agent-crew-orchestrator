## 1. Замер (шаг 1 постановки) — пара на ОДНОМ дереве

Дерево — `a945e56f` (чистый `origin/main`), команда одна и та же, `TMPDIR=/tmp`:

```
npx vitest run packages/agent-protocol/src/orchestrator/daemon.watchdog.process.test.ts -t "only the BARE key"
```

| прогон | окружение | итог |
| --- | --- | --- |
| A | как есть на ящике | **красный**, `:505` — ждали `circuit watchdog OFF`, 4.2 с |
| B | `env -u HEALTHCHECKS_CIRCUIT_URL_HETZNER` | **зелёный**, 5.8 с |

- **переменная:** `HEALTHCHECKS_CIRCUIT_URL_HETZNER`;
- **значение на ящике:** URL монитора живого контура (не показываю — это credential в точном смысле: кто его знает, тот гасит тревогу); **в раннере переменной нет вовсе**;
- **строка теста, которая на это смотрит:** `packages/agent-protocol/src/orchestrator/daemon.watchdog.process.test.ts:505` — `expect(run.out).toContain("circuit watchdog OFF")`;
- **что говорил баннер вместо OFF** (прогон A, значение вырезано): `agent-protocol: daemon — circuit watchdog ON — every tick pings the monitor named by 'HEALTHCHECKS_CIRCUIT_URL_HETZNER' … 'HEALTHCHECKS_CIRCUIT_URL' is set in '<tmp>/secrets.env' as well and is IGNORED here`.

**Механизм — измерен по коду, а не выведен из совпадения:** `loadSecrets` (`packages/agent-protocol/src/notify/secrets.ts:99`) кладёт файл секретов ПОВЕРХ окружения — `{ ...env, ...parsed }`. Значит ключ, которого в файле НЕТ, отвечает из `process.env`. Тест пишет в свой файл ровно голый `HEALTHCHECKS_CIRCUIT_URL` (в этом весь его случай: «именованный инстанс с одним голым ключом не бьёт никуда»), а `resolveWatchdog` находит суффиксный ключ инстанса в среде ящика, где он стоит ШТАТНО. Отсюда `ON` вместо `OFF`.

Так что «переменная сторожа» — верно, но недостаточно: без слоя слияния секретов непонятно, ПОЧЕМУ файл теста не перебивает ящик. Он и не должен был — он про этот ключ молчит.

## 2. Вторая половина, в постановке не названная — тест бил в боевой монитор

При `watchdog ON` демон, поднятый ТЕСТОМ, слал beat не на loopback-сервер теста (в прогоне A `open.paths` пуст — ассерт на строке 504 прошёл именно поэтому), а **на монитор живого контура**. То есть локальный прогон пакета гасил боевую тревогу за демона, которым он не является. Это хуже красного теста: красный виден, а лишний зелёный beat — нет.

## 3. Починка — #189

Окружение фиксирует сам тест, стенд не трогается (отклонённый постановкой путь и не рассматривался). Вычитание — в `sandbox()` (`testing/process-sandbox.ts`), там же, где три предыдущих случая этого класса, и **по префиксу, а не по двум именам**: ключ именованного инстанса — это голый ключ с суффиксом (`resolveWatchdog`), и каждый новый инстанс бокса добавляет ещё один. Удаляются `HEALTHCHECKS_URL` (крон бокса), `HEALTHCHECKS_CIRCUIT_URL`, `HEALTHCHECKS_CIRCUIT_URL_*`. Имена берутся из констант `watchdog.ts`, а не переписываются в тестовый файл.

Проверяемость закрыта так:

- **юнит** — `testing/process-sandbox.test.ts`, три случая: вычитание трёх форм ключа; тест, который ИМЕННО о переменной, передаёт её через `extra`; имя, лишь ПОХОЖЕЕ на монитор (`HEALTHCHECKS_CIRCUIT_URLS_OWN`), не трогается. 11/11;
- **живая приёмка (то, что просила постановка)** — `vitest run …/daemon.watchdog.process.test.ts` на ящике с живым контуром, **при выставленной переменной, без снятия чего-либо руками: 9/9, 44 с**;
- **доки** — `docs/protocol-reference.md`, четвёртым случаем к трём соседним (055 / 003 / 015), тем же коммитом.
