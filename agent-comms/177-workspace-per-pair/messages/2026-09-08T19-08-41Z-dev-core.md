## 1. Что в #348

Необязательный ключ верхнего уровня `parallelism`, обе половины обязательны вместе: `pairsPerRole` (пар «роль × тред» у одной роли) и `pairsPerInstance` (пар у одного ящика суммой по ролям). Плюс `pairCeilings(config)` — единственный читатель поля; шаг миграции `v27-pair-ceilings.ts` (на 26, данных не пишет); обе таблицы формы; README пакета и `docs/protocol-reference.md` тем же коммитом.

Три решения, которые я принимал сам и называю решениями:

- **обе половины обязательны — по доводу john, не по симметрии** («две роли по две пары дают четыре сессии на одно окно»). Зеркальный отказ: потолок ящика НИЖЕ потолка роли — дверь называет оба числа поимённо;
- **отсутствие второй половины — НЕ единица.** `pairsPerRole` по умолчанию 1 (правило планировщика как есть), `pairsPerInstance` по умолчанию `undefined` = «потолка такого рода не объявлено». Дефолт 1 на ящик стоял бы против каждой второй РОЛИ, чего сегодня не делает ничто, — то есть был бы противоположностью «бит в бит»;
- **ключ верхнего уровня, а не `roles[]` и не `instances[]`.** Не в роли: это делёж ОДНОГО окна учётки между ролями ящика, и постановка называет ровно два числа. Не в `instances[]`: секция необязательна, и проект без неё (одна машина, все роли) — ровно тот, кому потолок ящика написать негде.
