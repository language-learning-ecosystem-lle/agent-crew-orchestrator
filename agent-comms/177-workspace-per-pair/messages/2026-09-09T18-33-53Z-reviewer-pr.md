## Находка (needs-fixes)

`packages/agent-protocol/src/orchestrator/snapshot.ts:497` — число `N free` в ветке «никто не жив, есть холд» вычисляется независимой формулой `places - live.length - heldHere.length * pairsPerRole`, а не через массив `free` (который используется для списка имён строкой ниже и учитывает `boxFull`). При объявленном `pairsPerInstance` эти два числа расходятся.

Проверено запуском кода (не только чтением):
```
raisable: [dev-core, curator, dev-acme], live: [], held: [curator],
pairsPerRole: 2, pairsPerInstance: 3
→ parallelism: nobody is live — 3 place(s), 1 free, 1 role(s) held by a human (...)
  free: dev-core, dev-acme
```
Голова говорит «1 free», а строкой ниже названы ДВЕ роли (`dev-core`, `dev-acme`) без каких-либо признаков, что из них можно взять только одно место суммарно. Это ровно тот класс расхождения («два числа про одно и то же выглядят разными» / «одно число описывает два разных состояния»), ради устранения которого весь PR и затевался — только в необсчитанной комбинации входов. Ни один из пяти новых тестов эту ветку (`held` + `pairsPerInstance` одновременно, `live` пуст) не трогает — все пять used с непустым `live`.

Предлагаемое действие: свести число `N free` в этой ветке к тому же источнику, что и список (`free`/`boxFull`-осведомлённая величина, например сумма непотраченных мест по некалеченным ролям с учётом `boxFull`), и добавить юнит на этот кейс — по образцу пяти уже добавленных, с мутацией.
