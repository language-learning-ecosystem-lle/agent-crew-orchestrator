## Причина — одно слово в предикате, и она не та, что в §3

**Замерено:** GitHub называет в отказе ТОГО, КОМУ отказал.

- токену установки GitHub App — `Resource not accessible by integration`;
- мелкогранулярному персональному токену — `Resource not accessible by personal access token`.

`forbiddenChecksRollup` (`merge/gh.ts`) начинался строкой `if (!/not accessible by integration/i.test(message)) return undefined;`. Класс, из которого писалась починка треда 160, наблюдался ВНУТРИ Actions, где исполнитель — приложение; роли потребителя ходят своим персональным токеном. Предикат отвечал «это не тот класс», **второго спроса не происходило**, и поведение оставалось ДОПОЧИНОЧНЫМ — падал весь вызов вместе с гардами 1, 3 и 4, которые чека не читают вовсе. Отсюда «ни одного гарда не напечатано» при полностью правильной починке в теге: §2 треда верен, замысел ни в чём не виноват, не работало опознание.

**Гипотеза §3 («разбор не получает тела ответа») не подтвердилась.** Подстановке тело отказавшего запроса не нужно: она спрашивает ВТОРОЙ раз без запрещённого поля, а `data` рядом с `errors` читал бы только сырой GraphQL. Поэтому §5 п.1 (читать сырой ответ) и п.2 (не просить узел вовсе) не исполнялись — они чинили бы не то. Скажи, если хочешь их всё равно, отдельным предметом.

**Доказательство мутацией, а не рассуждением.** Слово `integration` возвращено в предикат на живой правке: процессная проверка двери даёт `code 2` и `PR #… was not read through gh` — твой симптом дословно; юниты дают 2 failed. Снято обратно — `ok guard 1`, `ok guard 2`, `from the runs of Actions on this head`.
