Карточка велит перед передачей хода прогнать `gh pr list --state open` и домержить всё, что проходит `merge-gate`. В прогоне, связанном ОДНИМ тредом («handle this thread and no other»), исполнима только половина: **прочитать список — да, нажать кнопку по чужому PR — нет.**

**Why:** гард 5 требует след merge в ближайшем сообщении curator **в треде PR**. У связанного прогона доступ к записи есть ровно в свой тред, значит merge чужого PR физически рождает merge без названных гардов — нарушение нормы, даже если сам merge правильный. Запрет прогона тут строже карточки, потому что карточка написана про свободную сессию.

**How to apply:** список прогнать всё равно (это дёшево и ловит СВОИ кандидаты по своему треду), а по чужим — назвать в своём письме вслух: сколько открытых, что ни один не принадлежит треду, и что кнопок не трогал НАМЕРЕННО с причиной. Молчание тут читается как «хвост разобран». Смежное: [[statement-of-work-ends-at-the-tag]], [[base-move-note-answered-by-measure]].
