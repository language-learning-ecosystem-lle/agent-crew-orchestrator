Дрейф-перезапуск ящика новый код НЕ проверяет. `self-restart.ts` (прочитано 2026-09-17 на
`c1240cf6`): тик спавнит отдельный процесс `spawn(input.node, [...nodeArgs, input.entry, ...argv])`
**ДО** pull, и pull делает уже спавненный процесс — то есть всю последовательность
(`down` → `pull --ff-only` → установка → подъём) исполняет **бинарь, который был на диске ДО
мёржа**. Новый код встаёт только поднятым демоном. Плюс шаг установки запускается, лишь **если pull
сдвинул манифесты** (`package.json`/`pnpm-lock.yaml`/`pnpm-workspace.yaml`) — дифф без них проходит
перезапуск вообще без установки.

**Why:** приёмка починки ПУТИ РЕСТАРТА (резолюция инструмента, текст отказа, порядок шагов) —
срабатывание, а не merge ([[new-execution-path-is-accepted-by-its-first-firing]],
[[merged-code-is-not-running-code]]). Ближайший самоперезапуск выглядит готовым полигоном —
`self-restart.json` уже несёт `target` = твой merge-коммит, — и объявить приёмку по нему значит
принять исполнение СТАРОГО кода за срабатывание нового.

**ЗАМЕРЕНО В ПОЛЕ 2026-09-17 — правило сошлось точно.** Эпизод `c1240cf6 → 9c4803d8` (починка #462)
шагов инструмента не назвал; СЛЕДУЮЩИЙ эпизод `9c4803d8 → 5cc15c23` (решающий демон бежал уже
`9c4803d8`) напечатал `running '/usr/bin/git' (from PATH — nothing beside this node binary)` и
`running '…/bin/pnpm' (beside this node binary)`. Два состояния одной строки лежат в `daemon.log`
подряд. Считать «второй» надо не по номеру, а по тому, ЧЕЙ КОД БЕЖИТ В РЕШАЮЩЕМ ДЕМОНЕ: эпизод `N`
исполняет бинарь, поднятый эпизодом `N−1`.

**How to apply:** чинишь путь рестарта — полигоном считай ВТОРОЙ перезапуск после мёржа, а не
первый; и если предмет — именно шаг установки, проверь, двигает ли дифф манифесты, иначе шага не
будет вовсе. Полевая ветвь (окружение БЕЗ nvm в `PATH`) вообще не воспроизводится самоперезапуском:
его `PATH` наследуется от демона, а тот поднят рукой из логин-шелла. Значит она — жест john
(`sudo -u aco-hetzner -i bash -lc 'orchestrator restart --pull'`), и просить его надо парком
`--parked-on john --expects ack` с вопросом первой строкой; своей рукой перезапуск не заказывают —
он убивает поднявшую тебя же сессию ([[ordering-a-firing-may-lock-the-role]]).
