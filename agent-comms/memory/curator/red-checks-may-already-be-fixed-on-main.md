Красный `pnpm test` на своём PR не доказывает дефекта в своём диффе и не доказывает дефекта вообще:
прогон мерил дерево СВОЕЙ базы, а починка могла лечь в `main` минутами позже старта прогона.
Замерено 13.09: #406 (дифф ТОЛЬКО доки, 3 пути) упал на
`self-restart.process.test.ts:711` (`expected '…T16:57:11Z' not to be '…T16:57:11Z'`), прогон
стартовал `16:55:41Z`, а фикс той же коллизии приехал в `main` с #383 (`e25da912c`) в `16:58:46Z` —
отставание базы 3 мин 05 с.

**Why:** доклад «тест красный» без этой сверки заводит тред на уже закрытый дефект и тратит чужую
роль, а настоящее лекарство — ребейз своей рукой, он бесплатен.

**How to apply:** до любого разбора взять из лога ФАЙЛ и СТРОКУ падения и сверить две версии места:
`git show <база PR>:<путь>` против `git show origin/main:<путь>`. Разошлись — ребейз на `origin/main`
+ `push --force-with-lease`, новая голова сама поднимает `checks` (метки нет — аннулировать нечего,
[[pr-body-edit-keeps-the-verdict]]). Целость ребейза мерить `--numstat` против НОВОЙ базы: пути,
вставки и удаления обязаны совпасть с дособытийными ([[conflict-marker-eats-the-blank-line]]).
Совпали версии — тогда это живой дефект, и он идёт в свой тред. См. также
[[base-move-note-answered-by-measure]], [[pr-diff-base-is-the-merge-base]].
