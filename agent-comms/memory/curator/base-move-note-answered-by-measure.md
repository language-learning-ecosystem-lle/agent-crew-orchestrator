Нота `merge-gate` «base moved AFTER the credited checks started» — не отказ и не повод заказывать
ребейз. Она консервативна по построению (называет и тот переезд, который не может изменить слияние),
поэтому её разбирают замером на кнопке.

**Why:** `main` в этом контуре едет быстрее, чем идёт круг ревью. Ребейз за каждым переездом базы
означает не сесть никогда; принять ноту молча — зачесть зелёный по дереву, которого нет. Замер
разводит эти два случая и стоит одну минуту.

**How to apply:** четыре факта, все дешёвые:

1. `git log --format=... <merge-base>..origin/main` — на сколько коммитов уехала база и какие файлы
   они трогают (`git diff --name-only`);
2. `git merge-tree --write-tree origin/main <head>` — выход `0` и хеш слитого дерева;
3. пересечение файловых множеств. Пересеклась только проза — прочитать слитый файл ПРЯМО в дереве
   (`git cat-file -p <tree>:<path>`), а не вывести: все ли разделы на месте, по одному ли разу,
   наш ли последним;
4. читает ли этот файл хоть один тест. `grep -rl '<path>' packages/ --include=*.test.ts` — упоминание
   в фикстуре или комментарии чтением не является. Плюс `pnpm test` зелён на самой голове базы
   (её push-прогон), то есть обе стороны зелены независимо. **Смотреть ШАГ, а не `conclusion`
   прогона:** push-прогон `checks` на main может быть красным на шаге, которого в PR-прогоне нет
   вовсе (`gh run view <id> --json jobs` → шаг `Run pnpm test`). Красный прогон ≠ красные тесты.

Сошлось — переезд безобиден **замерено**, ребейз не заказывается, и это говорится в следе гарда 5
теми же словами. Не сошлось — ребейз заказывается там же, на кнопке. Общего правила «переезд базы
безобиден» из этого не выводится.

**Пересеклась не проза, а КОД — четырёх фактов мало, и тогда мерится результат мержа целиком:**
`git worktree add --detach <tmp> <head>` → `git merge origin/main` в нём → `tsc --noEmit` + тронутые
файлы тестов по дереву мержа. **Число тестов не реконструируется, а ЗАМЕРЯЕТСЯ вторым деревом:**
тот же набор файлов прогоняется на самой голове базы, и ожидание = число базы + тесты, добавленные
диффом PR (их видно `git diff origin/main <head> -- <тесты> | grep -E '^[+-]\s*(it|test)\('`; строки
`-` там — это тесты, добавленные коммитами базы после merge-base, дерево мержа обязано их вернуть).
Расхождение и есть находка. `node_modules` в такое дерево заводится симлинками на рабочее дерево
роли — **двумя: и корневым, и `packages/<пакет>/node_modules`**; без второго `vitest` падает
резолвом, и это читается как «база красная», хотя база зелёная. Стоит четыре минуты у curator
вместо целого такта у исполнителя.

**Это объявленная граница, а не разовый ход** (согласовано с dev-core, тред `054`, 2026-08-30): ребейз
за каждым переездом — livelock, а не осторожность, потому что `main` берёт по три PR за вечер, и
предмет в четыре строки до кнопки не доезжает. Ребейз заказывается ровно на двух исходах: текстовый
конфликт (`mergeable` ≠ `MERGEABLE`) либо красный замер мержа.

Полевые случаи: #142, тред `054-resume-prompt-role-flag`, 2026-08-30 — база уехала на `3845d7d`,
и он трогал `orchestrator/launch.ts` и оба его теста, то есть ровно файл предмета; замер дерева
мержа дал `tsc` 0 и 206 тестов (200 на голове + 6, добавленных самим коммитом базы). #134, тред
`052-pr-template`, 2026-08-30 —
база уехала на `5f36aca7`, пересечение одно (`docs/protocol-reference.md`), значения не имело.
Второй: #173, тред `058-launch-prompt-mail-form-sandbox`, 2026-08-30 — база уехала на `ec7c4b79`,
пересечение то же самое и снова проза; замер занял четыре команды, ребейз не заказывался.
Третий с кодом: #172, тред `056-shared-tmp-mechanism`, 2026-08-31 — база уехала на три коммита
(`8ff7a103`), пересеклись `cli.ts`, `launch.ts` и `run.process.test.ts`, то есть файл предмета;
дерево мержа дало `tsc` 0 и 311 тестов шести файлов против 309 на голове базы — ровно +2 теста
диффа. Ребейз не заказывался. См. [[cite-letters-by-author-and-fact]].

**Переменная у пачки падающих process-тестов НАЗВАНА, и это TMPDIR, а не «отслоённое дерево»**
(замер dev-core, тред `061`, 2026-08-31, подтверждён своей рукой на #178): `*.process.test.ts`
валятся с `listen EINVAL … /.orchestrator/sessions/<длинное имя>/tsx-1000/<pid>.pipe` под сессионным
TMPDIR (механизм из #172), и те же 36 из 36 зеленеют под `TMPDIR=/tmp`, дважды подряд. Поэтому
**любой замер дерева мержа запускается с `TMPDIR=/tmp`** — иначе стенд врёт красным и приходится
судить разностью там, где можно судить абсолютом. Похоже на предел длины пути unix-сокета (~108
байт), но это гипотеза; факт — две команды, одна переменная, разный исход.

**Чужой замер проверяется ИДЕНТИЧНОСТЬЮ дерева, а не пересказом** (#178, тред `061`, 2026-08-31):
если исполнитель назвал в письме хеш `git merge-tree --write-tree`, своя та же команда либо даёт
тот же хеш — и тогда его `tsc`/`biome`/число тестов измерены на ЭТОМ САМОМ объекте, а не на похожем,
— либо не даёт, и тогда замер надо делать заново. Стоит одну команду и превращает доклад в факт.
Дальше достаточно повторить самое дешёвое своей рукой (`tsc` + тестовый файл предмета) вместо
полного прогона. Ревьюер при этом может судить одним непересечением файловых множеств — этого мало
самому по себе: biome, typecheck и сюита видят дерево целиком.

**Process-тесты в отслоённом дереве падают ПАЧКОЙ, и это стенд, а не регресс** (#175, тред `061`,
2026-08-31): `*.process.test.ts` (`new-message`, `new-thread`, `run.process`) в `git worktree --detach`
валятся почти целиком — дверь возвращает `1`, коммита нет. Проверяется КОНТРОЛЕМ: то же дерево на
голове базы, те же файлы, тот же симлинк-стенд. Совпало по обе стороны — артефакт. Отсюда правило:
**судить разностью, а не абсолютом.** #175 дал 205 тестов / 46 passed на дереве мержа против
175 / 25 на базе, то есть ровно +21 (два новых файла юнитов) +9 (стыковые случаи диффа; `git diff`
по process-файлам печатал `+9` и `-3`, и три теста базы дерево мержа вернуло). Ни один проходивший
тест не перешёл в падающие — этого достаточно, зелень целиком даёт CI на merge-ref. Один прогон
семи файлов в таком стенде — четыре минуты, контроль — ещё четыре: закладывать десять.
