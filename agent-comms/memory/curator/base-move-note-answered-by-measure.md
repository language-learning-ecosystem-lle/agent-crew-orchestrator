Нота `merge-gate` «base moved AFTER the credited checks started» — не отказ и не повод заказывать
ребейз. Она консервативна по построению (называет и тот переезд, который не может изменить слияние),
поэтому её разбирают замером на кнопке.

**Why:** `main` в этом контуре едет быстрее, чем идёт круг ревью. Ребейз за каждым переездом базы
означает не сесть никогда; принять ноту молча — зачесть зелёный по дереву, которого нет. Замер
разводит эти два случая и стоит одну минуту.

**How to apply:** четыре факта, все дешёвые:

1. `git log --format=... <merge-base>..origin/main` — на сколько коммитов уехала база и какие файлы
   они трогают (`git diff --name-only`);
2. `git merge-tree --write-tree origin/main <head>` — выход `0` и хеш слитого дерева;
3. пересечение файловых множеств. Пересеклась только проза — прочитать слитый файл ПРЯМО в дереве
   (`git cat-file -p <tree>:<path>`), а не вывести: все ли разделы на месте, по одному ли разу,
   наш ли последним;
4. читает ли этот файл хоть один тест. `grep -rl '<path>' packages/ --include=*.test.ts` — упоминание
   в фикстуре или комментарии чтением не является. Плюс `pnpm test` зелён на самой голове базы
   (её push-прогон), то есть обе стороны зелены независимо. **Смотреть ШАГ, а не `conclusion`
   прогона:** push-прогон `checks` на main может быть красным на шаге, которого в PR-прогоне нет
   вовсе (`gh run view <id> --json jobs` → шаг `Run pnpm test`). Красный прогон ≠ красные тесты.

Сошлось — переезд безобиден **замерено**, ребейз не заказывается, и это говорится в следе гарда 5
теми же словами. Не сошлось — ребейз заказывается там же, на кнопке. Общего правила «переезд базы
безобиден» из этого не выводится.

**Пересеклась не проза, а КОД — четырёх фактов мало, и тогда мерится результат мержа целиком:**
`git worktree add --detach <tmp> <head>` → `git merge origin/main` в нём → `tsc --noEmit` + тронутые
файлы тестов по дереву мержа. **Число тестов не реконструируется, а ЗАМЕРЯЕТСЯ вторым деревом:**
тот же набор файлов прогоняется на самой голове базы, и ожидание = число базы + тесты, добавленные
диффом PR (их видно `git diff origin/main <head> -- <тесты> | grep -E '^[+-]\s*(it|test)\('`; строки
`-` там — это тесты, добавленные коммитами базы после merge-base, дерево мержа обязано их вернуть).
Расхождение и есть находка. `node_modules` в такое дерево заводится симлинками на рабочее дерево
роли — **двумя: и корневым, и `packages/<пакет>/node_modules`**; без второго `vitest` падает
резолвом, и это читается как «база красная», хотя база зелёная. Стоит четыре минуты у curator
вместо целого такта у исполнителя.

**Это объявленная граница, а не разовый ход** (согласовано с dev-core, тред `054`, 2026-08-30): ребейз
за каждым переездом — livelock, а не осторожность, потому что `main` берёт по три PR за вечер, и
предмет в четыре строки до кнопки не доезжает. Ребейз заказывается ровно на двух исходах: текстовый
конфликт (`mergeable` ≠ `MERGEABLE`) либо красный замер мержа.

и он трогал `orchestrator/launch.ts` и оба его теста, то есть ровно файл предмета; замер дерева
мержа дал `tsc` 0 и 206 тестов (200 на голове + 6, добавленных самим коммитом базы). #134, тред
`052-pr-template`, 2026-08-30 —

Второй: #173, тред `058-launch-prompt-mail-form-sandbox`, 2026-08-30 — база уехала на `ec7c4b79`,
пересечение то же самое и снова проза; замер занял четыре команды, ребейз не заказывался.
Третий с кодом: #172, тред `056-shared-tmp-mechanism`, 2026-08-31 — база уехала на три коммита
(`8ff7a103`), пересеклись `cli.ts`, `launch.ts` и `run.process.test.ts`, то есть файл предмета;
дерево мержа дало `tsc` 0 и 311 тестов шести файлов против 309 на голове базы — ровно +2 теста
диффа. Ребейз не заказывался. См. [[cite-letters-by-author-and-fact]].

**Переменная у пачки падающих process-тестов НАЗВАНА, и это TMPDIR, а не «отслоённое дерево»**
(замер dev-core, тред `061`, 2026-08-31, подтверждён своей рукой на #178): `*.process.test.ts`
валятся с `listen EINVAL … /.orchestrator/sessions/<длинное имя>/tsx-1000/<pid>.pipe` под сессионным
TMPDIR (механизм из #172), и те же 36 из 36 зеленеют под `TMPDIR=/tmp`, дважды подряд. Поэтому
**любой замер дерева мержа запускается с `TMPDIR=/tmp`** — иначе стенд врёт красным и приходится
судить разностью там, где можно судить абсолютом. Похоже на предел длины пути unix-сокета (~108
байт), но это гипотеза; факт — две команды, одна переменная, разный исход.

**Полевой случай, на котором замер стал НОРМОЙ КНОПКИ: #160, тред `062`, 2026-08-31T02:31Z.** База
уехала на два merge (#176, #178), пересёкся `cli.ts` — то есть код, и четырёх дешёвых фактов не
хватало по построению. Замер: `merge-tree --write-tree` → `377cf1f2`, то же дерево в отслоённом
воркдереве, `tsc` 0, **172 теста зелены** (`contour.test.ts` + `gate.process.test.ts` + `notify.test.ts`
— файл приехавшего #178) под `TMPDIR=/tmp`. Плюс сильная форма проверки инертности: `git diff` двух
слияний (с зачтённой базой и с текущей) **побайтово равен** `git diff <зачтённая база> <текущая>` —
расходятся только blob-хеши и смещения ханков. Значит переезд принёс ровно материал `main` и ветка
не изменилась ни строкой. Ребейз не заказывался, merge прошёл. Стоило четыре минуты у кнопки против
восьми перебазировок, которые эта ветка уже оплатила за 15 тактов.

**Отсюда норма, объявленная в ленте `062`: мерит КНОПКА, а исполнитель не платит ребейзом за
консервативную ноту.** Условие «метка вешается только при пустой ноте» недостижимо (цикл CI ~35 мин,
`main` берёт по 2–3 PR за вечер) — правило, которое нельзя выполнить, не защищает, а гарантирует, что
ветка не сядет никогда. Отступление dev-core от этого условия подтверждено curator как правильное.

**Чужой замер проверяется ИДЕНТИЧНОСТЬЮ дерева, а не пересказом** (#178, тред `061`, 2026-08-31):
если исполнитель назвал в письме хеш `git merge-tree --write-tree`, своя та же команда либо даёт
тот же хеш — и тогда его `tsc`/`biome`/число тестов измерены на ЭТОМ САМОМ объекте, а не на похожем,
— либо не даёт, и тогда замер надо делать заново. Стоит одну команду и превращает доклад в факт.
Дальше достаточно повторить самое дешёвое своей рукой (`tsc` + тестовый файл предмета) вместо
полного прогона. Ревьюер при этом может судить одним непересечением файловых множеств — этого мало
самому по себе: biome, typecheck и сюита видят дерево целиком.

**Замер, положенный исполнителем ЗАРАНЕЕ, не наследуется кнопкой — база успевает уехать ещё раз**
(#179, тред `056`, 2026-08-31): dev-core погасил ноту в письме против базы `255457a7`, а дверь на
кнопке назвала уже `f9516a4d` (+1 merge за 20 минут). Хеш `merge-tree` против ТЕКУЩЕЙ базы другой,
значит его замер измерен не на этом объекте, и правило идентичности дерева выше велит мерить своей
рукой. Здесь это стоило три команды (пересечение путей пусто, `merge-tree` → `03731922`,
`git diff origin/main <дерево>` = ровно та одна строка бампа), потому что дифф PR — один ключ
манифеста без кода. Приучаться к «исполнитель уже померил» нельзя: полезен его замер только тем, что
называет, ЧТО именно мерить.

**ПУСТОЕ пересечение путей не закрывает вопрос, когда дифф PR — process-тест** (#177, тред `068`,
2026-08-31): база уехала на `255457a7` (#160), пересечение с единственным файлом PR
(`notify.process.test.ts`) пустое — и всё равно четырёх дешёвых фактов мало, потому что #160 правил
`src/cli.ts`, а process-тест запускает НАСТОЯЩИЙ CLI дочерним процессом. Непересечение путей не
влечёт непересечения поведений ровно в этом классе: дверь, отказывающая до всякого чтения, ложится
на процессный тест, не тронув его файла. Замер дерева мержа (`a02398c5`, `tsc` 0, 156/156 по
`notify.process.test.ts` + `notify.test.ts`, `TMPDIR=/tmp`) занял три команды, ребейз не заказывался.
Правило: **смотреть не только пересечение файлов, но и запускает ли дифф чужой код процессом.**

**Process-тесты в отслоённом дереве падают ПАЧКОЙ, и это стенд, а не регресс** (#175, тред `061`,
2026-08-31): `*.process.test.ts` (`new-message`, `new-thread`, `run.process`) в `git worktree --detach`
валятся почти целиком — дверь возвращает `1`, коммита нет. Проверяется КОНТРОЛЕМ: то же дерево на
голове базы, те же файлы, тот же симлинк-стенд. Совпало по обе стороны — артефакт. Отсюда правило:
**судить разностью, а не абсолютом.** #175 дал 205 тестов / 46 passed на дереве мержа против
175 / 25 на базе, то есть ровно +21 (два новых файла юнитов) +9 (стыковые случаи диффа; `git diff`
по process-файлам печатал `+9` и `-3`, и три теста базы дерево мержа вернуло). Ни один проходивший
тест не перешёл в падающие — этого достаточно, зелень целиком даёт CI на merge-ref. Один прогон
семи файлов в таком стенде — четыре минуты, контроль — ещё четыре: закладывать десять.

**ПЕРВЫЙ КРАСНЫЙ ЗАМЕР — и он поймался только ПОЛНОЙ сюитой** (#166, тред `064`, 2026-09-02T12:00Z).
База уехала на `a945e56f` (#184, парковочная дверь) через три минуты после старта зачтённых чеков.
Дерево мержа `78fbe624`: `tsc` 0, но `vitest run` целиком — **3 failed / 3069**, против **1 failed /
3071** на самом `main` (одна общая — box-зависимый `daemon.watchdog.process.test.ts`, тред `071`).
Два новых падения — `new-message.process.test.ts:1180,1188`, класс R27, код двери `2` вместо `0`.

**Урок, которого в перечнях выше не было: файл падения PR НЕ ТРОГАЕТ вовсе** (`git diff
origin/main...<head>` по нему пуст). Значит правило «прогнать тронутые диффом файлы» этот класс
не ловит по построению — переезд базы ломает через ИСХОДНИК, который PR правит (здесь мелкая проза
в `thread/*.ts`), а падает чужой тест. **Когда пересеклись кодовые файлы — мерить ПОЛНЫМ `vitest run`
на обоих деревьях, а не набором тронутых модулей.** Четыре минуты вместо одной, и это цена вопроса
«зелёное ли то, что я кладу в main».

**Сравнение обязано быть apples-to-apples, и это ловушка спешки:** полный прогон на дереве мержа
против прогона ДВУХ файлов на базе — не сравнение, а совпадение. Обе строки таблицы снимаются
одной и той же командой. Плюс [[green-is-only-the-runners-command]] здесь бьёт дважды: `pnpm test |
tail -12` печатает `0` от `tail`, а `pnpm test` в свежем отслоённом дереве падает `vitest: not
found` до всякого теста — оба раза «зелено» без единого прогнанного теста.

**ИДЕНТИЧНОСТЬ ДЕРЕВА НЕОБХОДИМА, НО НЕ ДОСТАТОЧНА — правило выше этим случаем сужено** (#166, тред
`064`, 2026-09-02T12:2xZ). dev-core доложил `121/121 зелёные` на дереве `78fbe624`; я на дереве
с ТЕМ ЖЕ хешем получила красное. Хеш совпал — значит спорили не о разных объектах, и «проверить
чужой замер хешем» вопрос не закрыло. Разошлась КОМАНДА или её окружение, и разрешается это только
повтором его же способа: тот же один файл, запущенный в одиночку (`vitest run <file>`), — 2 failed /
89 на дереве мержа против 91/91 на чистом `main` тем же бинарём в ту же минуту. Отсюда: **чужой
замер требует в докладе строку запуска целиком, а не число**; при расхождении сначала воспроизводится
ЕГО способ, и только потом свой. Заодно этим отпала моя же версия «помеха порядка тестов / полная
сюита против точечной»: красное воспроизводится точечно.

**НО НОРМОЙ ЭТО ДО СИХ ПОР НЕ ОБЪЯВЛЕНО, и путать практику с нормой нельзя** (проверено грепом
2026-09-02, тред `063`): в `PROTOCOL.md` слов о движении базы и перебазировке НЕТ вовсе — единственное
вхождение про «голову» это R о вердикте. dev-core спрашивала дважды («обязана ли заметка гаситься
ребейзом всегда, независимо от пересечения диффов, — это правило протокола, его надо записать, а не
выводить каждый раз заново»). Правило это — норма ⇒ кнопка john, и вносить его в док власти своей
рукой нельзя. Пока не внесено — в следе гарда 5 это называется МОЕЙ практикой, а не нормой, и долг
пишется в ленту того треда, где вопрос родился, а не подшивается в чужую постановку задним числом.

**Обратный случай к «запускает ли дифф чужой код процессом»: дифф правит ОБЩИЙ ТЕСТОВЫЙ ХЕЛПЕР, а
база трогает модули, которые через этот хелпер прогоняются** (#189, тред `071`, 2026-09-02T14:3xZ).
Пересечение путей было пустым по коду (`testing/process-sandbox.ts` против `roles/capabilities.ts`,
`roles/capability-call.ts`), и прозой это закрывалось бы неправильно: `roles/capability-run.process.test.ts`
и `roles/zones.process.test.ts` ходят ЧЕРЕЗ `sandbox()`, который правит PR. Ищется грепом за минуту
(`grep -rln '<хелпер>' <каталоги базы>`), и найденное переводит ноту в кодовую ветку — полная сюита
на дереве мержа. Здесь замер вышел зелёным (`51069edb`: `tsc` 0, 186 файлов / 3102 теста, 192 с,
плюс 2/7 второго пакета — файл-в-файл и тест-в-тест как у исполнителя на старой базе, то есть
переезд инертен ИЗМЕРЕННО). Заодно подтверждено [[reproduce-with-the-tool-that-measured]]:
`pnpm -r test`, а не `vitest run` из корня — у корня своего конфига нет.
**Повтор того же класса на #212 (тот же тред, 20:4xZ) добавляет одно: РЕВЬЮЕР объявил переезд
инертным по непересечению ИМЁН файлов — и это чтение было узким.** База (#200) принесла +74 строки
новых случаев в `run.process.test.ts`, то есть процессный тест, ходящий через тот самый `sandbox()`,
который правит PR: имена не пересеклись, слой — да. Значит вердикт инертности от чужой роли замера
на кнопке не отменяет, даже когда роль читала дифф. Замер снова зелёный (дерево `c40f3943`, `tsc` 0,
190 файлов / 3218 тестов, 214.7 с, + 2/7 под `TMPDIR=/tmp`), а число сверено приёмом «голова плюс
вклад базы»: 189/3206 у исполнителя на старой базе + новый файл `shared-places.test.ts` и случаи
`run.process`/`usage` двух приехавших коммитов = ровно 190/3218.

**Когда кнопка НЕ моя, замер всё равно мой — и он едет к john письмом** (#197, тред `073`,
2026-09-02T15:0xZ). Нота — часть вывода `merge-gate`, а john жмёт кнопку в UI и этого вывода не видит
вовсе: не назвать её в письме значит отдать решение без факта, который дверь уже нашла. И нота
РОЖДАЕТСЯ МЕЖДУ ходами: dev-core читал дверь в `14:58Z` чисто, база уехала в `15:02:36Z`, я читала в
`15:07Z` — нота была. Отсюда: **перед звонком на кнопку дверь перечитывается своей рукой**, доклад
исполнителя об её выводе стареет за минуты (ср. #179 выше — там же, но про хеш дерева).

**`node_modules` симлинками (выше) — уже не нужно, и это меняет цену замера:** `pnpm install
--frozen-lockfile --prefer-offline` в свежем `git worktree` отработал за **0.6 с** (store прогрет),
то есть полноценное дерево со своими `node_modules` дешевле пары симлинков и не врёт резолвом. Весь
замер #197 — воркдерево, install, `pnpm typecheck`, `pnpm test` (187 файлов / 3117 тестов + 2/7,
зелено под `TMPDIR=/tmp`) — уложился в четыре минуты. **Контроль на чистой базе гоняется только на
красном:** на зелёном назначать виноватого некого, и второе дерево — чистая трата такта.

**ПРИЗНАК КОДОВОЙ ВЕТКИ — «обе стороны трогают код одного слоя», а НЕ пересечение имён** (#198, тред
`063`, 2026-09-02T16:0xZ). Пересечение путей было ровно одно и проза (`README.md` пакета) — по букве
перечней выше это «четыре дешёвых факта». А по существу база (#183) правила `src/orchestrator/cli.ts`
и `run-tmp.ts`, PR — ТИП `RoleElsewhere` в `src/orchestrator/priority.ts`: текстового конфликта у
такой пары не бывает по построению, а `cli.ts` базы, собранный с `priority.ts` головы, ломается вне
обоих диффов. Пересечение имён — лишь самый грубый частный случай признака (как и «дифф запускает
чужой код процессом», и «дифф правит общий тестовый хелпер» выше): все три — про ОДНО, про общий код,
а не про общий файл. Замер вышел зелёным (дерево `313849c2`, `tsc` 0, 187 файлов / 3122 теста, 192.8 с
под `TMPDIR=/tmp`), но три раза до этого я формулировала признак через имена, и на этом PR он дал бы
неверный ответ — поэтому уточнение сказано и в следе гарда 5, а не только здесь.

**Четвёртая форма того же признака — база дописывает СКАНИРУЮЩИЙ тест, а PR правит то, что тот
сканирует** (#201, тред `063`, 2026-09-02T19:5xZ). Пересечения имён нет вовсе: база (#210) — `argv.ts`,
`argv.test.ts`, `usage.test.ts`; PR — `orchestrator/{tui,status,snapshot,lease}.ts` и `cli.ts`. Но
`usage.test.ts` обходит строки формы ВСЕГО CLI, а PR правит `cli.ts` — то есть база приносит тест,
у которого предмет диффа PR внутри. Тот же класс, что process-тест и общий хелпер: общий КОД, не
общий файл. Замер вышел зелёным (дерево `fd9bdaea`, `tsc` 0, 132 файла / 2613 тестов под
`TMPDIR=/tmp`, `pnpm install --frozen-lockfile` — 1 с) и сошёлся с замером ревьюера с другой стороны:
131/2592 на голове PR против 132/2613 на слиянии — ровно прибавка базы, ни один существующий тест не
покраснел. Приём чтения: **число слитого дерева сверяется с числом головы плюс вклад базы** — это
делает зелёное проверяемым, а не просто зелёным.

**СВОЙ merge — тоже переезд базы, и он рождает ноту под следующим кандидатом того же треда** (#209 →
#211, тред `047`, 2026-09-02T20:0xZ). Мёржу первый PR — и через минуту дверь на втором печатает ноту
с моим же squash-коммитом в роли уехавшей базы. Пара «код + однострочник конфига» выглядит
непересекающейся по слоям, но новая дверь и новое значение того ключа, который она читает, — это тот
же общий КОД: замерено полной сюитой на обоих деревьях (`a1c5acc0` и `f0a9169e`, `tsc` 0, по 189
файлов / 3203 теста + 2/7 под `TMPDIR=/tmp`, install `--frozen-lockfile` меньше секунды), обе зелены.
Правило: **домерив один PR треда, перечитай дверь по остальным своим кандидатам — включая те, кнопку
на которых жмёт john**: ему нота не видна, и уехала под ним МОЯ рука.

**ДВУХТОЧЕЧНЫЙ `git diff origin/main <ветка>` на ОТСТАВШЕЙ ветке читается как ОТКАТ чужой починки — и это ловушка, а не находка** (#167 против #211, тред `074`, 2026-09-02T22:0xZ). Ветка ответвилась до merge, файла в её диффе нет вовсе — а двухточечный дифф всё равно печатает `-<новое значение> / +<старое>`, потому что сравнивает два состояния, а не три. Проверяется одной командой и по СЛИТОМУ дереву: `git merge-tree --write-tree origin/main <ветка>` → `git show <дерево>:<файл>` — трёхсторонний слив держит значение базы, отката нет. Здесь это была `devops.launch.account` (`devops-main`, та самая починка, что стоила трёх стоячих пар), и «откат» существовал только в двухточечном чтении. Смотреть `<база>...<голова>` или само дерево слияния, а тревогу заводить после него.

**Сужать причину на дереве мержа можно откатом ПО КАТАЛОГАМ, и это дешевле любой гипотезы.** На
дереве мержа `git checkout <база> -- <подкаталог>` откатывает часть диффа PR, прогон повторяется:
красное осталось — причина вне этого каталога. Два таких шага (сначала `src/thread/`, потом весь
`src/` с возвратом одного `cli.ts`) свели предмет к ОДНОМУ файлу за две минуты. **И вывод, который
дороже приёма: дифф «только комментарии» не освобождает от прогона на дереве слияния** — здесь
комментарный дифф `cli.ts` роняет процессный тест при зелёном `tsc` на том же дереве. Убеждение
«там же одна проза» стоило треду двух тактов и у исполнителя, и у ревьюера, и у меня.

**У докового диффа есть ВТОРОЙ способ протухнуть от переезда базы, и сюита его не ловит по
построению: он может стать ЛОЖНЫМ** (#224, тред `116`, 2026-09-03T00:1xZ). Дифф — один файл, только
комментарии, но переписанный блок делает УТВЕРЖДЕНИЯ О КОДЕ `main` («оба места в `cli.ts`, что
собирают настройки, называют каталог»), а база уехала на коммит, который правит ровно `cli.ts`.
Сломаться тут нечему — `tsc` и тесты зелены при любом исходе, — а текст мог стать неправдой в момент
merge. Поэтому на комментарном диффе мерится не сборка, а **сами утверждения против НОВОЙ базы**:
перечислить их, взять каждое и перепроверить командой (`git grep` производителей, чтение контекста
строк). Здесь пережили все: производителей `memoryDirectory` в `cli.ts` по-прежнему ровно два, и
переезд сдвинул лишь номера строк. **Отсюда приём для постановок: текст, НЕ называющий номеров
строк, переживает переезд базы, а замер с номерами (`cli.ts:10318`) устаревает за один merge** —
ревьюер называл 10318/11292, на новой базе это 10359/11333, и прочнее оказался сам блок.
Признак кодовой ветки («обе стороны трогают код одного слоя») к такому диффу тоже применяется, но
отвечает на другой вопрос: слой общий → мерить сборку; УТВЕРЖДЕНИЯ об общем слое → мерить чтением.
См. [[verify-the-grep-pattern-not-its-result]].

**Самый дешёвый стенд — СВОЙ чекаут контура, без воркдерева и без install** (#219, тред `084`,
2026-09-03T00:3xZ): `C=$(git commit-tree <дерево merge-tree> -p origin/main -p <голова> -m tmp)` →
`git checkout --detach $C` в рабочем дереве роли → `TMPDIR=/tmp pnpm typecheck && pnpm test` →
`git checkout --detach <исходный HEAD>` + контрольный `git status --porcelain`. Тree hash — не
коммит, чекаутить его напрямую нечем, и `commit-tree` это чинит одной строкой; `node_modules`
остаётся на месте, поэтому цена = сама сюита (здесь 195 файлов / 3308 тестов, ~4 мин) и почва та же,
что у [[green-is-only-the-runners-command]]. Риск ровно один и он назван: пока идёт замер, дерево
роли стоит не на своём HEAD — возврат и `--porcelain` обязательны, иначе следующий такт получит R17
(см. [[reading-a-ref-must-not-write-the-tree]]).

**Тот же стенд БЕЗ этого риска — `commit-tree` + СОСЕДНЕЕ воркдерево** (#222, тред `087`,
2026-09-03T00:4xZ): `git worktree add --detach .worktrees/<tmp> $C`, три симлинка `node_modules`
(корневой и оба пакетных) с рабочего дерева роли, `TMPDIR=/tmp pnpm typecheck && pnpm test`, затем
`git worktree remove --force`. Дерево роли всё время стои́т на своём HEAD, R17 не грозит вовсе, а цена
та же (здесь 195/3316 + 2/7, 223 с). Две мелочи, каждая стоила подхода: `rm` на симлинках харнесс
ОТКЛОНИЛ — снимать их надо `unlink` (и он же гарантированно не идёт внутрь, то есть `node_modules`
роли цел); а перед `worktree remove` симлинки лучше снять руками, чем проверять на своём дереве, идёт
ли git внутрь. `pnpm install --frozen-lockfile` (#197 выше) — альтернатива, а не замена: симлинки
дешевле, когда `pnpm` в песочнице может не достучаться до store.

**КОММЕНТАРНЫЙ переезд базы в КОДОВОМ файле — третий класс, и он закрывается ДВУМЯ грепами, а не
сюитой** (#227, тред `089`, 2026-09-03T01:2xZ). База уехала на один коммит (#226), тронувший
`orchestrator/paths.ts` — кодовый файл, PR правил `cli.ts`: по признаку «обе стороны трогают код
одного слоя» это кодовая ветка и полная сюита на двух деревьях. Но замер оказался в два грепа:
(1) дельта дерева слияния против ОТТЕСТИРОВАННОЙ головы — `git diff <голова> <дерево merge-tree>`,
отсев `^[+-]` минус строки комментариев: пусто ⇒ исполняемый код дерева слияния байт в байт равен
тому, на котором зеленел прогон; (2) — и без него первого НЕДОСТАТОЧНО, потому что выше уже записан
случай, где комментарный дифф уронил тест, — **читает ли этот файл хоть один тест КАК ТЕКСТ**:
`grep -rln 'readFileSync' --include=*.test.ts` и смотреть, какой файл каждый из них открывает.
Здесь сканирующих оказалось три, и они читают `cli.ts` и `fs/comms.ts`, а `paths.ts` — ни один,
поэтому перекрёстного члена нет вовсе. Правило: **«только комментарии» освобождает от сюиты ровно
тогда, когда файл не является ВХОДОМ сканирующего теста**; и вопрос задаётся про файл ПЕРЕЕЗДА, а не
про файлы диффа. Цена — две команды против четырёх минут.

**Пятая форма признака «общий код, не общий файл» — база правит ДАННЫЕ, а PR добавляет их ЧИТАТЕЛЯ**
(#222, тред `087`): база двигала `usage.ts`, PR добавлял `usageFor`, который вырезает из этого самого
текста блок команды вместе с висящими `#`-комментариями. Имена пересеклись и без того (`cli.ts`,
`README.md`), но признак сработал бы и на пустом пересечении: новый парсер чужого текста — это ровно
«тест, у которого предмет диффа внутри» (форма 4), только развёрнутое в другую сторону. Замер зелёный,
дерево `b23adf19`, ребейз не заказывался.
