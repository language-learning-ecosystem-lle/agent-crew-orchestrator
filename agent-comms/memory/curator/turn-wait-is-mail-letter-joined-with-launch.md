Замер «сколько ход ждёт роль» собирается из двух источников: `git grep -m1 "^waiting-on:" origin/comms -- '*.md'` из почтового чекаута (путь файла даёт тред и штамп, строка — роль) против событий `{"kind":"launch"}` в `.orchestrator/journal.jsonl`; ожидание = `launch.ts − ts первого непотреблённого письма` этой пары. Событие `handoff-detected` в журнале для этого НЕ годится: оно есть лишь у 1019 подъёмов из 1736 и рождается по другому поводу — наивный join по нему даёт n=0.

**Why:** john держит видимым размен «круги ревью против ожидания», и прибора под него в пакете нет — считается руками этой парой источников. Вторая половина (круги) — `gh run list --workflow 'Claude PR Review'`, только `event=pull_request`, против `gh pr list --state merged`; обе усекаются молча к новейшим N ([[run-list-truncates-to-the-newest-n]]).

**ЗАПИСИ МЕТОДА НЕ ХВАТАЕТ, ЧТОБЫ ПОВТОРИТЬ ЗАМЕР (поле 14.09, тред `194`):** исполнив описанное выше буквально, я получила на ТОМ ЖЕ окне `09-02 … 09-09T16:03` медианы 55.3 сырых / 24.0 очищенных против записанных 14.8 / 11.4 — расхождение вчетверо, и оно на ОБОИХ концах, то есть разный ОТБОР ПИСЕМ, а не разные сутки. Какой отбор стоял у снимка 13.09 — из этой записи не восстанавливается. Отсюда правило: **числа разных снимков этой величины между собой НЕ СРАВНИВАТЬ**, сравнивать только строки ОДНОЙ таблицы, снятой одной командой за один ход; расхождение называть своей рукой как своё ([[reproduce-with-the-tool-that-measured]]). Третий прибор на ту же величину — `scripts/turn-latency.mjs` — даёт на «базовом после» медиану 52.3 мин: он меряет `handoff-detected`, а не письмо, и его числа тоже не сопоставимы ни с одним из двух.

**How to apply:** сырую медиану публиковать нельзя одну: парк и замёрзший тред считаются «ожиданием» сутками и переворачивают знак (13.09: сырые 14.8 → 19.3 мин против очищенных от >6 ч 11.4 → 8.8 мин). Печатать ОБЕ колонки и долю ожиданий длиннее порога, называя порог своей рукой. Считать ДВЕ выборки и говорить, какая основная: все письма против только ПЕРЕДАЧ хода (автор ≠ `waiting-on`) — они расходятся вдвое на сырой медиане. И помнить, что окно с закрытой дверью merge красит эту метрику как занятость роли: 14.09 авария круга 17:33Z→09:21Z дала медиану 71.9 мин на `09-13` против 10.8 на `09-14` ([[red-checks-may-already-be-fixed-on-main]]).
