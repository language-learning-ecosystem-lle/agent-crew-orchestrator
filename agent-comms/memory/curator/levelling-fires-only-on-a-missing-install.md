`levelling.install` = `mayLevel(staleBuild !== undefined || !dependencies.installed)` (`cli.ts`,
ветвь запуска). Обе половины мерятся так:

- **сравнение сборок инертно ЗДЕСЬ по построению.** `checkWorkspacePackage` сравнивает ВЕРСИЮ
  установленного пакета в дереве роли с версией в домашнем чекауте и возвращает `{ok:true}` без
  всякой ноты, когда `reference === undefined` — а это ровно случай контура, который гонит пакет ИЗ
  СВОЕГО ИСХОДНИКА (`.../node_modules/agent-protocol` нет ни в одном дереве, включая домашнее). То
  есть `staleBuild` тут не выставляется НИКОГДА;
- **остаётся одно: `checkWorkspaceDependencies`** — есть ли install-корни (`node_modules`) в дереве
  пары.

Практическое следствие, которое легко предсказать неверно: **переезд домашнего чекаута на новый
коммит НЕ делает деревья ролей «позади сборки»** и выравнивания не зажигает — «сборка» здесь
опознаётся ВЕРСИЕЙ пакета, а не коммитом. Зажигает его только ПЕРВЫЙ подъём пары, чьё дерево создано
заново (новый тред; дерево, взятое уборкой и пересозданное). У всех живых деревьев `node_modules`
есть, значит на существующей паре выравнивание молчит — и молчит БЕЗ строки `stands aside`
(`planWorkspaceInstall` при `needed:false` не даёт `why`, печатать нечего).

Замерено 17.09 на подъёме `curator×221` на `5cc15c23`: строки `levelling — …` в `daemon.log` за этот
подъём нет вовсе. Заказать срабатывание удалением `node_modules` своего дерева нельзя — без них не
стартует и CLI почты, роль запрётся на всех тредах ([[ordering-a-firing-may-lock-the-role]]).
