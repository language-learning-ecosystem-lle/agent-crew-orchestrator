Имя журнального файла задаёт ТРЕД (`docs/journal/<роль>/<NNN-slug>.md`), а не PR. Поэтому два
одновременно открытых PR одного треда (у треда 197 это были #410 и #411) метят в ОДИН И ТОТ ЖЕ путь
и конфликтуют add/add — норма треда `195` их не разводит: её пункт 4 обещает отсутствие конфликта
между ПАРАЛЛЕЛЬНЫМИ парами «роль × тред», а не между двумя PR одной пары.

**Why:** перенос записи из общего хвоста `docs/journal/<роль>.md` в файл-на-тред снимает конфликт с
ЧУЖИМИ журнальными PR, но не с собственным вторым PR того же треда; ждать выигрыша от переноса в
этом случае — ошибка.

**How to apply:** ставя ребейз или перенос записи, назови в постановке, КАКОЙ из PR несёт журнальный
файл, а у остальных PR треда журнального файла не должно быть вовсе. Иначе объявляй порядок мёржа и
называй, кто платит вторым ребейзом ([[declared-merge-order-allocates-the-rebase]]). Сам хвост как
источник сериализации — [[protocol-reference-tail-serializes-merges]].
