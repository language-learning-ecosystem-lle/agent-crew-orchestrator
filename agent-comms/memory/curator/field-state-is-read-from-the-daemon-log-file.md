`journalctl -u <любой юнит>` из поднятой сессии роли возвращает 4 строки подсказки «You are
currently not seeing messages from other users and the system. Users in groups 'adm',
'systemd-journal' can see all messages» — и по СВОЕМУ юниту тоже. Любой `grep -c` поверх этого
даёт ноль-артефакт, а не замер; контроль — счёт строк самого вывода. 2026-08-30 та же команда
журнал читала, значит менялась учётка/группы, а не код ([[groups-come-from-the-user-manager]]).

Полевое состояние контура ACO мерится ФАЙЛАМИ, и они читаются всегда: `.orchestrator/daemon.log`
(текущий) и `.orchestrator/daemon.log.1` (ротированный, ~29 МБ ≈ сутки — глубже истории на ящике
нет, и окно любого полевого утверждения этим ограничено). Эпохи размечены строкой
`=== daemon epoch · <ISO> · pid N ===`; на каком коде стоит живой процесс — `daemon-code.json`
([[merged-code-is-not-running-code]]).

Ноль по строкам демона подпирается ДВУМЯ контролями ([[verify-the-grep-pattern-not-its-result]]):
тот же префикс обязан совпасть с живой строкой (баннер `circuit watchdog ON` — по одному на эпоху),
и якорь ставится на начало строки — сырой греп ловит эхо СВОИХ ЖЕ команд, они попадают в тот же
поток. Числом возможностей служат тики (`no candidate is launchable`, `the plan of this tick`).

**Отравление НАКОПИТЕЛЬНОЕ, и якоря на начало строки мало** (замерено 2026-09-07, тред 155):
шаблон едет в журнал вместе с эхом команды, поэтому СЛЕДУЮЩИЙ греп матчит эхо предыдущего — «1
совпадение» дважды подряд оказалось моей же рукой ([[reproduce-with-the-tool-that-measured]]).
Чистый замер — литералом, СОБРАННЫМ так, чтобы он не появился в тексте команды (конкатенация в
аргументе: `P="…HAS FALLEN AWAY "'—'" it was decl""ared"; grep -cF "$P"`), плюс контрольное
совпадение той же техникой на строке, которую демон печатает заведомо (`courier: `).

**И КОНКАТЕНАЦИИ НЕДОСТАТОЧНО: журнал пишет эхо не только КОМАНД, но и их ВЫВОДА** (замерено
2026-09-07T18:05Z, тред 155). Безопасно собранный шаблон дал 2 совпадения, и обоими было эхо
чужих РЕЗУЛЬТАТОВ: `dev-core`, читавший свой же тест-файл, и мой собственный вывод исходника
минутой раньше. Литерал попадает в журнал, стоит его один раз ПОКАЗАТЬ, а не только набрать, —
поэтому шаблон не защищает никогда.

**Отделяет эхо от демона ПРЕФИКС СТРОКИ:** эхо поднятых сессий идёт как `[<роль>×<тред>] result …`,
демон печатает свои строки без него, и контроль считается ТЕМ ЖЕ способом, иначе сравниваются
разные величины: на замере 155 контроль дал 891 против 896 сырых, а искомая нота — 0 против 2.

**Но отрицательный фильтр `grep -vc "] result"` НЕДОСТАТОЧЕН — эхо бывает трёх видов** (замерено
2026-09-08, тред 161): сырой `grep -c WITHHELD` дал 3, и ими были `] tool Bash command=…` (мой же
греп), `] result …` и `] assistant …`. Отрицательный фильтр отсеял бы одно из трёх и оставил ложные
2. Надёжен ПОЛОЖИТЕЛЬНЫЙ якорь — префикс самого демона: `grep -c 'agent-protocol: daemon — '` плюс
литерал его строки (`letter — WITHHELD` → 0 при 209 `letter — SUPPRESSED` и 1 совпадении в
исполняемом исходнике). Своя рука отравляет журнал В ТОТ ЖЕ ТАКТ, а не только в прошлые
([[own-hand-crutches-hide-the-defect]]).

**Хронология ЛОМАЕТСЯ на склейке двух файлов, и `tail` врёт молча** (замерено 2026-09-08, тред 176):
`grep -h … daemon.log daemon.log.1 | tail` кладёт РОТИРОВАННЫЙ (старший) файл ПОСЛЕ текущего,
поэтому последние строки вывода — самые СТАРЫЕ, и свежий эпизод выглядит отсутствующим. Я так
прочла «установки этого перезапуска в журнале нет», хотя она стояла на `daemon.log:22059-22060`
из 22544. Привязка эпизода — `grep -n` ПОФАЙЛЬНО плюс `wc -l` того же файла (номер строки против
длины даёт «свежее/старее»), а не порядок в склейке.

**Отказ планировщика по потолку роли (`role-busy`) в ЖУРНАЛ не попадает вовсе** (замерено
2026-09-08, тред 177): за всю эру `.orchestrator/journal.jsonl` событие `launch-refused` знает
ровно три причины — `run-budget`, `quota`, `auth`. Строка «`<роль>` already has a session» живёт
ТОЛЬКО в `daemon.log(+.1)` и СВОЕГО ШТАМПА НЕ НЕСЁТ, поэтому окно такого утверждения — файлов, а
не часов, и счёт идёт ТАКТАМИ (888 строк — это 33 разные пары `роль×тред`). Одновременность
сессий, наоборот, мерится журналом: интервалы `lease-acquired`→`lease-released`.
