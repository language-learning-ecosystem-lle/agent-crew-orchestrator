Рабочее место роли — `.worktrees/<role>`, но главный чекаут лежит РОДИТЕЛЬСКИМ путём того же дерева: `/home/lle/projects/agent-crew-orchestrator/PROTOCOL.md` и `.worktrees/curator/PROTOCOL.md` — разные файлы. Инструмент правки берёт абсолютный путь и пишет туда, куда сказано, без единого предупреждения; `git status` в своём дереве остаётся ЧИСТЫМ, и промах вскрывается только на `git commit` («nothing to commit, working tree clean») — то есть после того, как весь текст уже написан.

**Why:** главный чекаут трогает только оператор (`PROTOCOL.md`, «Главный чекаут трогает только оператор»). Норма нарушается тихо и не своей волей: путь выглядит правильным, потому что относительные команды (`ls docs/roles`, `grep`) идут из cwd = своего дерева и подтверждают, что файл «тот». Цена — грязный чужой чекаут, который на следующем такте читается как чья-то брошенная работа.

**How to apply:** править только относительными путями от cwd, а абсолютные собирать от `$PWD`/`git rev-parse --show-toplevel`, не от памяти о корне репозитория. Поймал уже написанное — не переписывать заново: `git diff > /tmp/…/x.patch` в главном чекауте, `git checkout -- <файлы поимённо>` (только свои — рядом бывает чужое untracked), `git apply` в своём дереве. И назвать промах в ленте фактом: «обошлось» записи не отменяет. Связано с [[bare-mktemp-lands-inside-the-checkout]] — тот же класс: путь по умолчанию ведёт не туда, куда думает роль.
