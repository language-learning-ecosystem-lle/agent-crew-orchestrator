`.worktrees/<роль>` — worktree одного репозитория, поэтому **refs общие**: тег, созданный сессией
ДРУГОЙ роли, виден в моём `git tag --list` без всякого `fetch`.

**Why:** 2026-09-03, тред `056`: после кнопок на #229/#228 `git ls-remote --tags origin` в 09:29:30Z
отдавал пусто, а в 09:36Z — sha. Локальный ref при этом уже лежал у меня, хотя `fetch` я не делала —
значит рез сделан РУКОЙ НА ЭТОМ ЯЩИКЕ и оттуда запушен, а не приехал чтением. Это единственное, что
отличило «локальная рука» от «сработала автоматика» (встречный замер: ни один воркфлоу не режет
теги — `grep -rlE 'split-package|git tag|refs/tags' .github/workflows/` пуст).

**How to apply:** 1) `git tag --list '<имя>'` ставить в один ряд с `git status --porcelain` перед
передачей хода (см. [[reading-a-ref-must-not-write-the-tree]]) — не только ради чистоты, но чтобы
УВИДЕТЬ чужое действие без письма; 2) отсюда же мина, которой боялся dev-core: пробный рез без
`--push` оставляет локальный тег В ОБЩЕМ СКЛАДЕ и уводит настоящий рез чужой роли в отказ «тег уже
есть» — свои пробы гонять только там, где имя заведомо разойдётся с `version` и дверь откажет ДО
`git tag` (см. [[statement-of-work-ends-at-the-tag]]); 3) чужой ref своей рукой не удалять — назвать
находкой в ленте и спросить руку.

Правильность самого тега мерится СОДЕРЖИМЫМ, а не именем: `<тег>^{tree}` против
`origin/main:packages/<пакет>` (посимвольно), `version` внутри тега против имени тега,
`CURRENT_PROTOCOL_VERSION` внутри тега против предыдущего тега. `git tag --contains <коммит main>`
здесь пуст ВСЕГДА — теги режутся `git subtree split` и живут на отдельной линии SHA.

**Из указателя (перенесено 2026-09-06, оглавление шло за потолок):** чужой тег виден без `fetch`: это улика («рука была на ящике», а не автоматика) и мина (пробный рез ломает настоящий рез чужой роли); правильность тега мерится деревом и `version` внутри, а не именем

**Из указателя (перенесено 2026-09-08, оглавление шло за потолок):** годность мерится деревом и `version`

**Дерево ПАРЫ приезжает БЕЗ зависимостей (замер 2026-09-09, тред `161`, первый прогон после `#366`
«прогон садится в дерево пары»):** сессию сажают в свежий `.worktrees/<роль>@<тред>`, где нет ни
`node_modules/`, ни `packages/agent-protocol/node_modules/`, и ПЕРВАЯ ЖЕ документированная команда
почты падает `ERR_MODULE_NOT_FOUND: Cannot find package 'zod'` (`tsx` разрешается подъёмом до корня
главного чекаута, `zod` — зависимость пакета, её там нет). Дерево создаётся пустым ВСЕГДА: у
`dev-core@184` зависимости появились через 0,4 с после создания — рукой самой сессии. Починка —
`pnpm install --frozen-lockfile` в своём дереве, **0,7 с из стора**, после чего документированная
строка работает; `node_modules/` в `.gitignore` первой строкой, дерево остаётся чистым. Демон

does not install anything… this door NAMES the fault and a human repairs it»).
