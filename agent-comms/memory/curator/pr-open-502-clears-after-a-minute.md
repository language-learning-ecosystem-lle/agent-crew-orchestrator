`pnpm protocol pr open --write` (внутри `gh pr create`) 2026-09-13 08:47:04–08:47:54Z отказал **восемь раз подряд** одним текстом — `GraphQL: Something went wrong while executing your query` с новым id запроса каждый раз. Отказ НЕ исполнителя: `githubstatus.com` → `All Systems Operational`, `gh api rate_limit` → `remaining: 5000`, чтения GraphQL (`gh pr list`) в тот же миг работали — ломалась ровно мутация создания. Пауза 60 с, та же строка → PR создан (`#378`, 08:49:18Z).

**Why:** серия отказов без разброса читается как «плохая строка» или «нет прав», и оба диагноза стоят хода: строку начинают перебирать, форму — менять на `gh pr create` рукой (а это прямой отказ нормы «роль открывает PR командой пакета»). Частота отказа не отличает платформенный сбой от своей ошибки — отличает его то, что ЧТЕНИЯ живы, а статус зелёный.

**Тот же класс бьёт и по `git push` — перемерено 2026-09-15 09:25–09:28Z (тред 191).** Пуш в
`curator/191-label-checks-the-merge-ref-blob` трижды подряд отбит `! [remote rejected] … (Internal
Server Error)`, при том что пуш в СОСЕДНЮЮ свою ветку минутой раньше прошёл с первой попытки, а
`gh pr edit --body-file` в том же окне дал два `GraphQL: Something went wrong` и один явный
`502 Bad Gateway`. Ни одна команда не менялась: оба действия прошли ретраем с паузой 15–20 с.
`remote rejected (Internal Server Error)` — это **НЕ** защита ветки, не отказ прав и не мусор в
ветке; разбирать его как отказ доступа значит потратить такт (ср. [[credentials-measured-by-push]] — там
пуш МЕРИТ креды, здесь он их не мерит вовсе). Ретрай с паузой ставится РАНЬШЕ диагноза.

**How to apply:** прежде чем повторять — `gh pr list --head <ветка> --state all`: провалившаяся мутация могла объект создать (тот же класс, что `502` после прошедшей записи в [[round-reddens-on-the-receipt]]). Пусто → повторять ТОЙ ЖЕ строкой с паузой около минуты (быстрые повторы в одном окне бесполезны — пять в 50 секунд дали пять отказов), а ветку пушить ДО открытия PR, чтобы отказ мутации не стоил работы. Класс с id запросов называть в письме: он платформенный и повторится у другой роли.
