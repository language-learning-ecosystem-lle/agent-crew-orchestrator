Юнит `agent-protocol@hetzner.service` на этом ящике: `WorkingDirectory=/home/lle/projects/agent-crew-orchestrator`, `ExecStart` зовёт `packages/agent-protocol/src/cli.ts` через `tsx` — то есть контур исполняет ИСХОДНИКИ этого чекаута, не срез тега. Замер 2026-09-02T10:5xZ: `HEAD` этого чекаута стоял на `147905ee` — голове ветки чужого треда, а не на `main`.

**Why:** отсюда следует, что «смёржено в `main`» и «работает в контуре» — два разных факта, и второй не выводится из первого. Живая половина приёмки (тип «сессия, поднятая штатно, ведёт себя так-то») на такте мержа фактом ещё не является.

**Одна половина этого чинится флагом, и это дёшево:** `orchestrator run --ref origin/main …` берёт конфиг из РЕФА и переводит дерево роли на него (баннер печатает `workspace — … moving to origin/main <sha>`), поэтому живая приёмка смёрженной правки конфига снимается штатно, даже пока чекаут ящика стоит на чужой ветке. Замер 2026-09-02: `origin/main` нёс `pilot-codex` на `gpt-5.6-terra`/`max`, а `agent-protocol.json` рабочего чекаута — всё ещё `gpt-5.4-mini`/`low`; приёмка без `--ref` измерила бы старую пару и выглядела бы нормально.

**How to apply:** живую половину называть в докладе отдельно — «станет фактом, когда чекаут понесёт мерж и демон перезапустится», — но НЕ делать её блокером приёмки: доставка до работающего процесса это состояние установки ящика (`docs/install-notes.md`, зона devops), общее для каждого смёрженного механизма, а не свойство правки. Тащить её внутрь постановки — та же ошибка формы, что в [[statement-of-work-ends-at-the-tag]]. Ревизию чекаута ящика, если понадобится, ставить отдельной постановкой.
