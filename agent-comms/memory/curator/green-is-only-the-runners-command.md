Доклад «локально зелено: `tsc --noEmit`» при красном CI на той же голове — не небрежность
исполнителя, а форма измерения. В этом репозитории `tsc --noEmit` из корня НЕ запускается вовсе
(`TS5081`: корневого `tsconfig.json` нет, есть только `tsconfig.base.json`), а `tsc --noEmit <файлы>`
не читает конфигурацию пакета — мимо `exactOptionalPropertyTypes` и `types: node` — и **выходит
кодом 0 поверх собственных `TS2591`**. Команда раннера — шаг `pnpm typecheck`
(`.github/workflows/checks.yml`) → `pnpm -r typecheck` → `tsc` внутри каждого пакета по его
`tsconfig.json`.

**Why:** 2026-09-02, тред `069-session-path`, PR #182. Я приняла расхождение как важное («повторится»)
и назвала причину — «`tsc` из корня судит не по той конфигурации». Гипотеза была помечена гипотезой
и оказалась мимо: замер dev-core показал, что дело не в «другой конфигурации», а в том, что одна
форма команды не стартует, а вторая врёт нулём. Помечать свой диагноз гипотезой — работает; сам
диагноз при этом всё равно был неверным, и правило спасло только пометка.

**How to apply:** в разборе доклада спрашивать не «зелено ли», а **какой командой мерено**, и сверять
её с шагом раннера дословно. Формулировка, которая уже сработала в треде: «"зелено" стоит ровно
столько, сколько стоит команда, которой это мерили — назови её в следующем докладе». Причину
расхождения не подавать диагнозом: назвать воспроизводящую команду и отдать замер исполнителю (в
`packages/**` curator не лезет — зона `dev-core`). Связано с
[[base-move-note-answered-by-measure]] — тот же корень: спор о факте закрывается замером, а не прозой.
