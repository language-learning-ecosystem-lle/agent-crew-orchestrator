Замерено 2026-09-14 рефлогом дерева `curator@206-journal-writes-without-a-pr`: прошлый ход оставил
его на ветке PR `docs/206-journal-in-mail-branch` (голова `01c85a975`) и так доложил в тред, а
следующий подъём увидел **чистое** дерево на `b1a451bb2` — острие `main`, detached HEAD. Строка
рефлога `checkout: moving from docs/206-journal-in-mail-branch to b1a451bb2…` со штампом
`17:25:18 +0200` = `15:25:18Z` — это момент ПОДЪЁМА сессии, не действие прошлой.

**Why:** доклад «дерево стои́т на X» верен только на момент письма, а следующий ход читает его
заново. И обратная, полезная сторона: грань «своё дерево не знает своего же мёржа»
([[merged-code-is-not-running-code]]) живёт РОВНО один такт — инструмент, принятый своей кнопкой,
следующий подъём уже несёт без `fetch`.

**How to apply:**
- ручной `git checkout <sha>` забирает инструмент для СВОЕГО такта и только — как «подготовка дерева
  следующему» он не работает вовсе;
- коммит ветки PR пушится В ТОМ ЖЕ такте, где сделан: после перечекаута он невидимая работа —
  [[unpushed-branch-is-invisible-work]];
- состояние дерева мерится `git status` + `git reflog` этого дерева, а не берётся из ленты;
- ветка PR остаётся локально целой, отцеплен только HEAD.
