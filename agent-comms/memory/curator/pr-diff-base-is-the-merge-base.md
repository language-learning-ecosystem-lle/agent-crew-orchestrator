Судить содержание PR (гард 4, «вводит ли дифф норму») можно только диффом от **общего предка**:
`B=$(git merge-base origin/main FETCH_HEAD); git diff $B FETCH_HEAD`. `git diff origin/main FETCH_HEAD`
на отставшей ветке печатает ОБРАТКУ всех чужих мержей после её точки ветвления.

Полевой случай 2026-09-06, тред `144` (PR #296, база уехала на `a7b5dad` между `checks` и кнопкой):
честный дифф — 3 файла, 52/19, комментарий и два `.md`. Тот же PR через `origin/main` — 14 файлов,
578 удалений, и среди них `PROTOCOL.md`, `docs/roles/curator.md`, `docs/roles/dev-core.md`,
`docs/roles/devops.md`, то есть ЧЕТЫРЕ дока власти «удалены целыми разделами».

**Why:** ошибка молчит в обе стороны и обе дорогие — ложный STOP гарда 4 (PR уходит к john ни за
что) либо ложное «дифф переписывает норму» и отказ классу полевого дефекта. Глазами это не ловится:
удаления выглядят как настоящая работа исполнителя, потому что ею и были — только в чужом треде.
`merge-gate` при этом отвечает `ok`: дверь считает пути правильно, врёт именно РУЧНОЕ чтение.

**How to apply:** дифф PR брать от `merge-base` ВСЕГДА, а не когда заподозрил переезд; нота двери
о переезде базы гасится там же — `git merge-tree --write-tree origin/main <голова>` даёт слитое
дерево, и `git diff origin/main <дерево>` показывает, что мёрж приносит СВЕРХ текущего канона (в
`144` — ровно те же 3 файла, 52/19, то есть переезд не приносил ничего). После кнопки это
проверяется точно: `git rev-parse <сквош>^{tree}` = перемеренному дереву. Связано:
[[pinned-blob-rots-in-the-review-circle]], [[base-move-note-answered-by-measure]],
[[acceptance-on-the-merged-tree-is-cheap]], [[norm-or-repair-is-read-in-the-diff]].

**Из указателя (перенесено 2026-09-06, оглавление шло за потолок):** `git diff origin/main <голова>` на отставшей ветке печатает чужие мержи как удаления и кладёт в дифф доки власти, которых там нет
