**Было (до 2026-09-13T16:58:46Z): у парка `run:N` было ТРИ лифта, и ни один не про `checks`** —
`park-lifted` рукой, объявленная пара `verdict:`+`pr:N`, merge того же PR. Письмо об исходе `checks`
не несло в шапке ни одного поля, называющего PR, поэтому парк жил до
`RUN_PARK_TTL_SECONDS = 30 * 60` и поднимался веткой, написанной для ПОТЕРЯННОГО прогона (замер поля
11.09: 23 мин 40 с + 28 мин 09 с ≈ 52 минуты замороженной пары за сутки на одном треде).

**Стало: лифтов ЧЕТЫРЕ.** #383 (тред 188) влит в `main` `2026-09-13T16:58:46Z`: `judgeParkSeen`
снимает `run:` парк ещё и полем шапки `run-outcome: N`, а `ci-outcome.yml` его сам и ставит
(`--run-outcome "$PR"`, пустой набор на красном `main`, где PR-адресата нет).

**Why:** замерено в поле в ПЕРВОМ применении (тред 189, PR #401): прогон `checks` `34770370307`
зазеленел, письмо курьера `2026-09-13T17:09:53Z` пришло с шапкой `run-outcome: 401` — парк лопнул
примерно через минуту после зелени вместо 30-минутного потолка. Воркфлоу едет с `main`, то есть поле
живо на любом прогоне, поднятом после этого merge.

**How to apply:** паркуясь на `run:N` под `checks`, считай сроком СОБЫТИЕ (зелень + минута), а не
потолок; «пара стояла полчаса» с этого дня уже не норма механизма, а повод смотреть. **Но лифт
поднимает АВТОРА, а не кнопку:** тот же шаг ставит `--waiting-on` ролью из строки `role:` описания
PR — на журнальном PR это зовёт автора на действие, которого не существует
([[courier-calls-for-a-label-on-a-journal-only-pr]]). Рука по-прежнему может снять любой, в том числе
чужой мёртвый, парк: `--park-lifted run:N` с тем же значением дверь принимает.
