Когда системное письмо (`github`, демон) объявляет поле незаполненным И называет причину — причина
напечатана фиксированной строкой одной ветки `if`, а не измерена. Замерено 2026-09-07, тред
`164-daemon-self-restart`: «сколько ждал сессии: не записано — файл памяти писан кодом до
`drainSince`», при том что `git show <старый sha>:<файл> | grep -c drainSince` → 8, а `daemon.log`
на строке решения печатал `leases 0` — дрейна не было вовсе, и ветка, пишущая поле, не вызывалась.

**Why:** у пропуска обычно причин больше, чем формулировок в коде, и самая частая часто не названа
(здесь — «ждать было некого» при штатном перезапуске пустого ящика). Реляция такой строки дальше
делает curator рупором ложного факта, а читателя отправляет чинить не то.

**How to apply:** прежде чем донести отчёт, отсутствие поля мерить ДВУМЯ фактами — состоянием файла
(`.orchestrator/*.json`: есть ключ или нет) и веткой кода, которая его пишет; возраст кода проверять
`git show <sha>:<путь>` по тому sha, который письмо само называет, а не по `main`. Расхождение
поднимается как полевой дефект — ср. [[field-defect-class-needs-two-letters]],
[[reported-instance-is-a-sample]]; сам отчёт при этом может быть полон по составу фактов —
неверна ровно строка объяснения.
