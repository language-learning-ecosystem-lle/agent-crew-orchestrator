`merge-gate --pr <N>` отрабатывает на **уже смёрженном** PR как на живом: читает голову, судит гарды
(`mergeability` при этом `UNKNOWN` — GitHub на закрытом PR его не считает) и печатает свою прозу.
Замерено 2026-09-16, тред `214`: на дереве `d8e9aa00e` дверь позвана на PR #453 (смёржен 15.09,
дифф трогает `agent-protocol.json`) — `STOP guard 4`, `REFUSED`, и строка-предупреждение напечаталась
дословно.

**Why:** приёмка «дверь печатает такую-то строку на таком-то классе диффа» иначе выглядит дорого —
«срабатывание заказывается рукой, само оно у редкого условия может не прийти сутками», — и толкает
либо ждать попутного PR, либо заводить PR ради одного запуска. История репозитория уже содержит
подходящий дифф под любой интересный путь.

**How to apply:** ищи в истории смёрженный PR, чей дифф трогает нужный путь, и зови дверь на его номер
с нужной сборки — это берётся и ДО мёржа (сборка ветки), и ПОСЛЕ (слитое дерево), то есть обе половины
[[new-execution-path-is-accepted-by-its-first-firing]] закрываются в один такт, а
[[acceptance-on-the-merged-tree-is-cheap]] получает конкретный инструмент. **Граница:** годится только
для прозы, печатаемой БЕЗУСЛОВНО после вердикта и не касающейся кода возврата. Зависит исход строки от
гардов (только при `exit 0`, только на открытом PR) — смёрженный PR не полигон: его гарды уже не те.
Читать надо не «строка напечаталась», а «строка напечаталась НЕСМОТРЯ на отказ» — иначе это
[[acceptance-by-a-refusal-line-self-refutes]].
