Замер 2026-09-03 (тред `097-conflict-has-no-signal`), две точки до и после мержа `#249`:

- ДО: `249 MERGEABLE CLEAN`, `247 MERGEABLE UNSTABLE`, `244 MERGEABLE CLEAN`, пять — `UNKNOWN`;
- СРАЗУ ПОСЛЕ: **все семь оставшихся `UNKNOWN UNKNOWN`**, включая `247` и `244`, отвечавших минуту назад.

**Обнуление РАССАСЫВАЕТСЯ САМО**, и это меряется тем же вызовом: 2026-09-03 через ~19 минут после
мержа `#247` все восемь открытых PR снова отвечали `MERGEABLE` (`CLEAN`, кроме идущего круга —
`UNSTABLE`). То есть подтверждающий запрос стоит ОДИН такт после мержа, а не постоянно: цена
худшего тика — потолок, а не средняя.

**Окно обнуления — ДЕСЯТКИ СЕКУНД, а не минуты**, замерено вплотную после мержа `#255`
(2026-09-03T20:53:22Z): через **7 с** пять из семи открытых PR — `UNKNOWN`, два уже `MERGEABLE`;
через **34 с** — все семь `MERGEABLE/CLEAN`. Оттого правило сторожа «два ПОДРЯД согласных вопроса»
(`agreed by two consecutive asks`) гасит этот класс само собой: при такте 30 с второй вопрос
приходит уже за окном, и ложного письма о потере сливаемости не будет. Ждать «минут» перед
перепросом не надо — надо переспросить.

**Два следствия, оба практические:**

1. **`UNKNOWN` — не редкий холодный старт, а нормальное состояние после ЛЮБОГО мержа.** Всё, что
   принимает решение по сливаемости (метка, дверь merge, доклад о готовности), обязано переспрашивать,
   и «не сошлось» вердиктом не считается — см. [[same-tree-proves-no-conflict-not-integrity]];
2. **`gh pr list --state open --json number,headRefOid,mergeable,mergeStateStatus` — ОДИН вызов на все
   PR (замер: 8 PR, 0.87s).** `mergeable` добавляется в этот `--json` за ноль лишних вызовов, так что
   первое чтение сливаемости по всему списку бесплатно; платится только подтверждающий запрос там, где
   первый ответ разошёлся с сохранённым.

**Why:** цена сторожа/двери считается неверно, если исходить из «два запроса на каждый PR на каждый
тик» — первый уже оплачен планировщиком (`orchestrator/merge-ready.ts`, `open()`).

**How to apply:** прежде чем везти john «расход» такого класса — замерить `gh api rate_limit`
(2026-09-03: 5000/час, использовано 0; худший тик ~8 вызовов ≈ 1.6 %). Арифметика снимает вопрос без
парка. Деньги в такой механизм входят ПИСЬМАМИ (каждое поднимает сессию), а не вызовами `gh` —
см. [[park-lift-is-pure-over-the-mail]].
