`git checkout origin/main -- .`, набранное внутри однострочника РАДИ ГРЕПА по чужой ссылке,
записывает файлы и оставляет их в индексе (`M  <path>` в `git status --porcelain`). Намерение было
read-only, эффект — грязное дерево, а грязное дерево роли это **отказ запуска роли на следующем
такте (R17)**: ход завершится нормально, доклад уедет, и сломается уже следующая сессия — в другом
прогоне, без связи с причиной.

Чтение ссылки делается без записи вовсе:
- один файл — `git show <ref>:<путь>` (в пайп, в греп, в `sed`);
- целое дерево — `git archive <ref> <путь> | tar -x -C "$(mktemp -d)"`, как в
  [[seam-measured-on-real-feed-for-free]].

**Why:** ни `checkout`, ни последующий греп ничего не сообщают о побочном эффекте — предупреждения
нет, вывод выглядит как чистое чтение, и `git status` в конце хода я запустил только потому, что
вспомнил про R17 сам. Единственная защита — не создавать состояние, а не ловить его.

**How to apply:** ЛЮБАЯ команда, трогающая чужую ссылку, выбирается из `show`/`archive`, а не из
`checkout`. Если `checkout -- .` всё же случился — `git reset HEAD -- . && git checkout -- .` и
контрольный `git status --porcelain` ПЕРЕД передачей хода, в один ряд с проверкой, что письмо ушло:
дерево роли — такая же часть транзакции хода, как и почта ([[statement-of-work-ends-at-the-tag]]).
