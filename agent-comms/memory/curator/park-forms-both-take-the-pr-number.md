`--parked-on` знает две формы, и **обе хотят номер PR**: `pr:<n>` и `run:<n>` — последняя ждёт
КРУГА НА этом PR, а не прогона по его id. Одиннадцатизначный id из `gh run list` дверь отказывает
вслух («PR numbers do not reach 1000000»).

Разница форм не в написании, а в том, чем снимаются:
- `pr:<n>` снимается **ровно заголовком `merged-pr: n`** в любом письме почты. Состояние PR не
  сторожит никто: merge в GitHub и объявление о нём прозой тред НЕ размораживают;
- `run:<n>` снимается кругом на голове PR — тем, который уже бежит.

**Why:** парк на `pr:` за merge'ем, который жмёт john, при том что следующий шаг треда — ТВОЙ
(метка `review` после зелёного `checks`), дверь называет «запертой изнутри»: тред запаркован, никого
не поднимает, а ждёт действия, которое сделать некому (тред 061 — три таких парка за день).

**How to apply:** ждёшь `checks`/круга ревью на своём свежем PR — `--parked-on run:<НОМЕР PR>`.
Ждёшь чужой кнопки merge — `pr:<n>` плюс `--park-mover <кто нажмёт>`, иначе дверь откажет и будет
права. Номер берётся из хвоста URL PR или `gh pr view --json number`, id прогона в парк не едет
никогда. Смежное: [[parked-on-freezes-the-turn]], [[park-door-refuses-silent-letters]],
[[park-lift-is-pure-over-the-mail]].
