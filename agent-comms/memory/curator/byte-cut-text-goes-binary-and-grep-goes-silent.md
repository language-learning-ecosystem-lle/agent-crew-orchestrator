**Слепота грепа — свойство РУКИ, а не файла.** В bash поднятой сессии `grep` — не бинарь, а
**функция-шим** (`type grep` печатает тело), зовущая `claude -G --ignore-files --hidden -I …`
(ugrep) — а `-I` значит «пропускать бинарные файлы», то есть файл пропускается ЦЕЛИКОМ, до всякого
сопоставления. Человек на ящике и роль в сессии по одному файлу расходятся молча.

Замер в три руки по `.orchestrator/daemon.log`, 13.09 (тред 188), `grep -c "HAS GONE STALE"`:

| чем меряю | печатает | rc |
| --- | --- | --- |
| `grep` сессии | **пусто** | 1 |
| `grep -a` сессии | `171` | 0 |
| `/usr/bin/grep` (GNU 3.11) | `171` | 0 |

GNU grep файл считает прекрасно: на `-c` даёт число и rc=0, без `-c` честно печатает
`binary file matches`. Хватает ОДНОГО NUL-байта (в `daemon.log` он приезжает из трасс инструментов
живых сессий). Второй случай того же класса: таблица, собранная через `cut -c1-130` из русского
текста, — порванные UTF-8 символы, `grep -c 'разморо'` печатает ничего, `awk` ругается
`Invalid multibyte data`; стоило двух ходов 09.09.

**Различитель — ФОРМА ответа, а не rc:** на текстовом файле без совпадений `grep -c` печатает `0`
и rc=1; на файле с NUL — печатает **пустую строку** и rc=1, ОДИНАКОВО и когда совпадений нет, и
когда они есть. rc два исхода схлопывает. **`-c`, напечатавший пусто вместо `0`, — это не ноль, это
отказ смотреть.**

**Why:** нулевой вывод грепа читается как факт о мире, а был фактом о своей руке — и на
append-only журнале такой «факт» отговаривает следующего читателя от исправного прибора.
**How to apply:** ноль по `daemon.log` (и по любому логу с трассами сессий) — СНАЧАЛА подозрение на
свой инструмент: перемерить `/usr/bin/grep` или `grep -a` + `LC_ALL=C.UTF-8` по тому же файлу, и
только потом выводить о мире. Якорить `^` обязательно ([[daemon-log-echoes-your-own-output]]:
неякорный счёт по этому файлу дал 171 против анкерных 157 — разницу составили мои же команды).
