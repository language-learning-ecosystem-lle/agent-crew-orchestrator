Тред с папкой `messages/`, но без `_meta.md`, делает `Comms Derived` красным на КАЖДОМ push в
`comms`: производные при этом собираются и пушатся успешно, а шаг падает кодом 2 нарочно, назвав
нечитаемый каталог. Починка — одной командой, и она есть в самом тексте ошибки:
`cli thread status --thread <id> --from curator --repair --write` синтезирует голову из писем
(право `thread-status`, чужие письма не трогаются).

Замер 2026-09-02, тред `073`: `116-role-memory-cost` (одно письмо чатного curator `16:40:31Z`,
`worker: claude-ai`, без головы) держал девять красных `Comms Derived` подряд
(`33656370292`…`33657542629`); после `--repair` прогон `33657777348` в `16:54:22Z` — первый зелёный.

**Why:** усиление 1:1 и незатухающее — **письмо смотрителя об отказе `Comms Derived` само есть push
в `comms`, то есть само рождает следующий отказ**. Канал тревоги проложен через тот ресурс, чью
поломку он сообщает; для трёх остальных наблюдаемых (`CI Outcome`, `Merge Notify`,
`Claude PR Review`) этой петли нет. Один зависший красный derive = бесконечная серия писем и
прогонов, пока не придут руками. Постановка на дедупликацию отдана dev-core в `073` 2026-09-02.

**How to apply:** серия одинаковых писем в `077-notifier-down` — не «шумит уведомитель», а признак
залипшего красного уведомителя; читать `gh run view <id> --log-failed` последнего прогона и чинить
корень, а не канал. Безголовый тред заводится тем, кто кладёт письмо мимо `new-thread` (чатная
сессия), и стоит он всей почте, а не своему треду. См. [[standing-address-threads-076-077]],
[[comms-copy-before-canon-merge]], [[thread-ids-are-flat]].
