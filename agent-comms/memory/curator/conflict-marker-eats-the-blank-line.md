Append-хвост журнала конфликтует при каждом ребейзе, разрешение механическое — стереть три строки
маркеров, — и ровно на нём теряется строка. `=======` стоит НА МЕСТЕ пустой строки-разделителя между
последним абзацем чужой стороны и своим первым заголовком: снял маркер — склеил абзац с заголовком.

Замерено 2026-09-13 (тред `187`, #389, второй ребейз на `b00789ed4`): `70 insertions(+)` против `71`
у той же работы до ребейза. **«Ноль удалений» этого НЕ ловит** — потеря на СВОЕЙ стороне, база цела,
`diff --numstat` показывает честные `70	0`.

Два замера, которые ловят:

```bash
git diff --numstat <новая-база> HEAD -- <путь>          # число вставок = ровно как до ребейза
diff <(git diff <старая-база> <старая-голова> -- <путь> | grep '^+') \
     <(git diff <новая-база> HEAD       -- <путь> | grep '^+')   # пусто = блок побайтно тот же
```

**Why:** содержание при этом цело, и глаз читает «всё на месте» — расхождение в ЕДИНИЦУ выглядит как
шум, хотя это склеенный markdown. **How to apply:** после `rebase --continue` сверять число вставок
с дособытийным, и чинить правкой файла + `--amend`, а не новым коммитом. См.
[[same-tree-proves-no-conflict-not-integrity]], [[protocol-reference-tail-serializes-merges]].
