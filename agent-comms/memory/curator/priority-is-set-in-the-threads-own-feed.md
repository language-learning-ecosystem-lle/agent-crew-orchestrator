Прочитано в коде 2026-09-09 (тред `181-thread-number-collision`),
`packages/agent-protocol/src/orchestrator/priority.ts`.

**Приоритет — не поле конфига и не флаг команды очереди: он заголовок ПИСЬМА** (`--priority high|normal|low`
у `new-message`), и резолвится `resolveThreadPriority` из ленты **самого треда** — последним словом
роли, у которой есть право `thread-priority` (у curator оно есть). Слово роли без права
отбрасывается ВСЛУХ при сборке очереди.

**Практическое следствие, которое стои́т помнить в связанном прогоне:** поднять приоритет ЧУЖОГО
треда нельзя, не написав в него письмо, — а прогон, связанный одним адресом, туда писать не вправе
([[handoff-to-another-thread-is-prose]]). Из шумного треда можно только **понизить СЕБЯ**.

**Очередь — четыре яруса, и явный приоритет первый** (`orderCandidates`: `RANK[a.priority] - RANK[b.priority]`
первым сравнением, дальше — держит ли тред готовый merge, возраст ожидания, номер треда). Умолчание —
`normal`, поэтому `low` ставит адрес позади всей обычной работы.

**Чего `low` НЕ делает:** не снимает кандидатуру — поднимается, когда в ящике есть место
([[low-priority-still-gets-raised]]), и не глушит того, кто в тред пишет. Отменяется **более поздним
словом** — письмом с `--priority normal` в тот же тред.

Полевой повод: смотритель коллизии повторял письмо каждый такт, и подъём по повтору держал место
ящика, пока пропускались `dev-core×184` (починка ЭТОГО повтора) и `dev-core×183` (красный `main`) —
повтор вытеснял собственную починку ([[standing-address-threads-076-077]]).
