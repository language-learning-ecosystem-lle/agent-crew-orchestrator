Адрес `origin` в конфиге репозитория — SSH-алиас `git@github-crew:…`, и работает он **не сам по
себе**, а строкой в доме одного пользователя:

```
$ git config --show-origin --get-regexp insteadof
file:/home/aco-hetzner/.gitconfig   url.https://github.com/.insteadof git@github-crew:
```

Тот же репозиторий, та же запись remote, две учётки — **два разных URL**: под `aco-hetzner`
`git remote -v` печатает `https://github.com/…`, под `aco-devops` — сырой `git@github-crew:…`.
Для роли с `systemUser` закрыты **все три двери сразу**: ключа нет (`/home/aco-devops/.ssh` не
существует), переписывания нет (чужой `~/.gitconfig`), токена нет (`secrets.env` — `600`
владельца, каталог над ним `770`; **`600` означает, что никакая группа не помогает вовсе**, и
готовый `GIT_CONFIG_*`-хелпер из [[credentials-measured-by-push]] в этой учётке не собирается —
ему нечего прочесть).

Закрыта не только запись. `thread show --ref origin/main` делает `fetch`, то есть роль **не
читает даже собственную постановку** и умирает на ПЕРВОЙ команде такта.

**Why:** в журнале это `exited-without-handoff`, `exitCode 0`, с настоящим расходом ($1.35, 34
хода) — неотличимо от «сессия не нашла работы и ушла молча». По этому признаку четыре ухода
`devops` (03.09 ×3, 06.09 ×1) три дня читались как пробел ПРОМПТА, под это была написана норма
и смёржен PR, а пять пар (`047`, `056`, `057`, `070`, `079`) стояли замороженными. Ветвь нормы
«непишущая роль печатает в поток» роль при этом ИСПОЛНЯЛА все четыре раза: печать в лог не
доставка, пара мёрзнет ровно так же. Отличается от [[system-user-role-cannot-read-shared-account]]
дверью: там креды Claude и смерть за 0 секунд, здесь git и полноценно отработавшая сессия.

**How to apply:** прежде чем объяснять молчаливый уход поведением сессии — открой её лог:
`grep -c "cannot access '/home/<user>/.ssh'"` и `grep 'ssh: Co'` называют класс за одну команду,
а `git config --show-origin --get-regexp insteadof` показывает, в чьём доме лежит рабочая
личность. Прогон рукой поверх потолка попыток такую пару НЕ чинит — он жжёт попытку на первой
команде; чинится это на ящике (строка `insteadOf` в `~/.gitconfig` роли + читаемый ей токен), а
не постановкой роли, потому что чинить надо ту самую учётку, которая не может ни прочесть тред,
ни отчитаться в него. Связано: [[merged-code-is-not-running-code]],
[[reported-instance-is-a-sample]].
