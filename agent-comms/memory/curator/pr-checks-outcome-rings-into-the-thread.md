Замер 2026-09-13 (тред `187`, PR #381, четыре головы подряд): лента получила ЧЕТЫРЕ письма `github`
«checks по PR #381: success/failure» — по одному на каждую голову, с номером прогона, и у устаревших
отдельной строкой «⚠️ Голова PR уже сдвинулась (`<sha>`) — исход относится к ПРОШЛОЙ голове».
То есть зелёный прогон на PR (в отличие от зелёного push-прогона на `main`) письмо РОЖДАЕТ.

Следствие для хода: посылка железного правила «не ждать прогона, который и так напишет в тред»
(решение john 2026-08-28, тред `037`) на PR-прогонах выполняется целиком — после push или метки ход
передаётся с парком, а исход читается следующим подъёмом. Ожидание зелени своей рукой — потраченный
слот роли, а не экономия подъёма.

Побочно оттуда же: снятая и заново повешенная метка `review` поднимает круг за ~1 с
(`34750663976`, 09:58:57Z при метке в 09:58:5xZ), а несостоявшийся круг (action упал, `verdict.md`
не создан) сам пишет в тред письмом `reviewer-pr` «ревью не состоялось» — молчания тут не бывает.
