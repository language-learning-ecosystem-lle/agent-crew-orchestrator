Шесть кругов `Claude PR Review` на ветках, созданных ДО посадки #399 в `main` (17:33:21Z 13.09),
показали НОВОЕ поведение переезда сразу после этого мига — головы тех PR не двигались. Значит для
события `pull_request` раннер берёт воркфлоу с merge-ref (голова PR, слитая с базой), а не с ветки PR
и не с её базы на момент открытия.

**Why:** отсюда путь разблокировки PR, застрявшего на дефекте воркфлоу: чинить воркфлоу в `main`, а
потом ОДНО перевешивание метки `review` даёт зелёный круг на том же дереве. Сдвигать голову PR —
ребейзом, попутной записью, чем угодно — не нужно и вредно: он осиротит уже доставленный `approve`,
привязанный к старой голове ([[pinned-blob-rots-in-the-review-circle]],
[[review-circles-are-countable]]).

**How to apply:** PR с доставленным вердиктом и красным гардом 1/2 по дефекту круга — не трогать
голову, ждать посадки починки, затем снять и повесить метку заново (событие `labeled` — единственный
подъём круга из руки curator). Это ВЫВОД из наблюдения шести кругов, а не отдельный замер платформы:
если цена решения высока, проверить прямым замером на первом же круге после следующей посадки
воркфлоу. Живой случай — #416 треда 192 и перепись в
[[fallback-step-reddens-a-successful-round]].
