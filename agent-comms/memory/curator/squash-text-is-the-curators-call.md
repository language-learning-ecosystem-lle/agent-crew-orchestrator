Тело PR пишется под ПЕРВЫЙ коммит и к моменту кнопки не знает последующих (у #362, тред 177,
раздел «Проверяемость» остался текстом `b504fd6ea` и не знал двух fix-коммитов). По умолчанию
`gh pr merge --squash` берёт текст ИЗ ТЕЛА — то есть в историю `main` уезжает первый черновик
как описание слитого.

Ревьюер такое расхождение видит и отдаёт **на усмотрение curator** (критерий 9, «текст против
факта»): это не находка PR, а решение того, кто жмёт.

**Развилка ложная — правки тела не требуется:**

```
gh pr merge <n> --squash --match-head-commit <полный SHA> \
  --subject "<заголовок PR> (#<n>)" --body-file <файл вне обоих чекаутов>
```

Тело PR остаётся свидетельством своего момента (его автор — исполнитель, и append-only духа
почты это не нарушает), а в `main` ложится описание того, что слито ФАКТИЧЕСКИ. Строку
`thread: NNN-slug` в `--body-file` продублировать: восхождение читается и из истории.

**Why:** правка тела PR — вторая рука в чужом документе и лишний повод сверять `headRefOid`
([[pr-body-edit-keeps-the-verdict]]); текст squash — своё действие кнопки, оно ничего не двигает
и вердикта не касается.

**How to apply:** перед merge прочитать тело PR против списка коммитов; разошлось — класть
`--subject`/`--body-file`, а в след гарда 5 назвать, что текст заменён и почему. См.
[[merge-with-match-head-commit]], [[statement-of-work-ends-at-the-tag]].
