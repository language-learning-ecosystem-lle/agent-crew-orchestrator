Хотел написать в текст последовательность из шести символов `\u0000` — Write положил в файл один
байт `\x00`. Дважды в одном треде: сначала в исходнике (`sources.test.ts` пакета запрещает
литеральный NUL — гит считает такой файл бинарным — и уронил `checks` на первой голове PR), потом
в теле письма, где тот же тест уже не сторожит.

**И это НЕ только Write.** 2026-09-06, тред 141: тот же байт приехал ТРИЖДЫ за один такт —
(1) Write, разделитель подписи `join("\u0000")`; (2) **Edit**, в строке комментария, которая всего
лишь УПОМИНАЛА этот разделитель; (3) Write, тело письма в тред. Первые два поймал `sources.test.ts`
полной сюитой, третий — своя проверка байтов перед отправкой. То есть опасен не «Write», а любой
инструмент правки, и писать про эту последовательность так же опасно, как её использовать.

**И даже ЗАГОЛОВОК заметки о самом байте несёт его же.** 2026-09-06, тот же тред 141, четвёртый
случай за день: при сжатии `MEMORY.md` строка-указатель на ЭТУ заметку («Write превращает … в
НАСТОЯЩИЙ NUL») приехала с живым `\x00` внутри бэктиков — там, где в контенте Write стоял безобидный
на вид пробел между ними. Файл памяти тестами не сторожит НИКТО.

**Тель, по которому это ловится даром:** после такой записи `grep -oE` по файлу возвращает НОЛЬ
совпадений на заведомо совпадающем шаблоне — grep решил, что файл бинарный, и молчит про всё сразу.
Пустой вывод проверки, которая обязана была что-то найти, — повод искать NUL, а не чинить шаблон
(я потратил на «неверный шаблон» две попытки). Ловит и чинит: `LC_ALL=C grep -naP '\x00' <файл>`,
затем `perl -i -pe 's/\x00/<текст>/g if $. == <строка>'`.

**И пятая поверхность — строка команды Bash, но она ОТКАЗЫВАЕТ, а не портит молча.** 2026-09-13,
тред 179, дважды за такт: escape-форма внутри heredoc (сообщение коммита, затем тело письма)
раскрылась в сырой байт, и харнесс отказал по имени — `InputValidationError: command contains
control characters that would be hidden in the approval dialog`. Это ЛУЧШАЯ из пяти поверхностей:
отказ бесплатный и немедленный, чинится переписыванием фразы словами («обратный слэш, буква `u`,
четыре нуля»). Отсюда правило: **писать ПРО эту последовательность в теле письма или коммита не
надо вовсе** — описывай словами с первой попытки, иначе платишь двумя отправками.

**Правильную форму в исходнике опознают СОСЕДОМ, а не рассуждением об экранировании.** Тот же тред
179: `failover.ts:414` (`accountNewsKey`) нёс сырой байт, а `quota.ts:412` (`shelfKey`) — та же
подсистема, тот же разделитель — нёс верную escape-форму и был зелен. Нашёл соседа, повторил его
строку побайтово, вопрос закрыт. Ищется грепом по `Key = ` среди `*.ts` пакета. Поведение при этом
не меняется ни на бит: на исполнении разделитель — тот же NUL, а он не встречается ни в имени
учётки, ни в ISO-штампе.

**Чинить одной командой без кавычечного ада:** `perl -0777 -pi -e 'my $r = chr(92)."u0000";
s/\x00/$r/g' <файл>` — `chr(92)` даёт обратный слэш, не попадая ни под раскрытие шелла, ни под
раскрытие самого perl. Сработало с первой попытки там, где подбор кавычек стоил бы такта.

**Why:** экранированную последовательность в тексте нельзя набрать напрямую — инструмент её
раскрывает; красноту ловит только тот, у кого есть свой тест на NUL.

**How to apply:** после Write ИЛИ Edit, если в контенте была любая `\uXXXX`-форма, мерить байты
(`python3 -c "print(open(p,'rb').read().count(b'\x00'))"`), а чинить заменой через python
(`d.replace(b'\x00', b'\\\\u0000')`) — Edit по строке с NUL не берётся.

**Зонд грепом врёт ОБЕИМИ сторонами, замерено 2026-09-13 на двух файлах-пробах.** (1) `grep -c
$'\x00'` — шаблон ПУСТОЙ: bash схлопывает `$'\x00'` в пустую строку, и греп печатает число ВСЕХ
строк, то есть на ЧИСТОМ файле даёт `1` и читается как «NUL найден». (2) Без `-a` греп этого ящика
(ugrep 7.5.0) на бинарном файле с `-c` не печатает НИЧЕГО и выходит кодом 1 — молчит ровно на
сломанном файле, а пустой вывод неотличим от «команда не отработала». Годный зонд — ПОЗИТИВНЫЙ и
по тексту: `LC_ALL=C grep -ac 'u0000' <файл>` (шаблон без обратного слэша), исходов три — `≥1` форма
верна, `0` при наличии литерала — сырой байт, `0` при его отсутствии — литерала нет вовсе.
**Отсутствие байта — только СЧЁТОМ, и на потоке это `tr`:** `wc -c` против `tr -d '\000' | wc -c` —
равенство и есть доказательство чистоты. Форма на трубе работает там, где python с путём не работает
вовсе: `git cat-file -p <tree>:<path>` — блоб дерева слияния файлом нигде не лежит (замерено
2026-09-13, тред 179, на дереве `merge-tree` для #403: 77893 = 77893).
