Хотел написать в текст последовательность из шести символов `\u0000` — Write положил в файл один
байт `\x00`. Дважды в одном треде: сначала в исходнике (`sources.test.ts` пакета запрещает
литеральный NUL — гит считает такой файл бинарным — и уронил `checks` на первой голове PR), потом
в теле письма, где тот же тест уже не сторожит.

**И это НЕ только Write.** 2026-09-06, тред 141: тот же байт приехал ТРИЖДЫ за один такт —
(1) Write, разделитель подписи `join("\u0000")`; (2) **Edit**, в строке комментария, которая всего
лишь УПОМИНАЛА этот разделитель; (3) Write, тело письма в тред. Первые два поймал `sources.test.ts`
полной сюитой, третий — своя проверка байтов перед отправкой. То есть опасен не «Write», а любой
инструмент правки, и писать про эту последовательность так же опасно, как её использовать.

**И даже ЗАГОЛОВОК заметки о самом байте несёт его же.** 2026-09-06, тот же тред 141, четвёртый
случай за день: при сжатии `MEMORY.md` строка-указатель на ЭТУ заметку («Write превращает … в
НАСТОЯЩИЙ NUL») приехала с живым `\x00` внутри бэктиков — там, где в контенте Write стоял безобидный
на вид пробел между ними. Файл памяти тестами не сторожит НИКТО.

**Тель, по которому это ловится даром:** после такой записи `grep -oE` по файлу возвращает НОЛЬ
совпадений на заведомо совпадающем шаблоне — grep решил, что файл бинарный, и молчит про всё сразу.
Пустой вывод проверки, которая обязана была что-то найти, — повод искать NUL, а не чинить шаблон
(я потратил на «неверный шаблон» две попытки). Ловит и чинит: `LC_ALL=C grep -naP '\x00' <файл>`,
затем `perl -i -pe 's/\x00/<текст>/g if $. == <строка>'`.

**Why:** экранированную последовательность в тексте нельзя набрать напрямую — инструмент её
раскрывает; красноту ловит только тот, у кого есть свой тест на NUL.

**How to apply:** после Write ИЛИ Edit, если в контенте была любая `\uXXXX`-форма, мерить байты
(`python3 -c "print(open(p,'rb').read().count(b'\x00'))"`), а чинить заменой через python
(`d.replace(b'\x00', b'\\\\u0000')`) — Edit по строке с NUL не берётся. `grep -c $'\x00'` на таком
файле молчит вовсе, то есть его тишина доказательством отсутствия НЕ является.
