2026-09-03 такт на `076-main-red-alarm` подняли два письма `github`, у обоих единственный
упавший шаг — `comms-derived синхронен с каноном`. По тексту это одна авария. По времени —
две разные: прогон `33741946049` (`3c46a2c2`, 10:00:22Z) — последний красный ПРЕЖНЕГО окна,
а мерж #167 лёг в 10:00:36Z, через 14 секунд; прогон `33746202354` (`4930561d`, 10:47:33Z) —
уже НОВОЕ окно за другим PR (#217). Между ними три зелёных прогона.

**Почему:** имя упавшего шага — это класс, а не происшествие. Один класс («копия в `comms`
разошлась с каноном в `main`») повторяется на каждом PR, который трогает канон, и интервал
между экземплярами измерен: 42 мин 31 с. Считать серию красных «от последнего зелёного назад»
верно ТОЛЬКО внутри одного окна — зелёный в середине означает, что окно закрылось, и то, что
краснеет после него, принадлежит другому предмету и другой кнопке.

**How to apply:** прежде чем назвать причину, взять `gh run list --branch main --workflow
checks.yml --limit 100` и найти ближайший `success` — он и есть граница. Дальше проверить
СТОРОНУ расхождения (`git diff origin/comms origin/main -- <канон>`): она переворачивается при
смене окна и опознаёт новый экземпляр надёжнее, чем имя шага. Уточняет
[[notifier-letters-collapse-to-one-cause]] (там N писем = одна причина — верно внутри окна) и
[[price-an-open-window-by-the-red-streak]] (серию резать по мержу, не по последнему письму);
предмет класса — [[red-main-checks-may-be-comms-sync]].
