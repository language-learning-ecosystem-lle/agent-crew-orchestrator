Множество учёток, которые контур реально может потратить, меряется **чтением креда из-под
пользователя роли**, а не перечнем в машинном конфиге:

```
id                                    # кто я на самом деле (демон/роль, не оператор)
test -r <configDir>/.credentials.json # претендент на трату
```

**Ловушка (замерено 2026-09-08, тред `179`):** дома на ящике `drwxr-x--x`, а креды `-rw------- <owner>`.
Значит каталог чужой учётки **виден и листается**, `existsSync(configDir)` → `true`, а
`.credentials.json` — EACCES. Единственная проверка, которая в пакете есть (`doctor`,
`configDirExists`), зелена ровно на той учётке, которую потратить нельзя; `resolveAccount`
файловой системы не касается вовсе — только «объявлен ли `configDir`» и спор типов.

Цена промаха: сессия умирает на кредах и записывается `exited-without-handoff`, то есть
**как провальная попытка роли** — три таких, и пара `exhausted` за чужую вину.

Причина, по которой это не теория: с 2026-09-04 контуры разведены по системным пользователям,
и каталоги в `/home/lle` (`.claude-lle-second`, `.codex`) для `aco-hetzner` закрыты. Учётка
доступна роли только если она либо в доме пользователя демона, либо у роли стои́т
`launch.systemUser` того дома (так живёт `devops`).

См. [[which-account-a-session-runs-on]] (какой каталог у живой сессии),
[[token-does-not-cross-the-sudo-switch]] (тот же класс: право пользователя, а не конфиг).
