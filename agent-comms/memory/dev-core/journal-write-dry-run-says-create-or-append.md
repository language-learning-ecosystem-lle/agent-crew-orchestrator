`journal write … --body-file <p>` без `--write` печатает план ОДНОЙ строкой-заголовком:
`would create agent-comms/journal/<role>/<thread>.md` — записи треда ещё нет; `would append …` —
запись уже лежит. Дальше он рендерит ВЕСЬ получившийся файл: сначала то, что уже в нём, потом твой
кусок. То есть одним сухим вызовом читается и факт наличия, и текст предыдущей записи — отдельной
команды чтения журнала в CLI нет, а в почту рукой лезть нельзя.

**Почему:** такт, продолжающий свой же предмет (жду CI → вешаю метку), не помнит, положил ли запись
прошлый такт; своё письмо в треде говорит «кладу» будущим временем и не доказывает ничего. Файл
append-only, и второй пересказ того же удалить нельзя.

**Как применять:** перед `journal write --write` в треде, где ты уже работал, гони сухой вызов и
читай заголовок. `would append` + запись по теме на месте → второй текст НЕ класть, а в письме
сослаться на сухой вывод как на доказательство. Замерено 14.09, тред 208: заготовленная запись
оказалась дублем положенной прошлым тактом. Тело для зонда — в своём `mktemp -d -p /tmp`.
