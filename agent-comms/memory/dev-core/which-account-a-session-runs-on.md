На какой учётке реально поднята сессия — замеряется, а не выводится из конфига:
`tr '\0' '\n' < /proc/<pid>/environ | grep CLAUDE_CONFIG_DIR` (рядом там же
`AGENT_PROTOCOL_SESSION_FILE` — по пути видно, ЧЬЕГО контура эта сессия, даже когда оба
контура живут на одном ящике).

**Ловушка:** `/home/lle/.claude` — одновременно каталог учётки `lle-main` И дефолт `claude`.
Значит его вид доказывает только «сессия НЕ на `lle-second`» (та требует явного
неде­фолтного `/home/lle/.claude-lle-second`), а не «лаунчер выставил `lle-main` осознанно».
Формулировать замер надо этой стороной, иначе выдаёшь совпадение за доказательство.

Так закрылось условие «демон прочитал новый конфиг» в треде 100 (2026-09-04): сессия поднята
через 62 с после мержа и уже из каталога `lle-main`.

Побочно: `doctor` пингует КАЖДУЮ объявленную в машинном конфиге учётку — по одному headless-вызову
на каждую, со следом-транскриптом в её каталоге. То есть каждый `doctor` тратит немного квоты
аккаунта с ограниченным окном, даже если ни одна роль на нём не поднимается.
