`faketime`/`libfaketime` на ящике **не установлен**. Чтобы прогнать процессный тест на другом
стенном времени, работает загрузчик, патчащий `globalThis.Date`, поданный через
`NODE_OPTIONS="--import file:///<path>.mjs"`: `sandbox()` процессных тестов наследует окружение,
поэтому смещение доезжает и до дочернего CLI.

**Оффсет обязан быть ОДИН на все процессы** — числом в переменной окружения
(`CLOCK_SHIFT_MS`, посчитать один раз в шелле). Загрузчик, который вычисляет «сдвинуть до
20:30Z» сам, пересчитывает его в каждом процессе заново: родитель уже поработал 20 секунд,
дочерний стартует с нуля — и дочерний оказывается ПОЗАДИ. 2026-08-31, тред `068`: возраст вышел
`36d 6h` вместо `36d 7h`, и это выглядело как дефект кода.

Два теста подмену не переживают, и это свойство инструмента, а не находка:
`fs/git.test.ts:117` (`toBeInstanceOf(Date)` — прототип-то подменённый) и
`orchestrator/instances.process.test.ts:454` при большом сдвиге ВПЕРЁД (дайджест сверяется со
временем, которое ставит git, а git оффсет не читает). Сдвиг НАЗАД в нужный час обоих последних
не задевает — если целевой час уже прошёл сегодня, брать вчерашний.

Зачем вообще: ассерт, зависящий от часа суток, — реальный класс дефектов, см.
[[assert-must-not-read-the-wall-clock]].
