Контур, докоммичивая брошенное дерево роли, называет ветку по треду ПРОГОНА:
`wip/<role>/<тред-прогона>-<стамп>`. Содержимое при этом может принадлежать совсем другому
треду — 2026-09-08 ветка `wip/dev-core/172-merge-gate-still-falls-on-private-…` несла правку
письма самоперезапуска треда 173, и все комментарии внутри диффа называли 173.

**Why:** решение «забрать или удалить» принимается по предмету, а по имени ветки предмет
опознаётся неверно — можно завести второй дом для работы, у которой дом уже есть.

Имя бывает и верным: 2026-09-08 ветка `wip/dev-core/177-workspace-per-pair-…` (`4dd63b0d`) несла
именно тред 177 — и всё равно была перекрыта живым PR #348, который **переименовал ключ**
(`orchestrator.pairs.perRole/perInstance` → `parallelism.pairsPerRole/pairsPerInstance`, второе
поле из опционального стало обязательным). Сверка блобов дала `DIFF` по всем файлам, кроме двух, —
перекрытие пришлось мерить идеями, а не хешами.

**Дешёвый решающий тест «это черновик, а не работа»: греп по САМОМУ СНИМКУ на потребителей его же
нового модуля.** `git grep -n <symbol> <wip-sha> -- packages` — у снимкового `config/pairs.ts`
(59 строк) нашлось ровно одно вхождение, и то упоминание пути в комментарии соседнего файла: ноль
вызовов внутри собственного коммита. Модуль без потребителя в своём же дереве — середина правки.

**How to apply:** дом брать из диффа (`git diff <wip>^ <wip>`), потом мерить, не перекрыт ли он:
`gh pr list --state open` по НАЙДЕННОМУ треду, дальше `git diff <wip> <pr-head> -- <пути>` и
посимвольная сверка идей. Снимок контура — середина правки: сигнатура функции уже сменена, а
вызов нет, новая функция объявлена и не вызвана — такой код не собирается, и это само по себе
довод, что живой PR его перекрывает. См. [[stale-pr-may-be-superseded]],
[[order-may-be-executed-by-another-thread]], [[predmet-can-change-threads-mid-run]].
