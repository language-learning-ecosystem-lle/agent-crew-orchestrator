Судишь принадлежность к множеству, которое посчитал чужой модуль, — бери функцию ключа ИЗ ТОГО ЖЕ
модуля. В `agent-protocol` два `pairKey`: почтовый `thread/index-doc.ts` даёт
`JSON.stringify([role, thread])`, планировщика `orchestrator/priority.ts` даёт `role\tthread`.
Множество замороженных пар приходит из `spentCeilings` (планировщик), и проверка почтовым ключом
не совпадает НИКОГДА — 2026-09-07 это давало «основание парка отпало» для любого живого основания.

**Why:** обе функции называются одинаково, обе экспортируются, обе про «пару role×thread», и
типы у них одинаковые — компилятор молчит, юниты со своим ключом зелены.

**How to apply:** импортируй ключ из модуля-источника множества (при коллизии имён — алиасом), а
негативный случай («молчит, пока факт жив») гоняй ПРОЦЕССНЫМ тестом: юнит, который сам строит и
множество, и ключ, эту рассинхронизацию доказать не может — см. [[door-defects-hide-in-process-tests]].
