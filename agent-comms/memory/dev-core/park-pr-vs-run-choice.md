Выбирая парк в `new-message`: `--parked-on pr:N` — ТОЛЬКО когда следующее действие на
маршруте буквально кнопка merge. Если между «сейчас» и кнопкой стои́т ещё чей-то ход
(curator видит зелёный CI и вешает `review`, ревьюер выносит вердикт), парк обязан быть
`run:N` — см. [[parked-on-run-takes-pr-number]] про то, что N там тоже номер PR.

**Почему:** `pr:N` снимается ровно одним событием — письмом с заголовком `merged-pr: N`
где угодно в почте. Пока парк стои́т, тред заморожен и роль, которая должна повесить метку,
контуром не поднимается. Событие, снимающее парк, наступает только ПОСЛЕ её хода — то есть
парк блокирует собственное условие снятия. Это случай треда `030` (8 часов замороженного
треда над готовой головой). У `run:N` условие наступает само: круг завершается, уведомитель
пишет, плюс есть потолок возраста 30 минут.

**Как применять:** 2026-08-30, тред `059`, PR #174 — я поставил `pr:174`, имея впереди ход
curator по метке. Чинится письмом в тот же тред: `--park-lifted pr:174 --parked-on run:174`,
редактировать отправленное нельзя (append-only). Дверь подтверждает правильный парк строкой
«waits for a run that is still running (1 of 1 on head …)».
