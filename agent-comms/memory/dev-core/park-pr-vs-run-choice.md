Выбирая парк в `new-message`: `--parked-on pr:N` — ТОЛЬКО когда следующее действие на
маршруте буквально кнопка merge. Если между «сейчас» и кнопкой стои́т ещё чей-то ход
(curator видит зелёный CI и вешает `review`, ревьюер выносит вердикт), парк обязан быть
`run:N`.

**N — номер PR В ОБОИХ случаях, а не номер прогона CI:** дверь идёт `gh pr view N`. Из строки usage
(`<person|pr:N|run:N>`) это не читается — `run:` там про «парк на круг прогона по этому PR», а не про
идентификатор прогона. Замер 2026-08-30, тред `056`: поставил `run:421` (номер прогона `checks`),
дверь не нашла PR #421, парк остался непроверенным и снялся бы только по 30-минутному потолку — пара
проснулась бы впустую. Правильно было `run:172`.

**Ошибка повторилась 2026-09-13, тред `189`, ХОТЯ эта заметка уже стояла** — значит строка индекса
обязана нести само правило, а не только ссылку (индекс поправлен тем же тактом). На 11-значном id
дверь теперь отказывает по имени и учит форме: `'run:<pr>' waits for the round ON that PR, not for a
run by its id` — то есть отказ ловит промах ДО отправки, но стоит лишнего круга рассуждения.

**Почему `pr:` опасен, когда впереди чужой ход:** `pr:N` снимается ровно одним событием — письмом с
заголовком `merged-pr: N` где угодно в почте. Пока парк стои́т, тред заморожен и роль, которая должна
повесить метку, контуром не поднимается. Событие, снимающее парк, наступает только ПОСЛЕ её хода — то
есть парк блокирует собственное условие снятия. Это случай треда `030` (8 часов замороженного треда
над готовой головой). У `run:N` условие наступает само: круг завершается, уведомитель пишет, плюс
есть потолок возраста 30 минут.

**`pr:N` дверь БЕЗ `--park-mover <участник>` не принимает** (замер 2026-09-03, тред `052`): отказ по
имени — «this park waits for A HAND on a button, and a thread that is parked raises nobody». Называть
надо роль, чья рука нажмёт (обычно `curator`); у `run:` такого имени не требуется — круг уже идёт.

**Кнопка john — это НЕ парк вовсе** (2026-09-03, тред `075`, PR #217: гард 4, дифф трогает
`.github/workflows/**`). Формально следующее действие — буквально merge, то есть по правилу выше
просится `pr:N`. Но нажимает john, а john контуром не поднимается: до кнопки вопрос доносит
curator, и парк на `pr:N` оглушил бы ровно того, кто её доносит — снялся бы он мержем, которого
без curator не будет. Признак случая: `--park-mover` некого назвать, кроме роли, чей ход и есть
условие снятия. Тогда парка нет, только `--waiting-on curator`.

**Как применять:** 2026-08-30, тред `059`, PR #174 — я поставил `pr:174`, имея впереди ход
curator по метке. Чинится письмом в тот же тред: `--park-lifted pr:174 --parked-on run:174`,
редактировать отправленное нельзя (append-only). Дверь подтверждает правильный парк строкой
«waits for a run that is still running (1 of 1 on head …)». Если в треде уже стоит чужой/свой парк,
новое письмо обязано его назвать — `--park-lifted <старый>` вместе с `--parked-on <новый>`, иначе
дверь откажет по имени ([[letter-into-a-standing-park-must-name-it]]).
