`.github/scripts/notifier-mute.sh:63,69` — ключ глушения это **имя** уведомителя, окно 900 с. У
`Claude PR Review` (событие `pull_request`) одно имя покрывает сколько угодно НЕЗАВИСИМЫХ PR, значит
письмо об отказе на одном PR глушит звонки об отказах на всех остальных в пределах четверти часа.
Замер 13.09.2026 (тред `180-notifier-down`): пять красных прогонов — писем три; заглушены
`34759487215` (#388) и `34759515483` (#383), в ленте их упоминаний **ноль** на 2536 строк.

**Why:** обещание письма «следующее доехавшее письмо назовёт его числом» исполняется только СЛЕДУЮЩИМ
ОТКАЗОМ того же имени. Кончилась серия зелёным — называть нечем, и заглушённое не попадает в почту
никогда. Автор правила объявил эту цену малой прямо (`notifier-mute.sh:37–43`), но с оговоркой, и она
несёт всю нагрузку: цена мала, «ровно в том случае… заглушённый хвост петли — это эхо СОБСТВЕННОГО
письма смотрителя». Заглушённый отказ о ЧУЖОМ PR эхом не является — там умирает живой круг ревью,
и его хозяину не сказал никто.

**How to apply:** разбирая звонок смотрителя, число отказов бери из прогонов НАБЛЮДАЕМОГО
(`gh run list --workflow '<имя>'`), а не из писем: письма — нижняя граница. Заглушённые опознаются
`gh run view <watch-run> --log | grep ЗАГЛУШЁН` — это единственное место, где они названы
([[notifier-watch-runs-count-the-window]]: `success` у смотрителя ≠ письмо). У каждого заглушённого
проверяй остаток в дереве: метка `review` висит, круга нет, PR выглядит отправленным на ревью
([[label-survives-force-push-and-mutes-the-lift]]). Починить ключ своей рукой нельзя: все места
решения (`notifier_mute_marker "$WF_NAME"`, `notifier_mute_decide`, тело письма) стоят в
`.github/workflows/notifier-watch.yml` — док власти; сам `notifier-mute.sh` доком власти НЕ является.
