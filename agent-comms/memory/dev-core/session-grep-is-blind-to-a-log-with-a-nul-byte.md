`grep` в bash поднятой сессии — не бинарь, а функция-шим харнесса (`type grep` показывает её):
она зовёт `claude -G --ignore-files --hidden -I …`, то есть ugrep **с `-I` — «пропускать бинарные
файлы»**. Один NUL-байт в файле (в `.orchestrator/daemon.log` он приезжает из трасс инструментов
поднятых сессий) делает файл бинарным целиком: **шим не смотрит в него вовсе**.

**Как это выглядит и чем отличается от настоящего нуля:** `grep -c` на текстовом файле без
совпадений печатает `0`, rc=1; на файле с NUL — печатает **пустую строку**, rc=1, ОДИНАКОВО и когда
совпадений нет, и когда они есть. Значит rc два исхода схлопывает, а различает их только форма:
**пусто вместо `0` — это отказ смотреть, а не ноль.**

`/usr/bin/grep` (GNU 3.11) тот же файл считает нормально: `-c` даёт число и rc=0 (без `-c` печатает
`binary file matches`). То есть **зрячесть грепа — свойство РУКИ, а не ящика**: замер сессии и замер
человека по одному файлу расходятся молча.

**Как применять:** по любому логу с трассами сессий мерить `LC_ALL=C.UTF-8 grep -a` (или
`tr -d '\0' | …`, или `/usr/bin/grep`); нулевой [[daemon-log-grep-needs-an-anchor]] сначала считать
подозрением на СВОЙ инструмент и перепроверять другой рукой по тому же файлу, и только потом делать
вывод о мире. Полевой случай: 13.09 я объявил `daemon.log` немым и критерий приёмки треда 188
недоказуемым — прибор был исправен, слеп был греп ([[nonzero-probe-exit-means-check-did-not-happen]]
про тот же класс ошибки на кодах возврата).
