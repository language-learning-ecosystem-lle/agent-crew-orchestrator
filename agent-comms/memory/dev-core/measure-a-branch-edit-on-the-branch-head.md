Оркестратор выдаёт дерево роли detached **на базе** (`origin/main`), а не на голове своей ветки —
даже когда дерево названо тредом, под который ветка уже открыта и запушена. Правка, дописанная в
таком дереве «поверх своего PR», на самом деле ложится поверх `main`: функции, объявленные ТОЛЬКО на
ветке, в ней отсутствуют.

**Чем это кусает:** tsx не тайпчекает, поэтому вызов отсутствующей функции доживает до рантайма и
падает `ReferenceError` внутри процессного теста. Снаружи это выглядит как **настоящий полевой
дефект правки** — тест краснеет, ассерт показывает пустой argv (`[]` вместо ожидаемого), и вывод
читается как «моя правка сломала логику». Замерено 17.09 (тред 219): правка `runWorkspaceInstall`
уронила 2 из 16 случаев `workspace-levelling.process.test.ts` — и на базе, и на голове, но по ДВУМ
РАЗНЫМ причинам, и только вторая была правдой.

**Why:** вывод «моя правка ломает стенд» я почти отправил заказчику как измеренный, стоя при этом на
чужом базовом дереве. Причина отказа была бы названа неверно, а решение «не брать в PR» — обосновано
несуществующим замером.

**How to apply:** прежде чем мерить правку своей ветки — `git log --oneline -1` в дереве роли и
`git checkout -q --detach <head PR>`. Дешёвая прямая сверка: грепнуть в дереве функцию, которую
правка зовёт (`grep -c 'const <fn>' <файл>`) — ноль значит, что мерить нечего. Обратный признак:
`git diff origin/<своя ветка> --stat` показывает СВОИ новые файлы со знаком минус («удалены») —
значит дерево стои́т не на голове. См. [[pair-worktree-may-have-no-node-modules]],
[[suite-color-depends-on-the-door-of-its-base]].
