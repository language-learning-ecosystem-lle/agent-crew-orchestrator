`merge-gate` печатает под guard 2 `note · base: the base moved AFTER the credited checks
started` — это **нота, а не STOP** (видно в самой строке: у STOP своя пометка). Она сравнивает
время коммита базы со временем СТАРТА зачтённого `checks`, поэтому гасит её ровно одно —
новый `pull_request`-прогон, а он рождается только движением твоей головы.

**Отсюда развилка, которую легко проспать:** пока у тебя впереди ещё есть правка, нота честно
«рассосётся сама» — так и было в 186 (msg-006 §3, msg-007 §5). Но после ПОСЛЕДНЕЙ правки голова
стоит, и та же нота доживает до кнопки curator. «Само рассосётся» становится ложным ровно в тот
момент, когда ты перестаёшь двигать ветку, — а формулировка в ленте остаётся прежней.

**Why:** цена — не отказ двери (guard 2 станет `ok`, как только круг позеленеет), а решение с
нотой на руках у того, кто жмёт. Не промеришь — либо кнопка встанет, либо инертность перемеряет
curator за свой такт.

**И «промерить прогоном на слитом дереве» НЕ стоит движения головы — это правка замером 14.09
(тред 198, #419 под approve).** Слияние строится и гоняется ЛОКАЛЬНО, голова PR не шевелится,
метка не снимается, круг не жжётся: `git merge-tree --write-tree <origin/main> <head>` даёт дерево,
`git commit-tree <tree> -p <base> -p <head>` — коммит, детач-чекаут в СВОЁМ рабочем месте роли даёт
его на диск, дальше по нему гоняются шаги джобы `checks`. Прежняя формулировка «лечение дороже
болезни» верна только для попытки перемерить руками CI (push), а не для замера на ящике.

**How to apply:** перед последним письмом такта спроси «двинется ли моя голова ещё раз?». НЕТ →
меряй инертность переезда САМ. Дёшево и слабо: `git merge-tree --write-tree <head> origin/main`
(код 0), `comm -12` над путями диффа и путями `merge-base..origin/main`, и — сильнее пустого
пересечения — греп по `origin/main` за именами тронутых тобой файлов: есть ли среди уехавших
путей хоть один их ПОТРЕБИТЕЛЬ. Пустое пересечение само по себе целости не доказывает
([[zero-hunk-consumer-can-still-break]]), поэтому границу замера называй вслух.

**Дорого и сильно — полная сюита на собранном слиянии (см. «Why»), и она отвечает на тот самый
вопрос, который нота задаёт, а не на соседний.** Три ловушки, каждая замерена 14.09:
1. **`refs/pull/N/merge` от GitHub — СНИМОК против СТАРОЙ базы** (первый родитель был `b20ac957d`,
   когда `origin/main` уже стоял на `a674e6c20`). Мерить по нему «текущее слияние» — соврать;
   слияние собирай сам от `origin/main` ([[pull-request-round-runs-the-merge-commits-yml]]);
2. **база уедет ПРЯМО В ХОДЕ прогона** (337 с сюиты хватило на ещё один merge в `main`). Не
   перемеряй с нуля: сверь ДЕРЕВО прогнанного слияния с деревом нового `git diff --name-only` —
   дельта в один файл журнала зелень переносит, дельта в `packages/**` требует перепрогона;
3. **рабочее место роли вернуть детач-чекаутом на исходную базу** и убедиться, что
   `git status --porcelain` пуст: грязное дерево — отказ запуска роли на следующем такте (R17).

Утверждение замера держи скромным: прогон на ЯЩИКЕ прогон CI не заменяет
([[green-depends-on-where-the-checkout-lives]]), гард 2 всё равно зачитывает старый прогон. Он
проверяет ГИПОТЕЗУ «база уехала → слияние покраснело», и этого нажимающему хватает. Смежное:
[[rebase-falsifies-measurements-about-the-base]], [[suite-color-depends-on-the-door-of-its-base]],
[[rebase-without-a-force-push]], [[label-survives-force-push-and-mutes-the-lift]].
