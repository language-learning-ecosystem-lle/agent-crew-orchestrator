Вердикт `needs-fixes`, чья находка — про ТЕКСТ (заявленное число тестов, формулировка в теле PR),
закрывается правкой тела PR + снятием и повторной навеской метки `review` на ТОЙ ЖЕ голове.
Коммита-пустышки ради «нового круга» не нужно.

**Why:** гард 1 хочет approve в окне ЗАКРЫТОГО круга на ТЕКУЩЕЙ голове; круг поднимает событие
`labeled`, а не смена головы (см. [[branch-may-be-ahead-of-thread]]). Раз дерево не виновато —
двигать голову значит выбросить уже зелёный `checks` и оплатить его заново.

**How to apply:** исправить тело PR, пометив в нём, что число исправлено по вердикту; настоящую
строку повторить письмом в тред (лента append-only, старое сообщение не редактируется);
`gh pr edit --remove-label review` → `--add-label review`; голову назвать в письме тем же SHA.

Полевой случай 2026-09-03, #232 (тред 064): заявлено `comms-derive.test.sh 12/12`, живой прогон —
17 `ok` (`grep -c '^check '` → 17). Отсюда же: число тестов в теле PR брать из свежего прогона,
а не из памяти о нём — см. [[door-defects-hide-in-process-tests]].

**НЕБЛОКИРУЮЩАЯ находка про тело закрывается ВООБЩЕ БЕСПЛАТНО — метку перевешивать не надо.**
Перевеска нужна только там, где надо ПЕРЕВЕРНУТЬ вердикт `needs-fixes`. Когда `approve` уже
доставлен, а находка объявлена неблокирующей («правки не требую, но назову»), правка тела ничего
не рушит: событие `edited` не поднимает ни круг (`claude-review.yml` — только `labeled`), ни
`checks` (`opened/synchronize/reopened`). Замерено 2026-09-14 на #411 (тред 197): `gh pr edit
--body-file` → повторный `merge-gate` на той же голове `9234fe7` даёт `ok guard 1` (approve внутри
круга 34839985145) и `ok guard 2` (review=SUCCESS, checks=SUCCESS). Перевесил бы метку — сжёг бы
круг ради абзаца.
