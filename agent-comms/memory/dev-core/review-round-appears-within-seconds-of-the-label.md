Прогон `Claude PR Review` создаётся практически мгновенно после события `labeled`: замерено дважды
на PR #461 — метка `11:30:41Z` → `created_at 11:30:43Z` (2 с) и метка `11:53:11Z` →
`created_at 11:53:12Z` (1 с).

**Что из этого следует:** повесил метку — тем же ходом проверь, что круг РОДИЛСЯ, одним вызовом
`gh api 'repos/<o>/<r>/actions/runs?head_sha=<sha>' --jq '.workflow_runs[] | "\(.id) \(.name)
event=\(.event) status=\(.status)"'`. Это не ожидание чужого прогона (ждать нечего, секунда), а
приёмка своего действия: «метка повешена» и «круг идёт» — два разных факта, и второй бывает ложным
(самопропуск по отставшему `claude-review.yml`, отсутствие прав, отказ триггера). Отложить проверку
на следующий такт — значит объявить в треде круг, которого может не быть, и потерять подъём.

Заодно этот же вызов даёт перечень прогонов на голове: после зелёного `checks` + метки их ровно два.
Ноль прогонов ревьюера на голове с меткой — дефект, а не «ещё не поднялся».
