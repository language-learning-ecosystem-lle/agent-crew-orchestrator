`git diff --numstat <старая голова> HEAD` после `git merge origin/main` **никогда не даст ноль
удалений**, если `main` правил существующие файлы: правка строки в `--numstat` — всегда пара
«добавлено/удалено», и все эти удаления принадлежат `main`, а не тебе. Замерено 15.09 (ветка
`dev-core/207-…`, влив `117164193` в `3be24909`): пятнадцать строк, шесть с ненулевыми удалениями,
конфликтов не было вовсе.

**Why:** «ноль удалений против КАЖДОГО РОДИТЕЛЯ» — критерий РУЧНОГО разрешения конфликта
([[manual-conflict-fix-needs-zero-deletions-proof]]), и в классе чистого влива он ложно краснит.

**How to apply:** целость влива доказывается ПАРОЙ:
1. `git diff --numstat origin/main HEAD` = ровно вклад PR (ни строки сверх) — никого не съел;
2. `git diff --numstat <старая голова> origin/main` против `git diff --numstat <старая голова> HEAD`
   — списки обязаны совпасть число в число ВСЮДУ, кроме строк собственного вклада, где числа
   зеркальны (`1 29 f` против `29 1 f`).

Ещё дешевле на ту же мысль — блобы своих файлов: `git rev-parse <старая голова>:<путь>` против
`git rev-parse HEAD:<путь>`. Совпали — влив предмета не коснулся. Отдельно гоняй греп на вторую
копию своего предиката ([[clean-merge-can-bring-back-half-the-defect]]).
