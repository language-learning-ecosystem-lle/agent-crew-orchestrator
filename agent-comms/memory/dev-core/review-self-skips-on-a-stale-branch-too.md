`claude-code-action` сверяет `.github/workflows/claude-review.yml` прогона с версией на дефолтной
ветке и пропускает сам себя при любом расхождении (гард против промпт-инъекции правкой воркфлоу).
Расхождение бывает ДВУХ происхождений, и лечатся они противоположно:

- **PR правит воркфлоу сам** — «подтянуть main» не поможет по построению, версии не совпадут до merge;
  ревью человеческое (`PROTOCOL.md`, класс 558);
- **ветка отстала**, а `main` уехал по этому файлу — PR воркфлоу не трогает вовсе. Лечится ровно тем,
  что называет коммент: перебазировка на `main` + метка заново.

**ГАРД МЕРЯЕТ ОДИН ФАЙЛ — `claude-review.yml`, а не каталог `.github/workflows/`.** PR, правящий
ДРУГОЙ воркфлоу, для этого гарда воркфлоу НЕ правит, и «ревью человеческое» к нему не относится.
Замерено 2026-09-14 на #413 (тред `191`, дифф — один путь `.github/workflows/notifier-watch.yml`):
грубая эвристика `git diff $(git merge-base origin/main <голова>) <голова> -- .github/workflows/`
НЕ ПУСТА → читалась бы как «PR правит воркфлоу», то есть отправила бы PR на человеческое ревью
навсегда. Прямой замер сказал обратное: блоб `claude-review.yml` головы `0f98404d` ≠ `main`
`d7c5c84a` — ветка просто отстала (ниже неё сели #417/#418, правившие этот файл). `git merge
origin/main` + ff-push → блоб `d7c5c84a` с обеих сторон.

**И блоб ГОЛОВЫ тоже не критерий — гард меряет дерево ПРОГОНА, то есть `refs/pull/N/merge`.**
Замер curator 2026-09-14 (тред `191`, msg-001), перепроверен мной: на #413 блобы были ТРИ разных —
`main` `d7c5c84a`, merge-ref `37770131` (им шёл прогон), голова `0f98404d`. merge-ref был собран
`09:21:47Z` против базы времён #418, а #417 правил `claude-review.yml` в `10:53:38Z`.

**Главное, и оно объясняет всё остальное: GitHub НЕ пересобирает merge-ref на каждый merge в `main`**
— только на движение ГОЛОВЫ PR (на движение базы — не всегда и не сразу). Поэтому у стоячего PR
перевешивание метки поднимает круг СТАРЫМ воркфлоу и самопропускается снова: **этот класс лечится
только сдвигом головы** (`git merge origin/main` в ветку + ff-push), а не меткой.

**Единственный годный замер — блоб merge-ref, ДО метки:**
```
git fetch -f origin refs/pull/<N>/merge:refs/tmp/<N>merge
git rev-parse refs/tmp/<N>merge:.github/workflows/claude-review.yml
git rev-parse origin/main:.github/workflows/claude-review.yml
```
Совпали → метку вешать можно. Не совпали → двигать голову, потом мерить ЗАНОВО (на #413 после
ff-push merge-ref пересобрался с базой = текущий `main` и блобом `d7c5c84a` — проверено до метки).
Постфактум самопропуск виден даром по ДЛИТЕЛЬНОСТИ: 40 с против настоящих 4–5 мин.

**ОТСТАВШАЯ БАЗА merge-рефа сама по себе головы двигать НЕ требует — критерий только блоб.** Замер
14.09 (тред `197`, до метки на #410/#411): базовый родитель обоих рефов `970957c37`, тогда как `main`
ушёл на `a1bd336f1` (два коммита: `PROTOCOL.md`, `docs/protocol-reference.md`, журналы) — базу
читать как признак значило бы двигать обе головы и обнулить два уже зелёных `checks` ради двух
лишних прогонов. Прямой замер: блоб `claude-review.yml` в ОБОИХ рефах `d7c5c84a` = `main`, метка
безопасна. Базового родителя мерят для ДРУГОГО вопроса — состоялась ли приёмка правки `.yml`
([[pull-request-round-runs-the-merge-commits-yml]]); для вопроса «вешать ли метку» он даёт ложную
тревогу.

**СОВПАДЕНИЕ блоба доказывает «круг не самопропустится» ТОЛЬКО если merge-ref собран против текущей
базы — иначе сверка проходит вхолостую.** Прямое следствие абзаца выше («GitHub не пересобирает
merge-ref на движение базы»): у стоячего или конфликтующего PR merge-ref — снимок, и сравнение его
блоба с `main` сравнивает `main` со СТАРЫМ деревом. Оба условия при этом выглядят исполненными.
Признак снимка бесплатный — номер merge-ref НЕ изменился, хотя `main` уехал. Но и он неоднозначен:
замер 14.09 (тред `200`, #414) — `main` ушёл `43bd494f0` → `b20ac957d`, merge-ref остался тем же
`3d94b1db4`, и это оказалось ЧЕСТНЫМ совпадением, потому что слияние новой базы с той же головой
даёт то же дерево. Различает одна команда, и мерить надо её, а не номер:
```
git log -1 --format='%H %P' refs/pull/<N>/merge     # второй столбец = ПЕРВЫЙ родитель
```
Первый родитель == `origin/main` → ref свежий, сверка блоба честная. Не равен → ref снимок, блоб
ничего не доказывает, сперва двигать голову. Дешевле любой перепроверки постфактум по длительности.

**ВЛИТЫЙ В ВЕТКУ `main` делает голову самопропуск-НЕПРОБИВАЕМОЙ — и свежесть merge-рефа перестаёт
быть вопросом вовсе.** Это лучше, чем «мерить блоб и ждать пересборки рефа»: как только ветка САМА
несёт дефолтную версию `claude-review.yml`, слияние её с любой базой даёт этот же блоб — снимок реф
или нет. Замер 2026-09-15 (тред `209`, #443/#444): `#445` сел в `main` в `09:14:30Z`, правя
`claude-review.yml` (`4eb5716d8` → `b2babcfb9`); через 10 минут оба merge-рефа всё ещё стояли
снимками (`parent1 = 117164193`, блоб `4eb5716d8`), и пересборку НЕ ВЫЗВАЛ даже запрос
сливаемости (`gh pr view --json mergeable` вернул `MERGEABLE/CLEAN`, реф не двинулся). Метка,
повешенная в это окно, купила бы красный самопропуск на обоих. `git merge origin/main` + ff-push →
блоб `b2babcfb9` на головах, и вопрос закрыт без гадания о рефе. Цена — по одному прогону `checks`
на PR и такт ожидания: метку всё равно вешают ПОСЛЕ зелени новой головы.

**Мнимое противоречие, на которое я потратил полтакта:** круги #388/#411/#410 шли полные 4–5 минут,
хотя блоб их ГОЛОВ расходился с `main`. Они ехали своими merge-ref, собранными когда те `main` ещё
соответствовали. Меряешь голову — получаешь ответ не на тот вопрос.

**Why:** второй случай выглядит как первый (тот же коммент «Ревью не состоялось», та же зелёная джоба,
шаг `claude-code-action` длиной в 3 секунды), но норма 558 читается как «лечение неприменимо» и уводит
к человеческому ревью на ровном месте. Полевой случай 2026-09-06, #285: голова зелёная по `checks`,
до неё три чужих merge, один из них — по `claude-review.yml`.

**How to apply:** различает случаи не `origin/main ↔ голова` (он не пуст в ОБОИХ), а дифф от базы
слияния: `git diff $(git merge-base origin/main <голова>) <голова> -- .github/workflows/`. Не пуст →
PR правит воркфлоу, ревью человеческое. Пуст, а `origin/main ↔ голова` не пуст → ты просто отстал,
перебазируйся. И метку снять ДО зелени новой головы —
[[label-survives-force-push-and-mutes-the-lift]].

**Гард меряет ФАЙЛЫ воркфлоу, а не «отстал ли ты» — и это разные вопросы.** «Не пуст `origin/main ↔
голова` → перебазируйся» выше верно как эвристика, но буквально прочитанное гонит на лишнюю
перебазировку, обнуляющую зелёный `checks`. Прямой замер критерия — тождество содержимого:
`git diff origin/main <голова> -- .github/workflows/` плюс `git rev-parse` блоба
`claude-review.yml` с обеих сторон. 2026-09-06 на #304 после перебазировки `main` уехал ещё раз
(#305, только `docs/`): ветка снова ОТСТАЛА, а блоб тождествен (`476d92eb`) — второй перебазировки
не делал, метку повесил на зелёную голову. Мерить надо ПРОТИВ ТЕКУЩЕГО `origin/main` в момент
метки, а не против того, на который перебазировался ([[rebase-falsifies-measurements-about-the-base]]).
Круг на этой голове при передаче хода стоял `queued` — критерий взят из текста самого гарда, исходом
круга он ещё не подтверждён.

**Направление расхождения роли НЕ играет — и «зато возьмётся версия main» здесь ложь.** Отставание
пропускает так же, как правка. (Механизм в этом абзаце я когда-то назвал неверно — «читает файл
ЧЕКАУТА ветки»; дерево прогона — `refs/pull/N/merge`, замер выше 14.09. Вывод абзаца от этого не
меняется, но мерить по нему голову нельзя.) 2026-09-06 на #304 этим рассуждением я повесил метку на отставшую голову: круг кончился
за 36 с (настоящие — ~4 мин; **длительность и есть первый признак**), `review` зелен и ПУСТ. Факт
называет не вердикт, а warning прогона: «в прогоне отличается от версии на 'main', и действие не дало
выхода (execution_file пуст) — оно пропустило само себя, правило №14». Ср.
[[failed-review-round-class-lives-in-the-artifact]].
