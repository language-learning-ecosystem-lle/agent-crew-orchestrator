Прогон события `pull_request` берёт `.github/workflows/*.yml` из **merge-рефа** PR
(`refs/pull/<N>/merge` = голова × база), а не из дерева головы. Отсюда две половины, и вторая
дороже:

- **отставание ДЕРЕВА ГОЛОВЫ правку не отменяет** — ветка, отрезанная задолго до посадки, всё равно
  несёт новый шаг;
- **но отставание САМОГО MERGE-РЕФА — отменяет.** Движение базы реф НЕ пересчитывает: замер 14.09 —
  базовый родитель `refs/pull/419/merge` стоял на базе `13.09 19:41Z`, когда `main` ушёл на 16 часов
  и много коммитов вперёд. Пересчитывают его head-пуш и (ВЫВОД, не замер: триггер не изолирован)
  запрос мержабельности — у PR, по которым гоняли `merge-gate`/`gh pr view --json mergeable`, реф
  свежий.

**Why:** приёмка правки воркфлоу «первым живым кругом после мержа» даёт ЛОЖНОЕ КРАСНОЕ. Полевой
случай 14.09: #417 сел `10:53:39Z`, круг `34836883802` в `11:10:51Z` (+17 мин) исполнил СТАРОЕ тело
шага; круг `34837984835` на голове, двинувшейся после посадки, — новое. Прежний замер (#418 сел
`09:21Z`, круг `34834578877` в `10:43Z` его нёс) верен, но правило из него было выведено слишком
сильное: там прошло 82 минуты и дверь по тому PR гоняли.

**How to apply:** ПЕРЕД приёмкой правки `.yml` чужим кругом мерь базового родителя его merge-рефа, а
не время старта прогона:
`git fetch origin refs/pull/<N>/merge:refs/tmp/m && git log -1 --format=%p refs/tmp/m`, затем
`git show refs/tmp/m:.github/workflows/x.yml | grep -c '<новая строка>'`. Реф старее посадки →
**замер НЕ СОСТОЯЛСЯ**, а не «починка не работает». Обратное тоже верно: сломанный шаг накрывает
открытые PR не разом, а по мере пересчёта их рефов. Само исполненное тело доказывается эхом `run:`
в логе. Дополняет [[run-headsha-does-not-name-the-code-it-ran]] и
[[conditional-step-fix-is-accepted-by-its-own-log-line]]; про `ref: main` у вызываемых скриптов —
[[workflow-wiring-is-pinned-by-a-delivery-integration-suite]].
