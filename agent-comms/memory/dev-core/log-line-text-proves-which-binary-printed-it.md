Чтобы доказать, что в поле работает код ПОСЛЕ коммита `X`, ищи в журнале подстроку, которую
ввёл сам `X`. Обратный замер обязателен: `git grep -c "<подстрока>" <X>^ -- <файл>` должен дать
**ноль**. Тогда строка — тождество по содержимому: двоичный код старше `X` её напечатать не мог,
и датировать такт не нужно вовсе.

**Why:** приёмка «после мержа поведение изменилось» обычно упирается в датировку строк, а
`daemon.log` датировать нечем — ISO-строки в нём приезжают из ТРАНСКРИПТОВ ролей, а не от часов
такта (та же причина, по которой счёт требует якоря — [[daemon-log-grep-needs-an-anchor]]).
Замер 2026-09-09 (тред 184): #363 добавил вторую ветку текста
`already told about in '…', nothing new to ring about` рядом со старой `every half closed`;
её отсутствие на предыдущей ревизии файла закрыло полевую приёмку за один греп — тогда как
«писем больше нет» не доказывало ничего, потому что тишина началась ЗА ЧАС ДО мержа
([[silence-claim-is-checked-in-notify-state]]).

**How to apply:** правя текст отказа/строки журнала, замечай, что делаешь себе ЯКОРЬ приёмки —
менять формулировку заодно с поведением полезно, а не косметика. Меряя чужой мерж — сначала ищи
в диффе новую подстроку, потом уже думай про время. Если время всё-таки нужно: такт датируется
не журналом, а именем файла в `.orchestrator/sessions/` (`<UTC подъёма>-<роль>-<тред>.jsonl`) —
строка журнала лежит внутри времени жизни сессии, транскрипт которой её окружает.
Родственное про деревья, а не про журналы — [[file-revision-in-a-tree-is-identified-by-content]].
