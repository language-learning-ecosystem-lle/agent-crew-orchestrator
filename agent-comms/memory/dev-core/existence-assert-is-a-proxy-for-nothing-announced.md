Добавил в `notify.state` счётчик, который пишется и на ОТКАЗАННОМ такте, — покраснели четыре чужих
ассерта в `notify.process.test.ts` (3) и `daemon.process.test.ts` (1): `expect(existsSync(state)).toBe(false)`.

**Why:** «файла нет» там стояло дешёвой заменой утверждению «триггер не съеден, ничего не объявлено».
Отменять свою запись ради зелени значит терять счёт, который обязан пережить процесс; менять ассерт на
`toBe(true)` значит стереть чужую проверку.

**How to apply:** сузить ассерт до точного — «в файле нет ни одной строки, кроме моей новой»
(`lines.filter((l) => !l.startsWith("<мой ключ>"))` → `[]`), и назвать в комментарии, почему файл теперь
может существовать. Проверка становится строже, а не слабее. И искать такие ассерты ЗАРАНЕЕ, гоняя полную
сюиту: точечные файлы предмета их не ловят — см. [[door-defects-hide-in-process-tests]].
