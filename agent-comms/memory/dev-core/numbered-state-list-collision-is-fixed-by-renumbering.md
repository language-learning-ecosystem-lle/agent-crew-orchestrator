Хвост `.github/scripts/review-delivery.integration.sh` — нумерованный список состояний, и два
открытых PR занимают одни и те же номера просто потому, что оба дописывают конец файла. Слияние
даёт ровно один конфликт по этому файлу (`claude-review.yml` при этом сливается сам).

**Как чинить:** блок ПОЗДНЕГО PR переномеровать, взяв номера после чужих (в 09.2026: #431 занял
(23)–(24), блок цвета круга стал (25)–(28)). Механическое склеивание номеров молчаливым не будет —
`note_state` роняет прогон по имени («состояние объявлено дважды»), а итоговая строка считает число
прогоном, а не переписывает из письма.

**Номер состояния живёт минимум в трёх местах, и греп по `(NN)` обязателен:** сам скрипт
(`note_state`, `CURRENT_STATE="A-B"`, `echo '== (NN) …'`, переменные вида `FINAL_NN`), комментарии-пины
в `.github/workflows/claude-review.yml` («пин на эту строку — состояния (…)») и тело PR + запись
журнала, где номера названы в приёмке.

**Целость слияния доказывается двумя замерами:** `git diff --numstat HEAD^2 HEAD` против `main` —
удалений 0 (чужого не съедено), а против прежней головы ветки каждая снятая строка перечисляется
поимённо — там обязаны быть только свои переномерованные строки и вытесненные чужой правкой
предикаты. См. [[manual-conflict-fix-needs-zero-deletions-proof]], [[contribution-patch-not-tree-diff-proves-a-merge]].
