У простоя самоперезапуска ДВА разных якоря, и они не обязаны совпадать:

- строка `daemon.log` `N commit(s) behind, drifting for … (since X)` берёт `X` = **время коммита**
  первого уехавшего коммита (`describeDriftSize`, `code-age.ts`; минуты — `Math.round`);
- поле письма «сколько ждал сессии» = `went − drainSince`, где `drainSince` — **первый ТИК**, на
  котором дренаж открылся (`self-restart.json`).

Между ними лежит задержка «коммит → тик, который его увидел» (fetch + интервал тика): замерено
15.09 — 24 с (цель `c9f3b9cab` 13:11:21Z, `drainSince` 13:11:45Z) и 30–89 с на соседней эпохе.

**Why:** приёмка починки #452 (тред 210) была сформулирована как «поле обязано сойтись со строкой
`drifting for …`» — дословно этого не будет НИКОГДА, и приёмку легко провалить по причине, которая
дефектом не является.

**How to apply:** сверять точно — с первым тиком дренажа (первая строка `DRAINING TO RESTART` этой
эпохи); с якорем дрейфа — с допуском в один тик. Занижение БОЛЬШЕ полосы — дефект; внутри — норма.
Закрыть остаток значило бы сменить объявленный смысл поля — это новая норма и кнопка john.
Мерить лог только анкерованно: [[daemon-log-grep-needs-an-anchor]], [[field-acceptance-is-a-before-after-across-code-epochs]].
