`.orchestrator/daemon.log`(+`.1`) — бесплатный оракул ДО/ПОСЛЕ для любой влитой в ящик починки
печати: строки `daemon — code: <sha> … up since <ts>` ([[daemon-log-dates-its-own-code]]) режут
журнал на эпохи, и одна и та же строка ящика по обе стороны границы — это замер, а не пересказ.

**Приёмка вида «после починки плохого не случилось» слабая** — её нули объясняются и отсутствием
входа. Сильная форма из трёх движений:

1. **счёт по эпохам одной командой** — `awk`, держащий последний `code=$5`, копящий строки такта и
   сверяющий их на строке плана; якорь `^agent-protocol: ` обязателен, иначе в счёт идут ленты
   собственных сессий ([[daemon-log-grep-needs-an-anchor]]);
2. **изоляция границы** — `git log --oneline <старый sha>..<новый sha>` обязан дать РОВНО
   проверяемый коммит, иначе эпохи различаются не только починкой; отдельно сверить, что не менялся
   конфиг, влияющий на печать (`daemon — gates:` под `sort -u` — одна строка);
3. **разводка «починка или просто данные»** — найти предмет, который через границу НЕ менял
   состояния: пара с тем же `waiting since` по обе стороны не доставляла и не поднималась, поэтому
   переворот её строки ровно на границе эпох объясняется только кодом. Пара, у которой
   `waiting since` уехало, для этого НЕ годится — её счётчик обнулила бы и старая ветка.

**Цена промедления — сам журнал:** `daemon.log.1` перезаписывается следующим перезапуском демона, то
есть доказательная сторона «ДО» живёт до ближайшей ротации. Отсюда: строки цитируются в отчёт
ДОСЛОВНО, а не адресуются номерами (номера в живом растущем файле не едут, но переживают только
текущую эпоху).
