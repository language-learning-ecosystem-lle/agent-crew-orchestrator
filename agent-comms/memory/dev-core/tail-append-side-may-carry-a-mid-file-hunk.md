Разводя конфликт «обе стороны дописывают в конец», собирай слитый файл из ЦЕЛОГО файла одной
стороны (`git show <ref>:<path>`) плюс своей дельты — НЕ из `база + хвост_чужой + хвост_свой`.
Перед сборкой посчитай хунки каждой стороны: `diff -u <база> <сторона> | grep '^@@'`. Один хунк в
конце — сторона действительно хвостовая; два и больше — нет.

**Why:** 13.09, #386, `docs/journal/dev-core.md`: постановка называла обе стороны хвостовыми, и
сторона ветки такой и была (один хунк, `@@ -593,3 +593,157 @@`). А сторона `main` несла ДВА:
`@@ -416,6 +416,80 @@` — две записи, вставленные в середину, — и хвост. Сборка по посылке
«база + хвосты» потеряла бы 74 строки середины МОЛЧА, и [арифметика ДО сборки](manual-conflict-fix-needs-zero-deletions-proof.md)
этого бы не заметила: числа сошлись бы всё равно, потому что она меряет только приросты хвостов.

**How to apply:** посчитать `^@@` у каждой стороны; собрать `cat <(git show <их-ref>:<path>) <своя
дельта>`; затем доказать блоки побайтово (`cmp`, не `diff`) — см. [[commutative-merge-is-not-proof-nothing-was-eaten]].
Журнал роли принимает записи по ДАТЕ, поэтому «хвостовым» его вход только кажется.
