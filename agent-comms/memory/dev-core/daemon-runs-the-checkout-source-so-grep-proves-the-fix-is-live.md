Письмо о самоперезапуске про установленную копию не утверждает ничего («критерий консервативен
намеренно» — он называет лишь пути, правка которых МОГЛА сменить программу). Замерить настоящее
состояние дёшево, потому что демон не ставит отдельную копию:

- `ps -o pid=,lstart=,args= -p <pid из daemon-code.json>` показывает
  `node --import …/tsx/dist/loader.mjs …/packages/agent-protocol/src/cli.ts orchestrator up` — то
  есть исполняется исходник ГЛАВНОГО чекаута;
- `git rev-parse HEAD` того же чекаута + `grep -c <имя новой функции>` по её файлам доказывают, что
  починка в исполняемом коде.

**Why:** приёмка «до/после» через границу эпох опирается на то, какой код породил письмо; отпечаток
из письма для этого слишком слаб, а `ps` закрывает вопрос одной строкой.

**How to apply:** `ps` печатает время старта в TZ СЕССИИ (здесь CEST +02), а `daemon.log` — с
офсетом +03; прежде чем звать расхождение дефектом, сверь зоны. Дату эпохи брать из
[[daemon-log-dates-its-own-code]]; см. [[field-acceptance-is-a-before-after-across-code-epochs]].
