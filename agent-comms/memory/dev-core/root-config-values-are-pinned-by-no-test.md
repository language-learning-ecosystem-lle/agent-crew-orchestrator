Тесты схемы и тика гоняют СВОИ фикстуры (`schema/v27-pair-ceilings.test.ts` собирает конфиг
хелпером `config({…})`, `orchestrator/tick.test.ts` получает `ceilings` аргументом). Корневой
`agent-protocol.json` ради его значений не читает НИ ОДИН тест — замерено 15.09 на `parallelism`
(тред 211, потолок 3 → 5).

**Why:** значит зелёный `checks` на PR, меняющем значение конфига, доказывает только валидность
JSON и общие двери схемы — про само новое число он не говорит ничего. Подать сюиту как приёмку
такой правки = выдать проверку соседнего предмета за проверку своего.

**How to apply:** приёмка такой правки — две вещи, обе рукой. (1) Прогнать НОВОЕ значение через
`parseProtocolConfig` на ФАЙЛЕ ветки (не на фикстуре) — ловит полудекларацию и перевёрнутую пару.
(2) Всё остальное — ПОЛЕМ, после merge, строкой живого демона; см.
[[dry-run-is-a-free-oracle-on-the-ceilings]]. И перед правкой грепать в ДВЕ кучи — пин в тестах и
норму в доках ([[changed-sentence-must-be-grepped-into-two-piles]]): молчание обеих куч само есть
результат замера, его докладывают, а не умалчивают. Кнопка: Д-4 покрывает только
`protocolVersion`, любая другая строка корневого конфига — гард 4 и john.
