Спор «чинится словом строки или это второй раз тот же тип работы» решается **прогоном кода на
БУДУЩЕМ входе**, а не чтением диффа. Собери руками то состояние, которое фича создаст после
включения, вызови нынешнюю функцию и напечатай её вывод.

**Why:** 2026-09-09, тред `177`, кадр оператора. По чтению — одна печатаемая строка
(`priority.ts:394`), цена — «поправить слова». Пробой `busyRoles` + `describeOrder` на двух живых
парах ОДНОЙ роли (то, что даёт потолок >1) показал три дефекта разом: карта `role → elsewhere`
молча теряет наряд (`set` по ключу-роли, побеждает последний), из-за потери ломается сравнение
`sameThread`, ради которого кадр писался, и строка выдаётся паре, у роли которой места ещё есть.
Ни один не чинится словами. Замер занял один файл в `mktemp -d` и одну минуту, а решал границу
«свой PR или тем же диффом» — то есть лишний круг ревью.

**How to apply:** пробой писать в своём `mktemp -d` ВНЕ обоих чекаутов (не временной копией теста
в пакете — [[probe-copy-pollutes-the-full-suite]]), импортируя модуль абсолютным путём через
`node --import tsx`; типы `as any` — вход собирается руками, tsx его не судит. Печатать НЕ «упало
/ не упало», а сам вывод: в докладе он идёт дословной цитатой и снимает вопрос без пересказа.
Класс ключа проверять первым: карта, ключ которой — половина пары, теряет данные ровно там, где
появляется параллельность ([[set-from-another-module-needs-its-own-key]]).
