Заметки `ci-outcome.yml` про снятый/неснятый ход запиннены процессными тестами
`new-message.process.test.ts` («lets the machine writer of the … note through»): тест кладёт фразу
СВОИМ литералом и гонит через дверь почты. Это пиньит ДВЕРЬ (что она не примет фразу за объявление о
снятии хода) и НЕ пиньит воркфлоу — правка yml мимо теста ничего не покраснит, а в поле уедет
непроверенная фраза.

**Why:** покрытие меряется не наличием ассерта, а тем, ЧЕЙ экземпляр литерала он читает. Две копии
одной строки в разных файлах — это два предмета, и тест сторожит ровно тот, который держит в руках.

**How to apply:** пиньишь текст, который печатает чужой файл (воркфлоу, скрипт, шаблон) — вынимай
его ИЗ ФАЙЛА (`readFileSync` + регэксп по `printf '\n(…)\n'`) и уже этот кусок веди через дверь;
литерал в тесте оставляй только как второй, дополнительный ассерт. Прецедент чтения файла из теста
рядом: `roles/reviewer-pr.test.ts` читает `claude-review.yml`. Смежное:
