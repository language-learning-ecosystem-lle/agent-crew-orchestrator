Правишь класс отказа GitHub (запрещённый узел, лишний scope, форма payload) — **грепни имя поля по
всему `src`, а не только по файлу двери**. `pullRequestFacts` один, а спрашивают его ДВА места:
`merge-gate` в `cli.ts` и `ghMergeReadySource.facts` там же. Подстановка треда 160 села только в
первое; второе продолжало спрашивать `statusCheckRollup` и молча гасило ярус приоритета полтора
месяца.

**Why:** общий МАППИНГ фактов (`pullRequestFacts`) выглядит как общая точка починки, но вызов `gh`
у каждого потребителя свой — и комментарий «одно чтение, два вызывающих» над маппингом это скрывает.

**How to apply:** после правки отказа — `grep -rn '<имя поля>' src --include=*.ts | grep -v test` и
посмотреть КАЖДЫЙ `execFileSync("gh"…)`, а не только тот, что в постановке. Второй потребитель часто
деградирует иначе первого: у двери это отказ по имени, у яруса — молчание, потому что там «ничего не
делать» и есть штатный ответ. См. [[silent-loss-is-the-unraised-turn]].
