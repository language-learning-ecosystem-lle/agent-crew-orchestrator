`gh api --jq '<фильтр>'` исполняет фильтр **встроенным gojq**, а не бинарём `jq`. Проверка такого
фильтра локальным `jq` судит не тот код: формулировки ошибок разные, и класс, зеленеющий мимо
дефекта, здесь реален.

Второе, что даёт `--jq`, хуже первого: **отказ сети и отказ фильтра возвращаются одним кодом 1**.
Идиома `X="$(gh api … --jq '…')" || X='?'` поэтому печатает СВОЙ дефект как «GitHub API отказал» —
см. [[gh-jq-failure-masquerades-as-api-refusal]].

**Как чинить оба разом:** `gh api … > ответ.json`, затем отдельной командой `jq -r '<фильтр>' --
ответ.json`. Движок в бою и в тесте один, и каждая сторона отказывает своим именем. `jq` на
`ubuntu-latest` предустановлен.

Полевой случай: `.github/workflows/notifier-watch.yml`, ветвь счёта заглушённых отказов
(тред `119-mute-count-blames-github`, 2026-09-03). Фильтр `[...] | index(.conclusion)` брал
`.conclusion` у массива-литерала — тип-ошибка ПРИ ЛЮБЫХ данных, ветвь не могла дать число никогда,
а письмо винило GitHub.
