Всё, что дифф говорит о БАЗЕ, привязано к конкретной базе. Сменил базу — перемерь:
числа проверок («было N на базе `SHA`»), утверждения вида «на чистом `main` это красно»,
ссылки «разъезд чинится тредом NNN». Молчаливо пережившее перебазировку утверждение — это
ровно тот класс дефекта, который ревьюер ловит как «реассертированная фраза не держится
прогоном», только теперь она не держится в ОБРАТНУЮ сторону.

**Why:** 2026-09-04, тред `125`, #272. Круг 1 нашёл, что фраза доки «Приёмка — состояния
(14)/(15)» ложна: сюита была красна на `main` из-за чужого #265. Починил оговоркой: «на двери
`main` красно 8 из 15, чинится тредом `127`». Через час смотритель объявил `CONFLICTING` —
приземлился #274, и он ЕСТЬ починка из `127`. После перебазировки на неё оговорка стала ложной
второй раз: замер дал 15/15 и на ветке, и на чистом `main`. Заодно уехали числа сюиты
(база 68 → 73, голова 91 → 96) — «91 (было 68)» после смены базы это в точности та находка
круга 1, из-за которой правка и делалась ([[test-counts-must-be-remeasured]]).

**How to apply:** после `rebase` пройти по своему диффу и телу PR грепом по именам SHA базы,
по словам «на `main`», «красн», «чинится», «было N» — и каждое перемерить. Дом починки,
который приземлился, из ссылки «где чинится» превращается в ссылку «чем починено».
Заодно это момент, когда косметику, отложенную «из-за цены круга», берут попутно: голова
всё равно едет ([[green-letter-does-not-mean-still-mergeable]] — про то, что перебазировка
вообще понадобится).
