Стык рождается и БЕЗ всякого действия автора. 2026-09-06: #278 (тред 122) лёг в 08:43:42Z и сменил
`.github/scripts/review-delivery.sh`; #277 (тред 128) лёг через 15 секунд, 08:43:57Z, и добавил в
`checks.yml` ШАГ, который гоняет `review-delivery.integration.sh` — то есть исполняет как раз этот
скрипт. Зелёный прогон #277 мерил `review-delivery.sh` блобом `f61e8d6c` от базы `06bf1c41`; в
`main` его шаг встал против блоба `6da63f3c`. **Пару не мерил ни один из двух зелёных прогонов** —
ни моя ветка (шага тогда не было), ни их (моего скрипта тогда не было).

**Why:** ни перебазировки, ни конфликта, ни общей строки здесь нет — общий предмет один: ЧУЖОЙ
НОВЫЙ ШАГ И МОЙ ФАЙЛ. Поэтому [[clean-rebase-can-still-create-a-seam]] этот случай не ловит: там
стык ищут после своего действия, а тут не двигался никто. И первый замер пары — push-прогон на
`main`, а он зелёным письма не рождает ([[green-push-run-on-main-writes-no-letter]]): пройдёт —
никто не узнает, что было чем рисковано; упадёт — звонок уедет в стоячий адрес красноты, а не в
твой тред, и разбирать будет другая сессия по другому поводу.

Механизм, из-за которого зелень мерит НЕ ту пару, назван точно: `checks.yml` висит на
`pull_request`, а `actions/checkout@v4` в нём стои́т без `ref:` — значит зачтённый прогон судит
`refs/pull/N/merge`, то есть голову ⊕ базу НА МОМЕНТ СТАРТА. Два своих открытых PR одного треда с
разными базами (2026-09-06, #290 и #292 треда 140) поэтому не мерены в паре ни разу: #292 позеленел
в 10:58Z на базе `7396c759`, а #290 лёг в `main` в 11:02Z. Замер пары своей рукой — четыре минуты:
`git merge-tree --write-tree origin/main <голова>` → `commit-tree` → `git checkout --detach` В СВОЁМ
воркtree (не в `/tmp`: [[green-depends-on-where-the-checkout-lives]]) → сюита; и отдельно сюита на
чистом `origin/main`, чтобы дельта была ПРИПИСЫВАЕМА, а не объяснена на глаз. Вышло 3658 → 3662,
ровно четыре теста PR, ни одного покрасневшего.

**Нота `pr mergeable` про инертный сдвиг базы пару НЕ меряет — и это легко прочитать наоборот.**
2026-09-06, тред 150, #308: `pr mergeable --pr 308` сказал «the base moved OUTSIDE the paths of this
pull request: 5 path(s) moved, none of them among the 1 this PR changes — the shift is inert BY THIS
MEASUREMENT», и той же нотой гарда 2 вердикт ревьюера оставил сдвиг на кнопку curator. Мерка там —
ПЕРЕСЕЧЕНИЕ ПУТЕЙ, и для процессного теста она слепа: мой единственный путь —
`daemon.process.test.ts`, а он через `spawnSync` гоняет НАСТОЯЩИЙ CLI и утверждает на его выводе,
тогда как чужой #301 правил `cli.ts`. Общая переменная — не путь, а бинарь, который тест зовёт.
Замер занял 4 минуты по рецепту ниже: дерево слияния `merge-tree --write-tree` → детач-чекаут в
своём воркtree → `TMPDIR=/tmp npx vitest run --root packages/agent-protocol <файл>` → 15/15, и
рабочее место возвращено на базу. Признак случая: **дифф — процессный тест, а чужой сосед трогает
`cli.ts` или то, что CLI грузит при старте.** Тогда «пути не пересеклись» доказывает только
отсутствие конфликта слияния.

**Нота `pair` самого `merge-gate` меряет ИМЯ ПУТИ, а не вызов — и даёт ложные срабатывания.**
2026-09-07, тред 063, #322: гард 2 зелён, но рядом две ноты — «the base moved AFTER the credited
checks started» и «NOBODY MEASURED THIS PAIR: `.github/scripts/review-delivery.sh` и
`.github/workflows/checks.yml` (обе правит ЭТОТ PR) называют `docs/protocol-reference.md` (лёг в
базе) по пути». Замер формы упоминания: оба вхождения — **комментарий** (`checks.yml:96`) и **тело
`printf`** (`review-delivery.sh:712`), ни одного чтения и ни одной ассерты. Гард честно это
оговаривает («what is caught is a LITERAL path name inside a workflow or a shell file»), но читается
нота как найденный стык — класс [[name-grep-counts-comments-as-callers]].

**Why:** ноты не отказ («this is NOT a refusal»), и обе сводятся к ОДНОМУ факту — база уехала после
зелёного. Настоящий стык там был другой и путями не ловился: чужой #324 добавил НОВУЮ строку
`err()` в stderr демона, а мой дифф добавлял тесты кадра демона — класс
[[existence-assert-is-a-proxy-for-nothing-announced]]. Спас `toContain` вместо равенства, но узнать
это можно было только прогоном.

**How to apply (замер пары, когда `node_modules` в дереве нет):** `git worktree add --detach /tmp/X
origin/main` → `git merge <голова>` → симлинки `node_modules` корня и обоих пакетов из своего
воркtree → `TMPDIR=/tmp vitest run --root .`. **Число тестов предсказывать ДО прогона**
([[predicted-test-count-proves-a-rebase]]): зелень головы + добавленные соседом `it(`/`test(` из
`git diff <их>^ <их> -- '*.test.ts'`. Сошлось точно: 3835 + 13 = **3848**, 228 файлов, зелено.

**How to apply:** после посадки своего PR прочитать, что легло РЯДОМ (`git log --oneline` вокруг
своего сквоша). Чужой новый шаг CI, гоняющий твой файл, — повод прогнать пару своей рукой на голове
`main` в СВОЁМ такте, а не ждать цвета: у меня это 15 состояний интеграционной сюиты + 141 проверка
юнитов, обе зелены, минуты две. Дешёвая проверка тождества, которая называет цену точно:
`git rev-parse <их-голова>:<мой файл>` против `git rev-parse <main>:<мой файл>` — разошлись блобы,
значит их зелень про твой файл не говорит ничего.
