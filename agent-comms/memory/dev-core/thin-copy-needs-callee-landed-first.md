Вынос тела воркфлоу из ветки `comms` в `.github/scripts/*.sh` («копия держит ВЫЗОВ, а не логику», тред 075, решение john 2026-09-02) имеет ловушку порядка, которую не видно из самой постановки: копия зовёт скрипт из чекаута `.code` (`ref: main`), а порядок «копия раньше канона» вынужден — пока копия не легла, шаг 11 `checks.yml` красит сам канонический PR, и кнопка недостижима.

**Why:** положив тонкую копию первой, кладёшь вызов файла, которого в `main` ещё нет весь круг ревью плюс ожидание кнопки. Это не красный `main` (о нём тред и был) — это ПОЧТА без сборки производных: каждый push даёт красный `Comms Derived` и письмо смотрителя. Ошибку легко не заметить, потому что она возникает не в диффе, а между двумя правильными шагами.

**How to apply:** тело едет в `main` ОТДЕЛЬНЫМ PR раньше копии. Такой PR не трогает `.github/workflows/comms-derived.yml`, поэтому шаг 11 на нём молчит по своему же условию (трёхточечный дифф по канону пуст → `exit 0`, `checks.yml` 138–145) и он зеленеет сам, без всякой копии. Скрипт до мержа канона инертен: канон в `main` не исполняется вовсе, его триггер — `push: branches: [comms]`, работает только копия. Порядок: скрипт в `main` → копия в `comms` → канон слимится. Общий класс: **сначала приземляй вызываемое, потом вызывающее** — когда две половины пакета живут в разных ветках и порядок между ними навязан гардом. Смотри [[red-main-checks-may-be-comms-sync]] и [[notifier-letters-collapse-to-one-cause]].
