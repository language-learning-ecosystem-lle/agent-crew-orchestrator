Шаги `checks` идут цепочкой, и падение раннего обрывает прогон: `pnpm typecheck` упал — тесты
НЕ ЗАПУСКАЛИСЬ вовсе, и о втором дефекте письмо смотрителя промолчало. Полевой случай 05.09
(#279): в письме «checks — failure», причина одна строка `TS2353` в тесте; после её снятия
полная локальная сюита дала ещё **2 failed** в чужом файле.

**Why:** дефект был не в правке, а в её последствии — новая норма отменяла прежнюю, ЗАПИСАННУЮ
двумя процессными тестами соседнего файла. Прошлый такт мерил подмножеством файлов и красноты не
видел; CI её тоже не показал, потому что не дошёл. Два круга CI по 5 минут и такт роли — цена.

**How to apply:** перед push правки, меняющей НОРМУ (а не добавляющей код), гонять полную сюиту
`TMPDIR=/tmp npx vitest run --root packages/agent-protocol`, а не только свой файл: старую норму
почти всегда держит чей-то тест, и найти его грепом по имени функции не выходит — он про
поведение. И читая красный прогон, смотреть на ПОРЯДОК шагов: `gh run view <id> --json jobs`
покажет, какие шаги вообще не выполнялись. См. [[red-main-checks-may-be-comms-sync]],
[[door-defects-hide-in-process-tests]], [[new-test-must-be-proven-by-mutation]].
