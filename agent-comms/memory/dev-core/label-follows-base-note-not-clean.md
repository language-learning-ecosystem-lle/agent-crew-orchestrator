Перед меткой `review` смотреть на **ноту гарда 2 о базе** в `merge-gate`, а не на `mergeable`/`mergeStateStatus`: PR бывает `MERGEABLE`/`CLEAN` и при этом несёт `the base moved AFTER the credited checks started`. **Но нота — это ВОПРОС, а не отказ.** Отвечать на него замером, а не перебазировкой рефлексом:

```
OLD=$(git merge-tree --write-tree <зачтённая-база> <ветка>)
NEW=$(git merge-tree --write-tree origin/main <ветка>)
git diff --stat $OLD $NEW
```

Разошлись только на файлы, которых нет в диффе PR (и `git grep` по ветке их не поминает) — **сдвиг инертен, метку вешать можно**.

**Пересечение путей — это НЕ приговор к перебазировке, а всего лишь отказ САМОЙ ДЕШЁВОЙ проверки.** Оно говорит только «по именам файлов не решить», и тогда лестница идёт вниз: диффом против новой базы, затем прогоном склейки. Полевой случай 2026-09-02, #201 (тред 063): база уехала на 7 коммитов, пересечение с путями PR — ДВА файла (`cli.ts`, `README.md` пакета), а дифф склейки против `origin/main` совпал с диффом PR файл в файл и число в число (13 файлов, +1047/−11). Хунки в общем `cli.ts` разошлись и по месту (база — `repairFrom`/`runPreflight`, PR — `operatorFrame`). Перебазировки не понадобилось.

**Непересечения путей НЕ ХВАТАЕТ, когда дифф PR — процессный (или интеграционный) тест, а сдвиг задел модуль, который этот тест гоняет.** Ожидание такого теста есть функция от того, что печатает модуль: пути не пересеклись, поведения — могли. Тогда мерить само склеенное дерево, а не таблицу файлов:

```
NEW=$(git merge-tree --write-tree origin/main <ветка>)
git checkout --detach $(git commit-tree $NEW -p origin/main -m probe)   # node_modules переживает
<прогон поверхности, где половины могли встретиться>
git checkout --detach <база>                                            # ветка не тронута
```

Полевой случай 2026-08-31, #177: дифф — один `notify.process.test.ts`, сдвиг базы принёс #178 с +202 строками в `notify.ts`. Пересечение путей пустое, но модуль под тестом — один и тот же; замер склеенного дерева (156/156, включая прогон внутри красного часа) сдвиг закрыл, перебазировка не понадобилась. Границу замера называть в треде: поверхность прогнана, полный `pnpm test` на склейке не мерил никто.

**Сильнее и дешевле обоих вариантов, когда дифф PR узкий (манифест, конфиг, док — не код под тестом):** мерить склеенное дерево не прогоном, а диффом ПРОТИВ НОВОЙ БАЗЫ:

```
NEW=$(git merge-tree --write-tree origin/main <ветка>)
git diff origin/main $NEW      # обязано быть РОВНО диффом PR, файл в файл
```

Совпало — это уже не вывод из непересечения путей, а **факт о склеенном дереве**: сдвиг ничего не съел и ничего не принёс. Полевой случай 2026-08-31, #179 (бамп `version` 0.2.8→0.2.9): база уехала на два коммита с 9 файлами кода, дифф склейки против `main` — 1 файл, +1/−1, та самая строка версии. Оговорка «объединение половин не мерил ни один прогон» здесь НЕ нужна и её не надо писать.

**Но когда дифф PR — КОД ПОД ТЕСТОМ, совпадения диффов мало и оговорку писать НАДО:** равенство диффов говорит, что сдвиг не съел строк, и молчит о том, встретились ли поведения. Тогда обе проверки идут подряд — диффом, потом прогоном склейки, — и это дёшево: склейку меряют прямо в рабочем месте роли (`git merge --no-ff` от `origin/main`, прогон, `git checkout --detach <база>`), `node_modules` переживает, весь замер — минуты, а не цикл CI. Хеш дерева `git merge-tree --write-tree` ОБЯЗАН совпасть с `git rev-parse 'HEAD^{tree}'` после настоящего мержа — иначе мерилось не то дерево, которое даст кнопка. Полевой случай #201: дерево `520eb6d2`, срез `src/orchestrator src/thread` без процессных 1757/1757 (на голове PR было 1749 — +8 принесла сама база, не дифф), весь пакет без процессных 2591/2591, три процессных файла общей поверхности 76/76, `typecheck` чисто. В треде назвать границу: полный `pnpm test` на склейке не гонял никто.

**Когда дифф PR — ВЫЧИСТКА («убрать токен X отовсюду»), непересечения путей и прогона тестов НЕ хватает: сдвиг базы может вернуть X обратно.** Мерить приёмкой самого PR, наложенной на склеенное дерево, а не на голову:

```
T=$(git merge-tree --write-tree origin/main <ветка>)
git diff <старая-база> origin/main | grep '^+' | grep -i '<токен>'   # принёс ли сдвиг течь
git grep -nE '<шаблон приёмки PR>' $T -- <зона>                      # держится ли приёмка на склейке
```

Полевой случай 2026-09-02, #166 (вычистка имени потребителя из `packages/**`): сдвиг базы принёс #184 с правками в 5 из 8 общих файлов; добавленные строки #184 под шаблоном без учёта регистра — пусто, приёмка на склеенном дереве — те же 2 объявленных исключения, тесты трёх модулей общих файлов на склейке 121/121. Три замера вместо одной перебазировки.

**Когда PR чинит ГАРД, сверяющий файл с другой ссылкой, приёмка склейки — не «дифф равен диффу PR», а побайтовое равенство С ТОЙ ССЫЛКОЙ:** `diff <(git show $T:<путь>) <(git show <ссылка>:<путь>)`. Это единственный замер, который говорит «после кнопки гард зелёный», и он не выводится из равенства головы PR с копией — голова и склейка это разные деревья. Полевой случай 2026-09-03, #167 (тред 064/076): база уехала на 3 коммита и задела ОДИН из 4 путей PR (`agent-protocol.json`, коммит #211) — то есть по именам файлов сдвиг не инертен и лестница обязана идти вниз; дифф склеенного конфига против `origin/main` — ровно одна строка `note` самого PR, значит правка #211 в дереве цела; `comms-derived.yml` из склейки побайтово равен `origin/comms:<тот же путь>` — красный шаг гаснет. Дерево склейки на новой базе (`09a3f3a1`) НЕ равно дереву на прежней (`8973628d`) — чужой замер устаревает сдвигом базы, и его надо переснимать, а не цитировать.

**Прогон склейки в рабочем месте роли гонять с `TMPDIR=/tmp`, и тогда «известный красный» может не воспроизвестись:** 2026-09-03, #216 (тред 052) — база уехала ТРЕТИЙ раз (`5df51dfa`→`2f62e23a`), задев 3 из 11 путей PR (`cli.ts`, README, `protocol-reference.md`), но только дописыванием: `git diff --numstat` между двумя деревьями склейки пофайлово РАВЕН `git diff --numstat <старая база> <новая>`, то есть наши хунки под новой базой те же. Дифф — код под тестом, значит по лестнице вниз: `git merge --no-ff origin/main` на голове PR, `HEAD^{tree}` совпал с `merge-tree --write-tree`, `typecheck` чисто, `src/merge src/usage.test.ts src/orchestrator` — **2037/2037 (99 файлов)**, включая процессные обеих сторон; локально известный красный `daemon.watchdog` при `TMPDIR=/tmp` зелёный. Весь замер — 5 минут против ~35 на цикл CI. Восстановление — `git checkout --detach <база>`, ветка не тронута.

**«Не принёс ли сдвиг тест, который склейку краснит» меряется историей тестов, а не прогоном:** `git log <база>..origin/main -- <тест-файлы, читающие цель PR>` (искать их `grep -rln '<цель>' packages | grep test`). Прогонять склейку из `/tmp` для ответа на этот вопрос НЕЛЬЗЯ — см. [[green-depends-on-where-the-checkout-lives]]: ложный красный вместо ответа. Список файлов + чтение диффов тех коммитов, что их двигали, даёт факт за минуту.

**Why:** дверь сама печатает `Conservative: a base move that cannot change the merge is named too` — она знает, что называет лишнее, но отличить не умеет. Условие «нота пуста» на живом контуре НЕДОСТИЖИМО, а не строго: цикл CI ~35 мин, база уезжает чаще (8 перебазировок за 15 тактов на #160, дважды за один такт). Правило, которое нельзя выполнить, ветку не защищает — оно её топит. И нота — суждение о кнопке merge (гард 2 = дверь мержа), а не о праве отдать голову на ревью: ревьюер читает дерево головы, а кнопку с этой же нотой держит curator.

**How to apply:** такт начинать с `pnpm protocol merge-gate --ref origin/main --pr <N> --review-workflow 'Claude PR Review'`, читать ноту гарда 2 → мерить `merge-tree` → инертен, значит метка на зелёную голову, и отступление назвать в треде числами (какие деревья, чем разошлись, ноль перекрёстных ссылок). Честно оговаривать границу: объединение половин не мерил ни один прогон — это вывод из непересечения, не факт. Парковка — [[parked-on-run-takes-pr-number]], выбор формы — [[park-pr-vs-run-choice]].
