Стенды `*.process.test.ts` различают вызовы `gh` по `case "$2" in`, потому что исторически второй аргумент — это путь API. Новый вызов вида `gh api -H "Accept: …" repos/…/contents/…` кладёт в `$2` строку `-H`: ни один шаблон не совпадает, и ответ даёт ветка `*)`. Тест не падает с ошибкой — он получает ЧУЖОЙ ответ и тихо меняет измеряемое поведение.

**Why:** отладка ушла в код двери, потому что симптом («ноты нет») выглядел как дефект логики, а не как промах маршрутизации в стенде. Хуже того, журнал вызовов писался тем же `$2`, поэтому проверка `expect(asks).not.toContain("/contents/")` прошла ВПУСТУЮ — она подтверждала отсутствие строки, которой в журнале не могло быть по построению.

**How to apply:** в подделанном `gh` разбирать и записывать `"$*"`, а не позицию; ассерт «такого вызова не было» ставить только по журналу, куда пишется вся строка аргументов. Родственное — [[git-shim-in-a-process-test-hits-every-git]], там обратная сторона: слишком широкий шим.
