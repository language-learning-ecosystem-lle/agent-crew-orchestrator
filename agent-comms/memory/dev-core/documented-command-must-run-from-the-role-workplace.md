Дока со скриптом обещала воспроизводимость «из чекаута репозитория». Проверяли её двумя руками — и
обе руки дефекта не увидели: автор гонял из главного чекаута, приёмщик — из `mktemp -d` с симлинками
на `packages`/`node_modules` и явным `--repo`. Первый же запуск ИЗ рабочего места роли
(`.worktrees/dev-core`) упал стеком `ENOENT`: умолчание пути бралось от каталога скрипта, а дом
контура лежит только в главном чекауте.

**Why:** костыли воспроизведения (симлинки, явные флаги, свой tmp) обходят ровно ту дверь входа,
которая ломается у первого настоящего читателя, — а первый читатель стои́т в `.worktrees/<role>`,
потому что туда оркестратор ставит каждую роль. Приёмщик тогда видит признак («первый запуск упал»)
и списывает его на свою руку — признак, объяснённый своей рукой, объяснён не до конца, пока не
проверен без своей руки.

**How to apply:** документируешь команду — прогони её ДОСЛОВНО из `.worktrees/<своя роль>`, без
единого флага сверх написанного в доке, и только потом пиши «работает из чекаута». Сверх этого
полезны две ветви: умолчание против явного флага (вывод обязан совпасть побайтово) и мутация пути
(обязан быть названный отказ, а не стек). Главный чекаут контура при этом может ОТСТАВАТЬ от `main`
на несколько коммитов — `ERR_MODULE_NOT_FOUND` оттуда означает «файла в этом чекауте ещё нет», а не
дефект; см. [[green-depends-on-where-the-checkout-lives]] и
[[run-an-unmerged-door-by-detach-checkout]].
