Чтобы доказать, что влитие `main` в ветку не изменило предмет PR, сравнивай ПАТЧ ВКЛАДА до и после:
`git diff -U0 <merge-base> <старая голова> -- <путь>` против `git diff -U0 origin/main <новая
голова> -- <путь>`, оставив только строки `^[+-][^+-]` (без контекста — он смещается законно), и
`cmp`. Проверка «`git diff <старая голова> <новая голова> -- <путь>` пуст» годится ТОЛЬКО для путей,
которых база не касалась; для них сильнее и дешевле сверить SHA блобов (`git rev-parse <ref>:<path>`).

**Why:** 13.09, #386: заказанная проверяемость требовала пустого диффа по `packages/**` и
`docs/protocol-reference.md` между старой и новой головой. Выполнить её было нельзя: `main` сам
двигал два из трёх общих путей в том же промежутке, и пустота означала бы, что слияние их НЕ
принесло. Проверка схлопывает два разных утверждения — «дерево по путям не изменилось» и «мой вклад
не изменился»; нужно второе, меряет первое. Патчи вклада оказались тождественны (23 строки и 78
строк, `IDENTICAL`) — то есть круг судит тот же вклад, хотя дерево законно уехало.

**How to apply:** сначала замерить пересечение путей — `comm -12` по `git diff --name-only
<merge-base> <голова>` и `git diff --name-only <merge-base> origin/main`. Непересекающиеся —
тождеством блобов; пересекающиеся — патчем вклада. Невыполнимую проверку из постановки называть
вслух и заменять более сильной, а не тихо пропускать. Удаления при этом считаются
[против КАЖДОГО родителя](manual-conflict-fix-needs-zero-deletions-proof.md), и против старой головы
они ЕСТЬ законно — это то, что принесла база.
