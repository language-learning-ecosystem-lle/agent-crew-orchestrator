Дверь почвы контура (`roles/contour.ts`, тред 062) судит дерево, в котором СТОИТ РАННЕР.
Любой процессный тест, поднимающий CLI без `env: sandbox(configHomeInside(repo))`, отказывает
кодом 2 (`belongs to no contour of this box`) из чекаута вне объявленного контура — то есть из
`git worktree` в `/tmp`, которым все меряют деревья слияния.

**Why:** 2026-09-02, тред 064: дерево мёржа #166 два такта считали красным. Замер 2×2 — тот же
коммит `a945e56f` даёт 91/91 из чекаута контура и 89/91 из `/tmp`. Переменная была почва, не
дифф. CI этого не видит: раннер не объявляет инстансов, дверь читает пустой список как `unknown`
и пропускает (сознательный fail-open).

**How to apply:** «зелено» — это команда раннера ВМЕСТЕ с деревом и МЕСТОМ чекаута, а не число;
называть в докладе всё три. Дерево слияния мерить в чекауте контура, не в `mktemp -d`. Расходится
твой зелёный с чужим красным на одном хеше дерева — сравнивать сначала почву. Отличать от
[[contour-ground-check-needs-tmp]]: там `/tmp` НУЖЕН, потому что мерится сама дверь.

**Рецепт (2026-09-02, тред 071):** мерить дерево слияния прямо в рабочем месте роли, не заводя
чекаута: `git checkout --detach origin/main` + `git merge --no-ff <origin/ветка PR>`, прогон,
затем `git checkout --detach <исходная база>` — ветка не двигается (пуша нет), значит `approve`
на её голове цел, а рабочее место остаётся чистым к концу хода. Сюиту гнать `pnpm -r test`
(корень своего `vitest.config.ts` не имеет — `vitest run` из корня возьмёт оба пакета мимо их
конфигов). Хеш дерева (`git rev-parse 'HEAD^{tree}'`) называть в докладе: коммит слияния у каждого
свой, дерево — одно.
