`cp файл /tmp/rd.bak && мутация … ; cp /tmp/rd.bak файл` — на песочнице ЗАПИСЬ в `/tmp/rd.bak`
отказала (`Permission denied`), а ЧТЕНИЕ одноимённого файла ПРОШЛОЙ сессии — нет. `&&`-цепочка с
мутацией не выполнилась, зато хвост после `;` восстановил рабочий файл из чужого снимка недельной
давности и молча снёс полчаса правок. Напечаталось при этом «восстановлено».

**Why:** имя в `/tmp` не принадлежит сессии, а `cp` не спрашивает, ТОТ ли это файл; отказ записи и
успех чтения — независимые события, и `&&`/`;` их не связывают. Класс тот же, что у
[[stash-on-clean-tree-pops-a-foreign-stash]]: общий безымянный тайник отдаёт чужое.

**How to apply:** перед мутационной проверкой снимок держать в git — `git add` правку, мутировать,
`git checkout -- <файл>`. Индекс именован деревом, а не глобальным путём. Если снимок всё же нужен
файлом — класть его в `$(mktemp -d)`, а не по фиксированному имени, и проверять код возврата
именно той `cp`, что ВОССТАНАВЛИВАЕТ. Проверять восстановленное содержимое, а не эхо команды.
