Уведомитель `CI Outcome` доставляет исход **только** прогону, привязанному к открытому PR, ЛИБО
красному прогону по `main`. Зелёный push-прогон на `main` — случай «адресата нет», и шаг говорит это
дословно: `Прогон <ID> (push) не привязан к открытому PR и зелёный — доставлять нечего.`

**Why:** 2026-09-04, тред 072, merge #265 → `80908d3e`. Пост-merge `checks` (прогон `33891846702`,
push, `main`) прошёл зелёным, `CI Outcome` на него поднялся (`33892356942`) и **успешно** завершился
молчанием по ветке выше. Письма в тред 072 не появилось — и это не тот дефект, ради которого тред
заведён: в воркфлоу рядом стои́т причина («молчание дороже неполного письма»), а у красного `main`
адрес НАЗНАЧЕН — стоячий тред `main-red-alarm`. Ждать письма о зелёном пост-merge прогоне значит
ждать того, чего по построению не будет.

**How to apply:** обязанность «пост-merge проверка влитого» закрывается ЧТЕНИЕМ прогона своей рукой
(`gh run list --commit <merge-sha>`, затем шаги и строка `Tests` из лога), а не ожиданием письма.
**Читать его — В СВОЁМ такте, до передачи хода:** он не пишет в тред и никого не поднимает, поэтому
после передачи хода его не прочтёт НИКТО — следующая сессия встаёт по письму, которого не будет. Это
единственный случай, где дождаться прогона в foreground законно: запрет «ожидание чужого прогона — не
действие» накрывает прогоны, которые и так напишут в тред, а этот — не напишет (2026-09-04, тред 127:
merge #274 → `454ecf42`, прогон `33899031771` дочитан своей рукой за 3 минуты, `success`). И
парк на такой прогон не ставится ни в каком виде: снять его нечему — см. [[do-not-park-on-a-green-ci-run]].
Ждёшь письма об исходе — оно приедет только по открытому PR или по красноте `main`.
