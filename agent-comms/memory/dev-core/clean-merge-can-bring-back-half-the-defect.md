Перед коммитом слияния `main` в свою ветку греп по ПРЕДИКАТУ/посылке, которую PR правит, — по
ВСЕМУ файлу, а не по конфликтным хункам: чужой PR мог добавить второго потребителя той же выдачи,
и авто-слияние оставит его судить по-старому.

**Why:** 15.09 в #443 (тред 209) конфликт шёл по трём файлам, а опасное лежало ВНЕ конфликта:
влитый #419 добавил `notifier_mute_ambiguous` — вторую перепись той же выдачи, — и она судила
`.created_at`, ровно то, что PR чинил. Обе печатаются в ОДНУ строку письма: число и причину, по
которой оно объявлено нижней границей. Разъехавшись мгновением отбора, они врут СОГЛАСОВАННО —
письмо называет число точным, хотя один отказ ни засчитан, ни отвергнут. Нашлось это только
потому, что #419 сделал 4-й аргумент обязательным и три сверки упали кодом 2; **если бы подпись
не менялась, тесты остались бы зелёными**.

**How to apply:** красное от чужой смены подписи — приглашение перечитать вторую копию правила, а
не механически добить аргумент. Мутацию в файле с ДВУМЯ дословно совпадающими предикатами ставить
`sed` по НОМЕРУ СТРОКИ (общая замена сломает оба и покрасит чужие сверки — доказательства это не
даёт). И не гонять мутацию через `perl -0pi -e "…$1…"` в ДВОЙНЫХ кавычках bash: `$1` съедает
оболочка, захваченная группа исчезает, получается сломанный `jq` вместо мутации.
