Шим `git` на `PATH` процессного теста ловит **ВСЕ** вызовы гита внутри прогона, а не только тот,
который хотел уронить. `case " $* " in *" commit "*)` уронил заодно коммит **почтового чекаута** —
и тест, писавшийся про «уборка не прошла», молча стал мерить «доставка не прошла»: журнал сказал
`'new-message' exited 2 — fatal: the index is broken`, то есть чужую ветку кода.

**Why:** прогон запускает подпроцессы (доставку письма, свой же CLI), и они наследуют `PATH`.
Отказ по имени подкоманды — слишком широкий предикат: `commit` делает и уборка, и почта.

**How to apply:** сужать шим по **уникальному куску argv того самого вызова**, а не по имени
подкоманды — здесь `" -m wip("` (тему пишет только уборка). И если два класса отказа живут в
одном файле, проверять, что каждый роняет ТОЛЬКО свой: мутация [[new-test-must-be-proven-by-mutation]]
показывает это сразу — пересечение видно как «упало два теста вместо одного».

Смежное: в стенде процессного теста дверь почты проверяет участников по конфигу, поэтому
**отсутствие роли в конфиге стенда — самый дешёвый способ уронить ИМЕННО доставку**, не трогая
ничего другого. См. [[door-defects-hide-in-process-tests]].
