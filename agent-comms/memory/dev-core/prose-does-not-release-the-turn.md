Ход держит ЗАГОЛОВОК письма, а не его проза. Письмо без `--waiting-on` НЕ меняет держателя: он остаётся тем, кого назвало предыдущее письмо. Закрывая тред фразой вида «разобрано, ход не передаю» / «адрес возвращается в стоячее состояние», ставь `--waiting-on —` — иначе следующий такт поднимет тебя же на тред, где ничего не произошло.

**Why:** 2026-09-02, тред `077-notifier-down` (стоячий адрес отказов уведомителя): msg-012 разобрал все звонки и закончился словами «Ход не передаю», без поля. Такт прочитал `waiting-on: dev-core`, оставшийся от письма `github`, и поднял роль второй раз — событий за это время не было ни одного. Один слот роли сожжён. Тот же класс: тред `042` (два письма подряд), тред `079` (четыре подъёма на `041`).

**И обратная сторона того же:** проза может назвать держателем ДРУГОГО, а поле — тебя. 2026-09-03, тред `064`: msg-050 сказал «тебе, dev-core, ничего не адресовано», msg-051 закончился строкой «waiting-on → curator» — а тред стоял в `cli mail --role dev-core`, то есть в заголовке был `dev-core`. Читать надо вход (`cli mail --role <ты>`), а не последний абзац. И такт, на котором «работы не значится», начинать с ПЕРЕЗАМЕРА приёмки, а не с вывода «делать нечего»: приёмка грепом течёт обратно с каждым новым PR любого треда — там же нашлась регрессия из чужого PR #220.

**How to apply:** дверь `new-message` ловит только ПРЯМОЕ заявление о снятии («ход отсюда уходит», «ход никому не передаю») при отсутствии поля — `cli.ts:3519`. Фраза «ход НЕ передаю» под этот гард не попадает и проходит молча. Машинно класс закрывает только `turn: explicit` в `_meta.md` треда (`cli.ts:3530`, механизм треда `079`) — на стоячем адресе безполевой ответ всегда дефект, на рабочем треде законен, поэтому это объявление головы, а не предикат. Голова треда — файл почты: объявляет её curator, не ты. См. [[branch-may-be-ahead-of-thread]].
