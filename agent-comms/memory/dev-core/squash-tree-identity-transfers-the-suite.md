После merge своего PR приземление доказывается не «конфликта не было», а равенством деревьев:

```
git rev-parse <squash-sha>^{tree}
git merge-tree --write-tree <база на момент кнопки> <голова PR>
```

Совпали — в `main` лежат ТЕ ЖЕ БАЙТЫ, по которым уже гнали полную сюиту перед меткой, и её
зелень переносится тождеством, а не доводом. Не совпали — squash что-то решил иначе, и это
надо мерить диффом, а не объяснять.

**Зачем:** когда база уезжала под головой ЧЕРЕЗ пути, которые PR тоже трогает, класс «разрешение
съело чужой раздел» ловится только сравнением деревьев (см. [[commutative-merge-is-not-proof-nothing-was-eaten]],
[[manual-conflict-fix-needs-zero-deletions-proof]]).

**Как применять:** дерево слитого варианта материализовать и прогнать сюиту ДО метки, сохранив
sha дерева в письме; после merge сверить один `rev-parse`. Перепрогон полной сюиты на `main`
тогда не нужен — довольно точечного прогона своих файлов, чтобы число было перемерено, а не
перенесено ([[test-counts-must-be-remeasured]]).
