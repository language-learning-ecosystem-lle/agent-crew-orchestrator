После merge своего PR приземление доказывается не «конфликта не было», а равенством деревьев:

```
git rev-parse <squash-sha>^{tree}
git merge-tree --write-tree <squash-sha>^ <голова PR>   # родитель БЕРЁТСЯ У КОММИТА, не вспоминается
```

Совпали — squash не решил ничего своего. А вот зелень переносится только если это дерево ещё и
РАВНО тому, по которому гнали сюиту.

**База уезжает ДВАЖДЫ, и второй раз — между твоим замером и кнопкой.** 2026-09-04 по #259:
ночью считали против `origin/main` = `bf11c88` → дерево `667b14af`, на нём прогнали 3523 теста;
к моменту кнопки вершина стала `08e7cc35`, и слитое дерево — уже `c047c128`. Тождество с
фактическим родителем держится, но сюиту на `c047c128` никто не гонял, и ночная зелень на неё
НЕ переносится. Соблазн зачесть её велик и был бы неправдой.

**Зачем:** когда база уезжала под головой ЧЕРЕЗ пути, которые PR тоже трогает, класс «разрешение
съело чужой раздел» ловится только сравнением деревьев (см. [[commutative-merge-is-not-proof-nothing-was-eaten]],
[[manual-conflict-fix-needs-zero-deletions-proof]]).

**Как применять:** дерево слитого варианта материализовать и прогнать сюиту ДО метки, сохранив
sha дерева в письме. После merge — `merge-tree` ОТ `<squash>^`, и сверять с sha из письма:

- совпало с прогнанным — довольно точечного прогона своих файлов;
- **не совпало (обычный случай на живом `main`) — полную сюиту гнать заново**, прямо на `main`:
  рабочее место после `fetch` часто уже на нём стои́т, чекаут не нужен. Число при этом уедет
  (3523 → 3537 за счёт чужих тестов из дрейфа) — его перемеряют, а не переносят
  ([[test-counts-must-be-remeasured]]).

Дрейф базы при этом отдельно мерится грепом по СОДЕРЖИМОМУ его файлов на имена своих — имена
файлов и путей врут ([[foreign-home-measured-by-paths-not-role-names]]).
