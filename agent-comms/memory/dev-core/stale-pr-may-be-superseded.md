Перед перебазировкой PR, пролежавшего сутки и больше, сначала спросить `git log --oneline
origin/main -- <файл>` по КАЖДОМУ файлу диффа. **Конфликт `add/add` на файле, который PR
создаёт, означает не расхождение правок, а что файл уже существует в `main`** — предмет
закрыт параллельным пакетом, и перебазировать нечего.

**Почему:** треды разных контуров нумеруются независимо, один предмет может идти двумя
PR сразу, и выигрывает тот, что сел первым. Полевой случай 2026-09-02: #158 «форма D»
перебазировали трое суток спустя — вся его логика уже была в `main` (#159, #166, #194),
и версия `main` оказалась сильнее по механизму.

**Как применять:** измерить остаток (функция за функцией: что из ветки НЕ покрыто main),
и если остатка нет — искать долг вокруг севшего пакета. Чаще всего это
`docs/protocol-reference.md`: код садится с доковыми блоками в файлах, а справочник
поведения о предмете молчит. Переписать ветку под реальный остаток и сохранить номер PR
(закрыть и завести новый — значит оставить тред без нити). Отступление доложить.
См. [[branch-may-be-ahead-of-thread]].
