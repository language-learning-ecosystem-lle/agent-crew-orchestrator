`.github/scripts/notifier-mute.sh` — ключ глушения строится из имени уведомителя И предмета
события (`#<номер PR>` → `@<голова>` → пусто), окно 900 с. До #419 (влит 15.09.2026, тред `198`)
ключом было ОДНО ИМЯ, и письмо об отказе на одном PR глушило звонки обо всех остальных: замер
13.09 (тред `180`) — пять красных прогонов, писем три, заглушены `34759487215` (#388) и
`34759515483` (#383), в ленте ноль упоминаний. У `Comms Derived` предмета нет по построению
(`push`), ключ там остался именем — защита от петли треда `073` цела.

**Why:** обещание «следующее доехавшее письмо назовёт его числом» исполняется только СЛЕДУЮЩИМ
отказом с ТЕМ ЖЕ ключом; кончилась серия зелёным — заглушённое не попадает в почту никогда.
Восстановление съеденных звонков не покрывается сознательно.

**И хвост не ограничен ни аварией, ни часом — это НЕ лечилось ключом.** Строка «заглушено с
прошлого письма» якорится прошлым ПИСЬМОМ, и между ним и текущей аварией может лежать сколько
угодно зелени (замер 13.09: 3 ч 13 мин 03 с). PR #448 (тред `198`, 15.09) печатает у каждого
номера его СОБСТВЕННОЕ время и говорит, что хвост к этой аварии относиться не обязан; до его
merge в письме стоят голые номера рядом с датой чужой аварии.

**How to apply:** номера из строки глушения всё равно разрешай в свои прогоны перед отнесением к
аварии — `gh run view <id> --json createdAt,headBranch,conclusion`. Число отказов бери из прогонов
НАБЛЮДАЕМОГО (`gh run list --workflow '<имя>'`), а не из писем: письма — нижняя граница.
Заглушённые названы только в логе смотрителя: `gh run view <watch-run> --log | grep ЗАГЛУШЁН`
([[notifier-watch-runs-count-the-window]]: `success` у смотрителя ≠ письмо). У каждого проверяй
остаток в дереве: метка `review` висит, круга нет ([[label-survives-force-push-and-mutes-the-lift]]).
Правка ключа и текста письма живёт в `.github/workflows/notifier-watch.yml` — док власти, кнопка
john; сам `notifier-mute.sh` доком власти НЕ является.
