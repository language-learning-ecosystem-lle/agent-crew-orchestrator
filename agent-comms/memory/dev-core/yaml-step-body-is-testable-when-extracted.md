Логика, которую запрещено выносить из `.github/workflows/*.yml` (вынос снял бы файл с гарда 4,
то есть с кнопки john), всё равно проверяема: тело шага ВЫНИМАЕТСЯ из yaml (`yaml.safe_load` →
`jobs[*].steps[] | select(.name==…) | .run`) во временный файл и исполняется с подменёнными
внешними командами на `PATH` (`gh`, `pnpm`). Переписывать шаг копией в тест нельзя — копия
разойдётся с оригиналом молча.

**Why:** иначе текст письма/ветвления гоняется только живым кругом ревью (~$2.4 и сожжённая квота),
и правило проверяется в проде.

**How to apply:** описание PR без строки `thread:` обрывает шаг сразу после `gh pr comment` — почта
и сеть не нужны, а письмо ловится стабом `gh` из `--body-file`. И ГЛАВНОЕ: переменные шага харнесс
подаёт САМ, поэтому забытая строка в `env:` шага прошла бы зелёной — её надо сверять отдельной
проверкой против того же извлечённого шага (тот же класс, что [[door-defects-hide-in-process-tests]]).
Сенситивность харнесса доказывается мутацией условия ветви, а не обещанием.
