Уведомитель доставляет исход прогона, привязанного к **открытому PR**, независимо от цвета. Замер
2026-09-13, тред `177`, PR #387: прогон `34754279781` закончился `success` в `11:31:18Z` — письмо
`github` «✅ checks по PR #387: `success`» легло в тред в `11:31:41Z`, через 23 секунды. Письмо ещё и
несёт подсказку маршрута: «круга ревью на этой голове нет — метка `review` вешается сейчас, ход у
автора ровно на это одно действие».

**Why:** соблазн обобщить [[green-push-run-on-main-writes-no-letter]] («зелёный прогон писем не
шлёт») на PR — ложь, и она дорогая: из неё следует «исход не узнает никто, значит дочитываю сам», то
есть ровно то foreground-ожидание, которое запрещено железным правилом (`PROTOCOL.md`, «Ожидание
чужого прогона — не действие»). Молчание — свойство прогона БЕЗ адресата (push по `main`), а не
свойство зелёного цвета. Я сам написал обратное в письме треда `177` и в следующем такте действовал
по своей же неверной строке.

**How to apply:** `checks` идёт по своему PR → **отдать ход сразу, БЕЗ парка** — письмо поднимет пару
само. Парк `run:N` тут всё равно не годится: письмо адреса `run:` не несёт и парк им не снимается
(см. [[run-park-under-checks-has-no-lifter]]). И шире: факт установки «канал доставляет / не
доставляет» меряется лентой (`thread show`), а не цитируется по своему прошлому письму — обе мои
ложные посылки в треде `177` родились из цитирования себя.
