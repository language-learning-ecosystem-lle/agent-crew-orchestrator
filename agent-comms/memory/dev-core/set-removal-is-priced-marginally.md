Цена снятия набора каталогов = `du(все места)` − `du(все места, КРОМЕ набора)`. Ни сумма
построчных `du -sk --count-links`, ни ОДИН прогон `du` по набору на этот вопрос не отвечают:
прогон по набору дедуплицирует жёсткие ссылки ВНУТРИ набора, но ссылки, уходящие к тому, что
ОСТАЁТСЯ, считает как выигрыш.

Замер 17.09 на `.worktrees` ящика, одни и те же три дерева старого образца: сумма построчных —
**524M**, один прогон `du` по набору — **187M**, освободится на самом деле — **35M**. Разница в
15 раз ровно на числе, по которому принимают решение. Причина: pnpm жёстко линкует
`node_modules`, общий пул ~153M держит ЛЮБОЙ сосед. На мёртвом наборе 68 пар тот же эффект дал
856M маржинально против ~1007M прогоном по набору.

Остаток обязан включать ВСЁ, что остаётся рядом, включая чужие и незарегистрированные каталоги:
они держат тот же пул, и без них их доля вернётся в число как выигрыш. И число печатается вместе
с остатком, относительно которого посчитано, — иначе его начнут складывать.
