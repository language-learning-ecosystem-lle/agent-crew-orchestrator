Когда `main` красен из-за незакрытого окна (копия легла в `comms`, канон ждёт кнопки), не описывай
последнее письмо смотрителя — померь СЕРИЮ: `gh run list --branch main --workflow checks --limit 100
--json conclusion,headSha,createdAt` даёт последний зелёный и длину непрерывной красноты, а выборка
шагов у 3–4 прогонов серии (`gh run view <id> --json jobs -q '.jobs[].steps[] |
select(.conclusion=="failure") | .name'`) доказывает, что причина ОДНА на всю серию, а не совпадение
имён.

**Why:** такт, поднятый в стоячий адрес аварии, иначе повторяет прежний отчёт слово в слово; серия —
единственное, что в нём НОВОЕ, и это ровно то число, которого не хватает эскалации на кнопку.
Начало серии сверяется с моментом, когда легла копия (`git log origin/comms -- <путь>`): совпадение
с точностью до одного push'а превращает гипотезу «краснит окно» в замер.

**How to apply:** в отчёт идут три величины — последний зелёный (SHA + время), длина серии, момент
открытия окна. Из них считается возраст окна. Выборка шагов — обязательна: [[notifier-letters-collapse-to-one-cause]]
предупреждает, что пачка писем — это N push'ей поверх одной непочиненной головы, и серия без
выборки шагов ту же ошибку повторяет на прогонах. Парковать стоячий адрес за этим числом всё равно
нельзя — [[do-not-park-a-standing-address]].
