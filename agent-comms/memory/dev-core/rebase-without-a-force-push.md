Когда curator велит «перебазируй ветку на `main` и вези дальше», очевидный путь — `rebase` +
`push --force-with-lease` по тому же имени. Но force-операция по карточке роли идёт к john через
curator, и покупать этот ход не надо: те же коммиты садятся на свежую базу **черри-пиком на НОВОЕ
имя ветки**, старая остаётся нетронутой.

**Why:** ref старой ветки не переписывается, значит доказательство «ничего не потеряно» —
сама старая ветка: её содержимое целиком внутри новой, и это проверяется `git log
origin/main..<старая>` до черри-пика. Force-push такого доказательства не оставляет.

**А когда PR УЖЕ ОТКРЫТ, черри-пик на новое имя — не первый выбор: дешевле влить `origin/main` В
ветку.** Merge базы в ветку даёт ту же цель («ветка снова применяется к базе»), но push выходит
**fast-forward по ТОМУ ЖЕ имени** — номер PR, его тело, тред и все ссылки остаются на месте, а
черри-пик потребовал бы нового PR. Кнопка мержит squash, так что мерж-коммит внутри ветки в `main` не
поедет. Правило «force — ход к john» соблюдено буквально: `git push --dry-run` печатает
`<старая>..<новая>` БЕЗ `+`, и это и есть доказательство, что force не понадобился. Полевой случай
2026-09-09, #353 (тред `180-notifier-down`): смотритель написал «rebase the branch and push», сделана
склейка — отступление названо в треде с этой причиной.

**Ручное разрешение конфликта доказывается ДВУМЯ сверками, а не одной.** `git diff --numstat` против
`origin/main` обязан быть чистой прибавкой (`N / 0`) и совпасть с вкладом PR в этот файл; против
СТАРОЙ ГОЛОВЫ удаления будут — и их надо не объяснять словами, а приравнять побайтово к удалениям
самого сдвига базы:

```
diff <(git diff <старая голова> HEAD -- <файл> | grep '^-') \
     <(git diff <старая база> origin/main -- <файл> | grep '^-')
```

Совпало — удалено ровно то и только то, что удалила база. 2026-09-09, #353: add/add в хвосте
`docs/protocol-reference.md` (обе стороны дописывают секцию), 58/0 против `main`, 129/**5** против
старой головы, и эти 5 побайтово равны удалениям #359. Порядок секций — сначала та, что уже в `main`
(её текст не трогается вовсе), затем своя. См. [[manual-conflict-fix-needs-zero-deletions-proof]].

**Склейка НЕ ломает исключение гарда 1 у журнального PR — дифф PR трёхточечный.** Влитие `main` в
ветку тащит в её дерево чужие пути (замер 2026-09-13, #397: 8 путей — код, тесты,
`docs/protocol-reference.md`), и кажется, что `merge-gate --journals` после этого потребует круг. Не
требует: дифф PR считается `base...head`, и после мержа он остался ровно `69 0
docs/journal/dev-core.md` — дверь на голове мержа дословно `not asked: this diff is wholly a
journal`. Значит journal-only PR чинится склейкой без всякой потери, и метку вешать по-прежнему не
надо ([[courier-calls-for-a-label-on-journal-prs]]). Проверять всё равно ЗАПУСКОМ двери, а не
рассуждением.

**How to apply (черри-пик, когда PR ещё не открыт):** из detached-чекаута на свежем `main` —
`git merge-tree --write-tree origin/main <старая ветка>` (exit 0 = стыка нет), затем
`git cherry-pick <sha>` по коммитам, дальше своя работа,
`git push -u origin HEAD:refs/heads/<новое имя>`. В письме назвать оба имени и сказать, что
старая ветка станет пустой после посадки PR, — снятие лишней ветки чужой ход, не твой.

**Скретч-имя склейки НЕ кладётся под `wip/`, и это замерено (17.09, тред `218`).** `refs/heads/wip/`
— инвентарь планировщика: он перечисляет всё, что там лежит, и об имени не своей формы
(`wip/<role>/<thread>-<YYYYMMDDTHHMMZ>`) печатает «⚠ имя не говорит ни ЧЬЁ, ни КОГДА», то есть
роль, обязанная ветку взять или выбросить, не названа никем. Ровно этот рецепт и породил трёх сирот
`wip/189-rebase`, `wip/417-rebase`, `wip/418-rebase` — все три моей рукой, все три пустые по
содержанию (вклад сел squash'ем), все три лежали 3–4 дня. Скретч берёт имя `rebase/<n>` (вне
`wip/`), и **после ff-push удаляется своей же рукой** — `git branch -D rebase/<n>`: она локальная,
нигде не опубликована, удаление своего скретча необратимым действием карточки не является.

**How to apply (склейка, когда PR открыт):** `git checkout -B rebase/<n> origin/<ветка PR>` →
`git merge origin/main` → разрешить руками → доказать двумя сверками выше → `git diff --numstat
origin/main HEAD` обязан быть РОВНО диффом PR файл в файл → `tsc --noEmit`, потом сюита →
`git push --dry-run origin HEAD:refs/heads/<ветка PR>` (нет `+` = ff) → push → **снять метку
`review`**: вердикт был о дереве, которого больше нет, а висящая метка молчит, потому что круг
поднимает СОБЫТИЕ навешивания ([[label-survives-force-push-and-mutes-the-lift]]). Число
тестов на новой голове предсказывается заранее — см. [[predicted-test-count-proves-a-rebase]];
измерения о базе, сделанные ДО, становятся ложными — [[rebase-falsifies-measurements-about-the-base]];
почему нота гарда 2 сама по себе не приговор — [[label-follows-base-note-not-clean]].
