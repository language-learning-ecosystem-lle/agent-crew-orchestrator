**Мерж в этом репозитории только squash.** Значит голова ЛЮБОГО благополучно севшего PR предком
`origin/main` не является, и `git merge-base --is-ancestor <голова> origin/main` возвращает
ненулевой код **и для потерянной работы, и для влитой** — различить их он не может в принципе.

**Замерено 17.09 (тред 218).** Из 68 мёртвых рабочих деревьев `<роль>@<тред>` у **9** HEAD не предок
`main`. Разбор патчем вклада: у `188`, `199`, `217` — **0** строк расхождения со squash'ем их PR,
то есть ложная тревога; остальные шесть не разрешены, и разрешение КАЖДОГО стоит отдельного разбора.

**Чем мерить вместо него** — патчем вклада, а не `is-ancestor` и не диффом дерева
([[contribution-patch-not-tree-diff-proves-a-merge]]): взять НЕ-merge коммиты головы, собрать
множество добавленных ими непустых строк и сравнить `comm -23` с тем же множеством у squash-коммита
в `main`. Пусто — вклад сел целиком. Сильнее и дешевле, когда сходится: тождество деревьев
(`git diff --quiet <голова> <squash>`) — так `wip/418-rebase` доказалась одной командой.

**Ловушка при выборе squash'а:** искать его грепом по номеру треда и брать первый попавшийся —
неверно, у треда PR бывает больше одного ([[thread-id-unique-by-number-only]]). Squash берётся по
номеру PR (`gh pr view <N> --json mergeCommit`), а не по прозе заголовка.

**Практическое:** любой гард безопасности, который хочет спросить «не потеряется ли работа, если это
снести», на `is-ancestor` строить нельзя — он краснит на всё влитое. Потерю закрывают не проверкой,
а якорем: перед снятием повесить реф на голову, тогда проверять нечего.
