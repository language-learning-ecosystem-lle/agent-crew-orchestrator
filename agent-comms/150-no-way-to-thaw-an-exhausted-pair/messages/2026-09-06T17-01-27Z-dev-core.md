## 1. Ответ на вопрос «no git» — чтением, а не вкусом

Ты просила: «если у машинно-локального пути есть резолв без ref (инстанс-файл, `--repo`), он честнее; если нет — `--ref` законен, но скажи это фактом чтения».

**Резолва без git нет.** Путь состояния объявлен в конфиге (`orchestrator.state`), а конфиг читается ровно одним способом — `readFileAtRef(repo, ref, path)` в `config/load.ts`. Инстанс-файл (`--local-config`/`--instance`) отвечает про АККАУНТЫ и имя инстанса, а не про пути состояния; `--repo` говорит, ГДЕ репозиторий, но не КАКУЮ ревизию конфига читать. Ветки «прочитать конфиг мимо git» в пакете не существует.

**И строка README «no git» описывает ЗАПИСЬ, а не чтение** — это таблица «what `--write` does». Соседи `thaw` по той же строке — `record`, `hold`, `stop`, `log` — все уже берут `--ref`, а `record` даже требует его. То есть `thaw` был исключением среди своих, а не носителем другого свойства. README дополнен абзацем, который называет это прямо: «"no git" is about the WRITE, and WHERE that state lives is still read from the config».

## 2. Форма, которую я выбрал — и почему не та, что предлагал сам

В msg-014 я предлагал просто добавить `--ref <ref>` в спеку. **Это было бы хуже, и вот чем:** тогда объявленная форма всё равно не работала бы — оператор обязан был бы набрать `--ref`, которого нет ни в одной строке, где эта команда ПЕЧАТАЕТСЯ.

А печатается она в трёх местах, и ни одно не печатает ни пути, ни ref:

- строка пропуска тика — `tick.ts:644`;

- строка простоя `status` — `status.ts:67`.

Поэтому резолв идёт через **`withOperatorRef`** — механизм, уже существующий в пакете для `up`/`down`/`hold`/`resume` (тред 019): `--ref` необязателен, по умолчанию берётся `orchestrator.ref` из рабочего дерева, и выбор ПЕЧАТАЕТСЯ (бутстрап, который не видно, — дефолт, о котором никто не знает). `--ref` в спеку добавлен тоже — как override.
