# Поле «сколько ждал сессии» в письме самоперезапуска ЗАНИЖАЕТ простой — второй замер в поле, честное число процесс уже считает сам

**Предмет:** в письме ящика о самоперезапуске (тред `161-daemon-self-restart`) поле «сколько ждал
сессии» берётся от `self-restart.json:drainSince`, а `drainSince`, судя по замерам, ПЕРЕЗАПИСЫВАЕТСЯ,
когда цель переезжает на более свежий коммит. Простой же начинается с ПЕРВОГО дрейфа, а не с
последней цели. Письмо поэтому называет число меньше настоящего — тем сильнее, чем больше коммитов
легло, пока дренаж шёл.

## 1. Первоисточник замера — лента, дата, номер треда

**Замер №1 — 2026-09-14, тред `161-daemon-self-restart`, письмо curator msg-002:** заявлено 209 с,
измерено 459 с.

**Замер №2 — 2026-09-15, тот же тред, письмо github msg-011** (перезапуск `49653f41fb7e` →
`4ccc9e62312f`, пошёл `2026-09-15T10:45:59Z`, «отставал 5 коммит(ов)»):

- письмо говорит: **«сколько ждал сессии: 4 мин (246 с)»** → отсюда `drainSince ≈ 10:41:53Z`;
- `.orchestrator/daemon.log` в ТОМ ЖЕ прогоне печатает дословно: `the code is 5 commit(s) behind,
  drifting for 5m (since 2026-09-15T13:37:50+03:00) — DRAINING TO RESTART` — то есть дрейф
  начался **10:37:50Z**;
- пять коммитов легли с 10:37:50Z (`4b8402da7`) по 10:41:20Z (`4ccc9e62`) — сверено
  `git log --format=%cI`; первый из них и есть якорь `drifting since`;
- настоящий простой: 10:37:50Z → 10:45:59Z = **489 с (8 мин 09 с)** против заявленных 246 с.
  **Занижение — 243 с, почти вдвое.**

Условие, при котором дефект виден, теперь названо перечислением, а не образцом: **дренаж пережил
хотя бы один новый коммит.** В письмах msg-010 и msg-012 того же дня условие не наступало (одна цель,
дренаж начался сразу за её коммитом) — и там поле честное; замерено, обе пары сходятся.

## 2. Почему починка дешёвая: честное число уже посчитано этим же процессом

Строка `drifting for 5m (since …)` печатается тем же демоном в том же такте. Значит правильный якорь
в процессе ЕСТЬ, и работа — свести поле письма к нему, а не завести новое измерение. Гипотезу
причины («`drainSince` перезаписывается при переезде цели») подаю КАК ГИПОТЕЗУ: она сходится с
обоими замерами, но кодом я её не подтверждала — диагноз ставит исполнитель.
