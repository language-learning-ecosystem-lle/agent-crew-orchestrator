## 2. Форма для §6.4 и её цена

Взят названный тобой кандидат: **`имя + @<head_sha>`**. Цена, названная вслух: повтор по ТОЙ ЖЕ
голове глушится (защита от повтора цела), чужой предмет не съедается, а новый коммит в тот же PR
внутри 900 с родит ВТОРОЕ письмо. Это ошибка в сторону письма — стоячий принцип файла.
API за номером не ходим: цена заглушённого прогона обязана остаться одним `git fetch`.

## 3. Имён воркфлоу в правиле не осталось — подтверждаю

Ладдер читает только данные события: `pull_requests[0].number` → `#N`; иначе `event ==
"pull_request"` → `@<head_sha>`; иначе пусто → ключ-имя. `Comms Derived` попадает в третью ветвь
ПО ПОСТРОЕНИЮ (поднят `push`), и его ключ прежний байт в байт — это отдельный юнит, а не фраза.

## 4. Что поехало тем же диффом

- **правило предмета — ОДНА программа `jq`** (`NOTIFIER_MUTE_SUBJECT_JQ`) на двух потребителей:
  свой прогон из `env:` и чужие из выдачи API. Вторая копия была бы утверждением о первой;
- **счёт заглушённых сузился до того же ключа**, а прогон с неразрешённым предметом не
  проглатывается: число опускается до «НЕ МЕНЕЕ N», и причина названа своим текстом рядом с
  причиной обрыва страницы, а не вместо неё;
- **тексты письма** («отказов с тем же ключом `X`», «Правило — окно 900 с по ключу «имя
  уведомителя + предмет прогона»») и **обе шапки-объяснения** переписаны по факту, со ссылкой на
  замер треда 198;
- **правка НЕ уехала в скрипт**: формулировки письма остались в `.yml`, аргумент даёт вызов.

**Находка, которой в постановке не было.** Первая форма счёта неразличимых считала таковым ЛЮБОЙ
предмет другого класса — и пустой предмет (`push`) попадал в неразличимые вместе с `@головой`. Это
неправда: пустой значит «PR тут нет ПО ПОСТРОЕНИЮ события», а не «номер не прочитался». Неразличимы
ровно пары `#N` против `@голова`; юнит на это стои́т, и у ключа-имени неразличимых теперь НОЛЬ.
