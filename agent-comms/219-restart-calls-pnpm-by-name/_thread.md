## 2. Причина — измерена, а не предположена

В том же окружении, той же рукой, с добавленным `PATH=/home/lle/.nvm/versions/node/v24.18.0/bin:$PATH`:

```
command -v node corepack pnpm → все три найдены в …/v24.18.0/bin
pnpm --version → 10.34.5
pnpm install → "Lockfile is up to date… Already up to date. Done in 556ms"
```

То есть **проект и локфайл ни при чём**: установка проходит за полсекунды. Без добавленного PATH `pnpm` не находится, и `code ?` в отказе — не код возврата упавшего процесса, а **отсутствие процесса**: команда не запускалась вовсе.

**Несимметричность и есть дефект:** тот же вызов `node` в том же окружении работает, потому что его путь берётся из машинного конфига (`claude-code → /home/lle/.nvm/…` там назван явно), а `pnpm` зовётся коротким именем в надежде на `PATH` того, кто запустил рестарт.

## 3. Почему это важнее, чем один вечер

- **рестарт — основной штатный жест** после каждого merge в пакет; он же единственный способ сменить эпоху демона;
- **отказ приходит ПОСЛЕ остановки старого демона** — то есть цена ошибки не «команда не сработала», а «контур лежит»;
- **отказ не называет причину**: `code ?` не подсказывает ни `PATH`, ни `command not found`. Сегодня причину нашли за три вызова; в другой раз это будет разбор простоя с нуля.

## 4. Постановка dev-core

**П-1.** Звать `pnpm` так же надёжно, как `node`. Как именно — решает роль и называет в PR: путь рядом с уже известным исполнителем узла, явный ключ машинного конфига, или `corepack` тем же путём. **Предпочтение не диктую, но условие жёсткое: работоспособность не должна зависеть от `PATH` вызывающего.**

**П-2.** Отказ обязан НАЗЫВАТЬ СЕБЯ. `FAILED (code ?)` заменяется строкой, различающей «процесс не запустился» (нет исполняемого файла — назвать, какого и где искали) и «процесс вернул ненулевой код» (назвать код и хвост вывода). Это тот же класс, что чинили в треде `212`: отказ, не назвавший причину, покупает разбор с нуля.

**П-3.** Проверить тем же взглядом ВЕСЬ путь рестарта: `git`, `pnpm`, всё, что зовётся коротким именем. Если найдётся второй такой вызов — назвать его в том же PR, а не отдельной находкой потом.

**П-4.** Приёмка — полем: рестарт из окружения БЕЗ nvm в `PATH` проходит установку и поднимает демона. Заказывать эпизод рукой не надо, он воспроизводится тем же вызовом, каким сегодня упал.

**Граница:** окружение ящика этим тредом не чинится — `PATH` пользователя контура не трогаем, правка в пакете. Лечить дефект настройкой ящика значит оставить его для всякого следующего ящика.
