## 2. Дефект в одной строке

`.github/scripts/review-delivery.sh`, `park_flags` (шапка правила — строки ~311–331). Правило
объявляет три случая: парк за ЭТИМ кругом → `--park-lifted`; парк чужой → `--parked-on` («чужой парк
снимать нечем, и врать о нём нельзя»); парка нет → без флагов. **Случая «чужой парк, чьё основание
дверь только что объявила МЁРТВЫМ» в правиле нет**, и попадание в него — не пауза, а ПОТЕРЯ:
`--parked-on` отказан дверью, `--park-lifted` запрещён правилом, письма не существует вовсе.

Класс замерен в поле один раз (сегодня) и стоит НЕ теоретически: парк `run:N` под уже завершившимся
прогоном лифта не имеет вовсе — снять его может только поднятая сессия своим письмом, а поднимать
некого, потому что тред запаркован.

> При отказе записи, чей ТЕКСТ содержит `every run on head … has ALREADY FINISHED`, курьер повторяет
> попытку РОВНО ОДИН раз с `--park-lifted <то же самое значение, что стоит>`. Ни при каком другом

предлагается разрешить машине; спор идёт о праве, а не о выполнимости.

## 4. Постановка (готова к старту по исходу 1; при исходах 2 и 3 не действует)

**Исполнитель:** `dev-core`. **Файл:** `.github/scripts/review-delivery.sh` (+ его процессный тест).
Доков власти в предмете нет; кнопка — curator по обычным пяти гардам.

**Предмет:** добавить в путь доставки вердикта ветвь под чужой парк, чьё основание дверь объявила
мёртвым, в узкой форме из §3.

**Приёмка — проверяемыми фактами:**

1. ветвь включается ТОЛЬКО по тексту отказа двери; ни одно решение о парке не берётся из второго
   разбора ленты (правило всего файла — «значение и суждение о парке берутся из ТЕКСТА двери»);
2. повтор ровно один; второй отказ оставляет шаг красным и называет в логе, где лежит текст вердикта
   (коммент PR и артефакт `reviewer-execution-<pr>-<run>`);
3. значение в `--park-lifted` — БУКВАЛЬНО то, что стоит; вычислять из номера PR запрещено (шапка
   `park_flags` объясняет, почему слепое `run:<PR>` чинит один случай из четырёх);
4. шапка `park_flags` переписывается вместе с кодом: правило из трёх случаев становится правилом из
   четырёх, и четвёртый назван словами вместе с его доказательством;
5. в диффе нет: новых полей и ключей конфига, новой формы сообщения, нового шага маршрута, правки
   двери почты и правки `.github/workflows/**` (последнее — чтобы кнопка осталась у curator, а не
   уехала к john гардом 4).

**Проверяемость — ответ на оба вопроса dev-core, и это ответ, а не вкус:**

- **класс покрытия — процессный тест** `.github/scripts/review-delivery.test.sh` на существующем
  стенде `gh`: юнита у этого пути нет и заводить его под один `if` дороже предмета, а живая приёмка
  человека невоспроизводима (нужен чужой парк, умерший под доставкой);
- **мутация «убрать ветвь → красный ПО ИМЕНИ» доказательством СЧИТАЕТСЯ** и является обязательной
  частью доклада: называется имя покрасневшего состояния и его текст. Красит — значит покрыто; молчит
  — значит теста нет, как бы он ни назывался. Число зелёных дельтой не меряется, меряются строки
  `FAIL`;
- **отдельное покрытие, без которого ветвь протухает МОЛЧА:** ветвь опознаёт отказ по фразе двери
  (`every run on head … has ALREADY FINISHED`). Фраза живёт в `packages/**` и может быть
  переформулирована безобидным PR — ветвь тогда перестанет включаться, и НИ ОДИН тест не покраснеет,
  потому что стенд `gh` пишет отказ сам. Поэтому требуется вторая проверка, связывающая фразу с её
  ИСТОЧНИКОМ: тест (в пакете либо в процессном прогоне), который краснеет, если такой строки нет в
  исходнике двери. Форму выбирает исполнитель, требование — исход: переформулировка отказа обязана
  покраснеть где-то;
- **сознательно НЕ покрывается:** поведение самой двери почты (не правится, см. §3) и повторная
  доставка вердикта после второго отказа — она остаётся ручной по красному шагу.
