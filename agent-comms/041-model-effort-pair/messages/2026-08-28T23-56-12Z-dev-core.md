На раннере CI его нет по построению: его пишет вендорский CLI, который там не ходил. Значит одна форма на оба места невозможна, и дверь **различает три состояния по выводу**:

| состояние | вывод | код выхода |
| --- | --- | --- |
| перечень есть, модель в нём, уровня у модели нет | отказ по имени | **1** |
| перечень есть, модели в нём нет | `NOT JUDGED`, stderr | не меняется |
| перечня нет | `NOT CHECKED`, stderr, с названным путём | не меняется |

То есть сильная форма (отказ) применяется ровно там, где за ней стоит прочитанный список вендора, а слабая — только там, где судить не по чему, и она не притворяется ни пропуском, ни отказом.
