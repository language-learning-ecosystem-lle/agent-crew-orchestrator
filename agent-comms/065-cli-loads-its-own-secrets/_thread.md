**Постановка по слову john (чат 2026-08-30 ~18:22Z), дословно: «пусть он сам свои креды берёт». Предмет: команды пакета требуют токен ОТ ОКРУЖЕНИЯ ВЫЗЫВАЮЩЕГО, хотя знают, где он лежит.**

## 1. Факт

Конфиг инстанса **прямо называет файл секретов**: `instances/hetzner.json:22` → `"secrets": { "envFile": ".../secrets.aco.env" }`, `instances/lle-hetzner.json:16` → `secrets.lle.env`. Команда, запущенная в дереве контура, читает этот конфиг — и всё равно отказывает, если `GH_TOKEN` не подставлен снаружи:

```
gh pr list --state open --json …
To get started with GitHub CLI, please run: gh auth login
Alternatively, populate the GH_TOKEN environment variable…
```

**Цена уплачена сегодня трижды, все три случая измерены:**

1. **Демон ослеп на пять тиков.** После закрытия общего входа `gh` (john, ~18:05Z) слой `merge-ready` отключился и сообщил об этом только через пять тиков: «refused by gh for 5 ticks in a row (threshold 5) since 18:08:23Z». Контур при этом продолжал тикать — то есть **потеря доступа к платформе выглядела почти как нормальная работа**;
2. **Лечение пришлось делать поверх пакета** — `EnvironmentFile=` в override юнита каждого контура, руками john. Юнит теперь знает про секреты то, что уже знает конфиг: одно и то же место, два источника истины;
3. **Человек не может позвать команду руками** — `orchestrator status` из консоли john отвечает `Username for 'https://github.com'`, хотя стои́т в дереве контура, у которого есть конфиг и в конфиге есть путь к секретам.

## 2. Что требуется

**Команда, работающая в дереве контура, сама читает `secrets.envFile` своего инстанса и подставляет переменные в окружение дочерних вызовов (`gh`, `git`).** Форма — на замер исполнителя; требования к ней:

1. **Источник один — конфиг инстанса.** Не юнит, не профиль оболочки, не `hosts.yml`. Юнитные `EnvironmentFile`, поставленные сегодня руками, после этого становятся лишними и должны быть сняты — иначе останется два источника, расходящихся молча;
2. **Уже стоящее окружение НЕ перетирается** — если вызывающий явно подставил токен, побеждает он (это путь отладки и путь john);
3. **Отказ по имени, а не «populate the GH_TOKEN»**: файла нет / ключа в нём нет / файл нечитаем — три разных сообщения, каждое называет путь, который команда пыталась прочитать;
4. **Секрет не печатается никогда** — ни в логе, ни в отладочном выводе, ни в строке ошибки;
5. **Границы контура соблюдаются**: команда берёт секреты ТОГО инстанса, которому принадлежит дерево. Смежно с `062` — токен привязан к контуру, и это второй забор на том же месте.

## 3. Что это чинит сверх удобства

- **демон перестаёт зависеть от того, как его запустили** — сегодня он ослеп именно потому, что окружение процесса и конфиг разошлись;
- **john может звать команды руками** без подстановки файла и без личного токена на машине (он сказал прямо, что личный токен ему не нужен);
- **исчезает молчаливый провал в общий вход**: пока `hosts.yml` существовал, команда без переменной работала «сама собой» — и мы не отличали «токен подставлен» от «сработал общий доступ». Это и было тем, что сегодня скрывало дыру границы контуров.

## 4. Проверяемость

- юниты: конфиг называет файл → переменная попадает в дочерний вызов; переменная уже стоит → не перетёрта; файла/ключа нет → отказ по имени с путём; секрет не встречается ни в одном выводе;
- сценарий: `orchestrator status` в дереве контура из ЧИСТОГО окружения (без `GH_TOKEN`, без входа `gh`) — работает;
- поле: после посадки снять `EnvironmentFile` из override обоих юнитов и убедиться, что демон продолжает работать; ни одного «refused by gh» в логах суток.

# Сделано: команда считает окружение дочернего вызова из `secrets.envFile` своего инстанса — PR #164

## 1. Что стоит в PR

`packages/agent-protocol/src/config/credentials.ts` — новый модуль. Окружение дочернего `gh`/`git` СЧИТАЕТСЯ из конфига того инстанса, которому принадлежит чекаут (`resolveLocalConfig`, тред 055 — там граница контуров уже живёт, и токен становится вторым забором на той же линии, что и `062`).

Требования постановки, по пунктам:

1. **Источник один — конфиг инстанса.** Ни юнит, ни профиль оболочки: `secrets.envFile` того `local.json`/`instances/<id>.json`, который claim'ит чекаут;
2. **Уже стоящее окружение не перетирается** — вызывающий с экспортированным `GH_TOKEN` побеждает файл. Это ОБРАТНАЯ сторона порядка в `notify/secrets.ts` (там побеждает файл), и расхождение объяснено в шапке модуля, чтобы следующий читатель не «починил» одно под другое;
3. **Отказ по имени** — четыре разведённых сообщения вместо «populate the GH_TOKEN»: `secrets.envFile` не назван / файла нет / файл нечитаем (с текстом ошибки) / файл прочитан и в нём нет ни `GH_TOKEN`, ни `GITHUB_TOKEN` (перечислены ИМЕНА того, что в нём есть). Каждое цитирует путь, который читали, и конфиг, который его назвал;
4. **Секрет не печатается** — ни в ноте, ни в отказе. Git-helper печатает токен из СВОЕГО окружения (`$GH_TOKEN`), поэтому значение не попадает ни в конфиг-значение, ни в командную строку, ни в имя процесса;
5. **Границы контура** — инстанс определяется чекаутом, поэтому бокс с двумя контурами отдаёт каждому вызову токен ЕГО контура.

**Подключено:** `merge-gate` (все три вызова `gh` — `pr view`, `api commits/<base>`, `api actions/runs`), слой `merge-ready` планировщика, дверь парка `run:` (`runParkFacts`), `git` доставки почты. В `merge-ready` окружение считается ПЕР ВЫЗОВ, а не один раз при подъёме источника: демон живёт неделями, и ротация токена под ним не должна требовать рестарта.

**`git` получает то же окружение:** credential helper для `github.com` через `GIT_CONFIG_*` (индекс ДОПИСЫВАЕТСЯ к уже стоящему `GIT_CONFIG_COUNT` — иначе чужая запись 0 молча пропадёт) и `GIT_TERMINAL_PROMPT=0`. Второе — независимо от наличия токена: `Username for 'https://github.com'` на stdin сессии, за которой никто не смотрит, это зависание, а не отказ.

## 2. Проверяемость (раздел 4 постановки)

- **юниты** — `config/credentials.test.ts`, 13 случаев: конфиг называет файл → переменная в окружении дочернего вызова; уже стоящая не перетёрта; три отказа, каждый с путём; `GIT_CONFIG_*` дописывается; и отдельный случай, который прогоняет `not.toContain` по значению секрета сразу по всем выводам модуля;

Это ровно то состояние, в котором консоль john отвечала запросом логина. Три случая: токен доехал из файла; файла нет → отказ с путём и кодом 2; токен в окружении вызывающего победил файл;
- **поле** — не сделано и сделано быть не могло этим PR: снятие `EnvironmentFile=` из override юнитов обоих контуров и сутки без «refused by gh» в логах.
