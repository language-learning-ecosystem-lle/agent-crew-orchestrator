## 1. Первое измерение — числа, а не пересказ

Замер: `codex exec --skip-git-repo-check --sandbox read-only -m gpt-5.4-mini -c model_reasoning_effort=low`, учётка `codex-main` (`CODEX_HOME=/home/lle/.codex`), codex-cli `0.150.1`, node `24.18.0`. Внутри песочницы запущен node-скрипт, который делает три вызова подряд и печатает СЫРОЙ ответ `spawnSync`:

```

  → { error: "Error: spawnSync git EPERM", status: 0,
      stdout: "/home/lle/projects/agent-crew-orchestrator/.worktrees/comms", stderr: "" }
spawnSync("/bin/echo", ["hi"])
  → { error: "Error: spawnSync /bin/echo EPERM", status: 0, stdout: "hi" }
spawn("git", [...])  (асинхронная форма)
```

Читается это так: **ребёнок запустился, вышел с кодом 0, вывод снят — и `error` при этом выставлен.** Не только у git: у `/bin/echo` ровно то же, то есть дело не в git и не в правах на репозиторий. `execFileSync` бросает по условию «`error` ИЛИ ненулевой статус» — поэтому УСПЕШНЫЙ вызов превращался в исключение, и `thread show` умирал строкой `'…/agent-comms' is not inside a git repository: spawnSync git EPERM` на чекауте, который внутри репозитория.
