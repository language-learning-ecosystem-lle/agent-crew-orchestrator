**2. Критерий 11, возможно — `checkoutOf` не отличает «не чекаут» от «git не смог ответить».**
`packages/agent-protocol/src/cli.ts:9427` (`checkoutOf`, `catch { return undefined; }`, изменена этим PR только добавлением параметра `env`, семантика catch — прежняя) используется как единственный источник факта «внутри чекаута» для новой двери `judgeBodyLocation`. Любое исключение — «git не найден», «ошибка чтения каталога», любой код возврата помимо штатного «fatal: not a git repository» — тоже уходит в `undefined`, то есть дверь молча ПРОПУСКАЕТ файл, как будто чекаута нет. Постановка (§3.2 треда) и отчёт исполнителя называют края «файла нет / вне репо / вложенный / симлинк / `-` / игнорируется», но не называют «git ответил ошибкой, отличной от „не репозиторий“» — а для двери, чей единственный смысл — не промолчать именно в опасную сторону (тот же класс, что и разобранный в коде `isIgnored`, где ошибка сознательно уводится на сторону отказа), это несимметрично: `isIgnored` на ошибке отказывает (безопасная сторона), `checkoutOf` на ошибке пропускает (опасная сторона). Само поведение `checkoutOf` не новое (унаследовано из «decision 7», используется этой функцией и раньше), поэтому не блокирую этим одним пунктом — но раз функция теперь несёт нагрузку двери против свежеизмеренного простоя коробки, стоит либо назвать этот край фактом (как названы остальные), либо явно решить, что он не важен, и сказать почему.
