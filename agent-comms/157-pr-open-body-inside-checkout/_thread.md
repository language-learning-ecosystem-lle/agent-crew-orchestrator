## Одно отступление от постановки — доложено, потому что оно меняет предикат

**Игнорируемый путь дверь пропускает.** Постановка §3.2 оставила определение «внутри чекаута» за исполнителем при условии замера — вот замер, сделанный в этой сессии, `2026-09-07`:

```

$ d=$(mktemp -d); echo $d      → /tmp/aco-5c148899a7a0/tmp.m2e9LzPvwt

$ git -C "$d" rev-parse --show-toplevel → /home/lle/projects/agent-crew-orchestrator
$ git -C "$(mktemp -d -p /tmp)" rev-parse --show-toplevel → fatal: not a git repository
```

То есть **привычный роли `mktemp -d` кладёт файл внутрь обслуживаемого чекаута**. Дверь на одном `--show-toplevel` отказывала бы каждой роли на нормальном пути — и живая приёмка §4 («следующий PR контура открывается штатно, дверь молчит») стала бы красной прямо в постановке.

Но авария не в «файл в дереве», а в «файл, поверх которого `git pull --ff-only` отказывается писать», — а над игнорируемым он не отказывается. `.orchestrator/` объявлен машинным состоянием контура твоим же §2 (решение john в `153`). Поэтому предикат: **внутри чекаута И `git check-ignore` молчит**. Это НЕ починка игнором, которую john отверг: дверь читает игноры, которые уже есть, и ни одной записи не заводит. Рабочее дерево роли показывает разницу: `.worktrees/` игнорирует обслуживаемый корень, а внутри самого дерева (оно и есть внутренний чекаут, и его спрашивают) не игнорирует никто — тело там отказано.

Если считаешь, что дверь обязана отказывать и над игнорируемым путём (то есть менять привычку каждой роли на `-p /tmp` принудительно) — это одна строка и один тест, скажи.

## Края, названные фактом (§3.2)

| край | исход |
| --- | --- |
| файла нет | дверь не достигается: тело читается раньше, путь отказан как нечитаемый (тест) |
| каталог вне репозитория | проход |
| вложенный чекаут | отказ по ВНУТРЕННЕМУ (тест против настоящего git, топлевел не пересказан) |
| симлинк снаружи внутрь | отказ: `git -C` делает каталог своим cwd, cwd git разрешает сам — руками не резолвим |
| `--body-file -` | не форма этой команды: тело читается файлом по имени; `-` искался бы как файл `-` |
| игнорируемый путь | проход (выше) |
| git не ответил / ответил пустым | «не чекаут» → проход; ошибка `check-ignore` → «не игнорируется» → сторона отказа |
