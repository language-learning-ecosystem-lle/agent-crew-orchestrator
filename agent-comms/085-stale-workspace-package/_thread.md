## 1. Факт

**Сессия роли поднимается на ОТСТАВШЕМ пакете молча, если номер схемы не двигался.**

Замер: `.worktrees/dev-speech` стоял на `agent-protocol` `0.2.7` при пине репозитория `v0.2.9` — из четырёх деревьев машины ровно одно; шаг ритуала «`pnpm install` в каждом воркспейсе роли» после бампа прошёл мимо этого дерева, и **никто об этом не сказал**.

**Почему гейт не поймал:** между `0.2.7` и `0.2.9` `protocolVersion` ОДИН И ТОТ ЖЕ — `25`. Версионный гейт сравнивает схему конфига со схемой пакета; здесь они сходятся, и подъём законен по его критерию.

**Кто платит:** первый же вызов почты. Флаг `--for` существует только в `0.2.9`; на `0.2.7` это `exit 2` плюс **749 строк usage в контекст сессии**. То есть роль тратит такт и контекст на выяснение того, что её окружение отстало.

## 2. Почему это класс, а не разовый недосмотр

1. **ритуал бампа исполняется рукой john** (`stop` → `pull` + `install` → `install` в КАЖДОМ воркспейсе → `start`), и «каждый» здесь держится на внимании человека в час ночи. Сегодня четыре дерева из четырёх прошли в контуре протокола и три из четырёх у потребителя — этого достаточно, чтобы назвать шаг ненадёжным;
2. **признак «схема не двигалась» будет ЧАСТЫМ**: большинство пакетов схему не трогают, а пин между тегами двигается регулярно. Значит слепое пятно открыто по умолчанию, а не в редком случае;
3. **отказ приходит не там, где причина**: роль видит непонятный `exit 2` от команды почты, а не «твой пакет отстал». Класс «система молчит там, где должна называть» — тот же, что контур чинил весь день.

## 3. Что предлагается

**Тик демона сверяет версию пакета воркспейса ДО спавна** и отказывает по имени, а не после. Кандидат назван в корневом `CLAUDE.md`; форма — на замер исполнителя. Требования:

1. **сравнивать не схему, а сам пакет** — версию установленного `agent-protocol` в воркспейсе против пина репозитория. Схема здесь не работает по построению (это и есть дефект);
2. **отказ по имени**: какая роль, какое дерево, какая версия установлена, какая ожидается, и что сделать (`pnpm install --frozen-lockfile` в этом дереве);
3. **не тратить попытку пары** — это дефект окружения, а не работы роли; тот же принцип, что у отказа по кредам;
4. **дешевизна проверки**: она идёт на каждом подъёме, значит читать надо файл манифеста установленного пакета, а не звать сеть;
5. **симметрия с ритуалом**: если проверка появится, шаг «install в каждом воркспейсе» перестаёт быть единственной защитой — но из ритуала НЕ убирается, потому что чинит он, а проверка только называет.

## 4. Границы

Автоматически чинить (запускать install из демона) — НЕ предмет: это запись в рабочее место роли из чужого процесса, и решать это john отдельно, если проверка окажется частой. Здесь предмет — **назвать вслух**, а не вылечить молча.

## 5. Проверяемость

Сценарий: воркспейс роли на пакете старше пина при совпадающей схеме → подъём отказывает по имени с обеими версиями; воркспейс совпадает → подъём идёт как прежде; попытка пары не тратится ни в одном случае. Поле: ни одной сессии, потратившей такт на `exit 2` от команды почты по причине отставшего пакета.
