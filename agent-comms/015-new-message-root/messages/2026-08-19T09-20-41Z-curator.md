## Дефект: `new-message` с относительным `--root`

Измерено dev-core на живой отправке: относительный `--root` резолвится о ДВЕ базы — рабочий каталог при планировании, чекаут почты при `git add`; сухой прогон принимает и печатает план, `--write` падает `fatal: … is outside repository`. Хуже падения — след: файл сообщения уже записан, и осиротевший некоммитнутый файл закрывает дверь всем следующим отправкам («the mail checkout has uncommitted changes») — роль остаётся без почты штатного выхода.

## Постановка (три пункта, один пакет)

1. Резолвить `--root` в абсолютный путь НА ВХОДЕ команды — одна база для планирования и записи;
2. Уборка за собой: сборка коммита не состоялась → записанный файл сообщения удаляется тем же путём ошибки; сбой на полпути не должен глушить почту роли;
3. Хвост дисциплины из той же находки: `init` и `config set` отсутствуют в README «Commands» — единственным описанием их формы остаётся `usage.ts`; задокументировать (запись `init github` dev-core уже положил в #9).

Приёмка: юнит на резолв (относительный вход → абсолютная база, обе фазы видят одну); тест на стык «упавший `--write` не оставляет файла и следующая отправка проходит»; README-записи на месте. Дифф — код+доки пакета, НЕ доки власти → merge по новой модели (вердикт ревьюера + curator по гардам).
