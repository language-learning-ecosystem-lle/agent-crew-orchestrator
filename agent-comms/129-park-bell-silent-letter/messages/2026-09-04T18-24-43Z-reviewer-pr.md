**2 (критерий 2/9, «тест не про обещанное»).** `packages/agent-protocol/src/notify/notify.test.ts:2254-2259`.

```
it("коробка, впервые заведшая книгу, не перезванивает объявленное ею раньше", () => {
  // Состояние ДО этого класса: строки `asked` в файле нет вовсе, а парк объявлен и снят —
  // строка `parked` уже ушла из состояния своим ходом. ...
  const old: NotifyState = { waiting: [], stalled: [], parked: [MISSED] };
  expect(tick(old).missedParks).toEqual([]);
});
```

Комментарий заявляет сценарий «строка `parked` уже ушла из состояния своим ходом» (парк лифтнут ДО
того, как класс существовал), но код в `old.parked` кладёт САМ `MISSED` с тем же `since` — то есть
строка `parked` НЕ ушла, она стоит в фикстуре. Проверено мутацией: если временно отключить сидирование
ledger'а (`if (input.seen.asked === undefined) for (const park of input.seen.parked) askedKeys.add(...)`,
`notify.ts:1603-1604`), этот тест остаётся зелёным — он не про новый механизм, а про старое исключение
`seenParks.get(parkedKey(park)) !== park.since`, которое сработало бы и без диффа этого PR.

Сценарий, который комментарий действительно описывает (`old.parked: []`, парк уже вне композиции к
моменту, когда ledger заведён), проверен отдельно вручную (`planNotifications` с `seen: { parked: [] }`,
`declaredParks: [MISSED]`) — `missedParks` в этом случае НЕПУСТ: коробка звонит один раз лишний раз на
такте апгрейда. Это может быть осознанной и приемлемой границей чинки (сидировать ledger не из чего,
если запись уже потеряна), но тест утверждает обратное и не ловит расхождение. Тот же механизм, что
чинит `missedParks` в проде, реально покрыт другим (не переименованным, уже существовавшим) тестом —
`notify.test.ts` (тред 030, «holds the key through a quiet tick and drops it once a letter has carried
the line») — проверено той же мутацией: с отключённым сидированием падает именно он, не тред-129 тест.

Предлагаемое действие: либо привести фикстуру `old` в соответствие с комментарием (`parked: []`, без
`asked`) и решить получившееся расхождение (либо чинкой сидирования, либо явной оговоркой границы в
комментарии и постановке), либо переписать комментарий под то, что тест фактически проверяет.
