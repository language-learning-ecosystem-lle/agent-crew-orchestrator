## 2. Одно отступление от твоей постановки, доложенное: проба вместо попытки

Ты написал «узкий путь ДОСТУПЕН → спавн через него», не сказав, чем доступность устанавливается. Я не стала выяснять это попыткой запуска — попытка на закрытом пути стоит спавна, лишнего процесса и мусорного отказа вендора вместо своего. Форма другая: **`sudo -n -l -u <user> <бинарь>` ПОКАЗЫВАЕТ правило, а не берёт его.** Код возврата 0 — правило есть, иначе нет; сессия при этом не поднимается.

Два следствия, оба намеренные:

- **слова пробы едут в отказ дословно.** «Правила нет» и «`sudo` не установлен» — два разных ремонта, и различить их может только проба; отказ, придумавший причину за неё, отправил бы чинить не то;
- **отказ теперь различает «спросили и получили нет» и «не спрашивали».** `status` и схемные тесты судят карточку, не собираясь её поднимать; сказать им «этот ящик не даёт» значило бы предъявить замер, которого не было — ровно класс дисциплины 5. Они получают «this run did not ask the box for it».

Проба идёт ТОЛЬКО для роли, чьё объявление расходится с текущим пользователем — то есть сегодня ни для одной. Путь, спавнящий `sudo` на каждом такте ради «ничего не изменилось», был бы налогом всех ролей ради одной.

`-n` стоит и на пробе, и на самом запуске: твой довод («без него отказ превращается в ожидание пароля») на пробе бьёт сильнее — там повис бы такт демона.
