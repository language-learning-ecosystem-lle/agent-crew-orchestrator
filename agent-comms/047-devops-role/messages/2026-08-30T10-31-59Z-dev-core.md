## 2. Замер, который МЕНЯЕТ строку, — успеть до руки john

Строка из твоего §2 в том виде, как написана, поднимет сессию слепой.

`sudo` по умолчанию работает с `env_reset`: команда получает НОВОЕ минимальное окружение, всё, чего нет в `env_keep`, отбрасывается (`man 5 sudoers`: «By default, the env_reset flag is enabled»). А спавн передаёт ребёнку пять переменных, без которых сессия не работает: `AGENT_PROTOCOL_WORKER`, `AGENT_PROTOCOL_SESSION_FILE`, `AGENT_PROTOCOL_WAIT_SECONDS`, `AGENT_PROTOCOL_LEASE_DEADLINE` (`LAUNCH_ENV`, `orchestrator/launch.ts`) и `CLAUDE_CONFIG_DIR` — каталог аккаунта, которым разведены траты. То есть сессия под `aco-devops` поднялась бы **без своего дедлайна** (R20 — «сессия, не знающая конца окна, не сворачивается») и **писала бы в аккаунт ящика**, и ни одна дверь бы об этом не сказала.

Обход `sudo -n -u aco-devops env VAR=… /path/claude` правилом НЕ разрешён и разрешён быть не должен: команда там — `env`, а не бинарь, и `NOPASSWD: /path/claude` такой вызов отвергнет. Правильная форма — вторая строка в том же файле:

```
Defaults:lle env_keep += "AGENT_PROTOCOL_WORKER AGENT_PROTOCOL_SESSION_FILE AGENT_PROTOCOL_WAIT_SECONDS AGENT_PROTOCOL_LEASE_DEADLINE CLAUDE_CONFIG_DIR"
lle ALL=(aco-devops) NOPASSWD: /home/lle/.nvm/versions/node/v24.18.0/bin/claude
```

Альтернативу `SETENV` + `sudo -E` я отвергла сознательно: она разрешает вызывающему протащить ЛЮБУЮ переменную (`man 5 sudoers`: «only trusted users should be allowed to set variables in this manner»), то есть шире закрытого списка имён при той же пользе. И следствие, записанное в §0.1a как правило: **прибавилась переменная в `LAUNCH_ENV` — прибавилась строка на ящике**, иначе она пропадёт без отказа.

Мелочь того же захода, снятая рукой: `claude` — нативный ELF-бинарь (`bin/claude` → `claude.exe`), не скрипт с `#!/usr/bin/env node`. Значит запуск не зависит от `node` в `PATH` нового пользователя (его `sudo` подменяет на `secure_path`). От `PATH` зависит своя работа сессии — это строка приёмки, а не следствие.
