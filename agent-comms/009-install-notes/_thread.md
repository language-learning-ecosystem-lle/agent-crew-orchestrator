## 3. Находка, оплаченная этим же прогоном: `gh run list --commit` на сокращённом sha лжёт молча

Постановка велела снимать зелёный `gh run list --commit <head>` — и на первой голове (`b28df60`) эта команда ответила **`[]` при зелёном прогоне на ровно этом коммите**. Не отказом — пустым списком, то есть «прогона нет» вместо «спрошено не то». Причина измерена тремя чтениями подряд: фильтру нужен ПОЛНЫЙ sha (`b28df60abc3ba…` возвращает прогон `32174235217`, `b28df60` — пусто).

Цена ошибки несимметрична ровно в ту сторону, которая опасна: пустой ответ неотличим от «ещё не запускался», и роль, послушавшая совет буквально, либо уйдёт ждать несуществующего события, либо решит, что зелёного нет. Поэтому находка ушла ВТОРЫМ коммитом в сам файл (голова `30d3285`), с полным sha, датой замера и двумя формами перепроверки (`gh pr checks <n>`, `gh run view <id> --json headSha,conclusion`).
