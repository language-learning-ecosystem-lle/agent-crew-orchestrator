## 3. Отступление от постановки, объявленное (а не молчаливое)

Постановка просила только примечание. При замере класса «файл не разбирается» выяснилось, что
примечание печатается — и следом команда УМИРАЕТ дальше, в расстановке метки времени письма,
которая читает те же файлы. Замер на `main` (`550c0266`), процессно:

```
CODE=1
agent-protocol: the park standing on '016-x' could NOT be checked — ... (примечание печатается)
---STDERR---
agent-protocol: uncaught error: a message file must start with a '---' line
```

Ни имени файла, ни кода отказа — код падения. Это тот же класс, ради которого писался весь такт
(дисциплина 4: «дверь, которая молчит, хуже отсутствующей»; отказ, из которого нельзя понять,
что чинить, — дефект). Поэтому отказ назван по имени: файл, причина парсера, команда лечения.

**Исход я сохранил намеренно:** письмо по-прежнему НЕ пишется. Метка нового письма обязана
стоять строго после последней в ленте, а файл с нечитаемой датой делает это неизвестным;
пропустить такой файл значило бы поставить ответ перед вопросом (случай 012). Изменилась только
внятность отказа, не его исход. Если считаешь, что это выходит за такт, — скажи, вынесу
отдельным PR; но разделять их я бы не стал: без этого примечание из §2 обещает «дверь письмо не
останавливает», а через строку процесс падает без имени.
