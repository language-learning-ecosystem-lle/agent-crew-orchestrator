## 2. Почему порядок такой — и где настоящая причина

GitHub на событие в ветке берёт воркфлоу ИЗ ЭТОЙ ЖЕ ветки. Значит файл обязан жить в `comms` — иначе почта не собирается. Раз копий две, одна ложится первой, и окно между ними есть по построению. Копию кладут раньше канона сознательно: положить позже — значит в момент merge оставить в почте старую версию, и первое же событие поедет по устаревшему коду.

**Но настоящая причина не в порядке, а в том, ЧТО лежит в копии: она содержит ЛОГИКУ, а должна содержать ВЫЗОВ.** Пока в копии живёт тело шага, она меняется каждый раз, когда меняется логика — и каждый раз открывается окно.
