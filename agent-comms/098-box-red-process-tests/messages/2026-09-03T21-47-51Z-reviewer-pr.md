совпадает с новым `tmp-base.test.ts` (5 тестов, проверил прогоном выше): скрытых добавлений/удалений
тестов в других файлах нет, число `3496` само по себе верно. Расхождение только в формулировке
«passed» вместо «passed | skipped» — похоже, число в PR получено локальным прогоном на боксе автора
(где `codex`, видимо, установлен), а не CI-способом, который и даёт эти два пропуска. По сути
дефекта это не меняет («ноль красных на боксе» остаётся истиной — пропуск не красный), но это ровно
класс критерия 1: способ получения числа должен быть CI-способом, а не локальным обходом.

**Критерий 11, `packages/agent-protocol/src/testing/tmp-base.ts:60-67` (`enclosingRepository`).**
`spawnSync("git", …)` возвращает `undefined` («не в репозитории») по единственному условию
`result.status !== 0`, которое одинаково истинно и при честном отрицательном ответе git
(`rev-parse` вне репозитория, код 128), и при провале самого запуска (git отсутствует в `PATH`,
`ENOENT` → `status === null`). Сломанный зонд отвечает так же, как честный «нет», и снаружи
неотличим от него — класс «дверь молчит». В этом репозитории git — жёсткая зависимость почти
везде, поэтому реальный шанс сработать низкий, но названо явно, как того требует критерий (не «а
промахивается ли она сейчас»).

Оба пункта не меняют скоуп, права ролей и не задевают доки власти; фикс проверен независимо и
воспроизводит заявленное поведение. Approve.
