## Решение формы — и почему не «просто два файла секретов»

Соблазнительный нулевой вариант: развести `secrets.envFile` по инстансам (механизм уже есть, кода не надо вовсе). **Отвергаю, и довод один, несущий:** дефект, который мы чиним, — не «неудобно», а **молчаливость по построению**. При разносе по файлам коллизия переезжает ЧЕРЕЗ файлы: процесс загружает только свой, второго не видит никогда, и «оба конфига смотрят на один URL» остаётся состоянием, которое **нечем отказать**. Тот же класс, только теперь размазанный по двум файлам, где его ещё труднее заметить глазом. Плюс побочно: `TELEGRAM_*`/`EXPO_TOKEN` придётся дублировать, и они разъедутся.

**Выбранная форма — суффикс имени инстанса в ОДНОМ файле.** Она держит два монитора в одном месте, где их видно рядом, и делает совпадение **проверяемым внутри процесса** — то есть отказуемым по имени, ровно как уже отказано переиспользование URL ящика.

Правило целиком (три случая, четвёртый — миграция):

1. **Ответил ИМЕНОВАННЫЙ конфиг инстанса** (`instances/<name>.json`) и суффиксный ключ есть → бьём по нему. Суффикс — имя инстанса в UPPER_SNAKE (`hetzner` → `HEALTHCHECKS_CIRCUIT_URL_HETZNER`, `lle-hetzner` → `HEALTHCHECKS_CIRCUIT_URL_LLE_HETZNER`).
2. **Ответил именованный конфиг, суффиксного ключа НЕТ, а голый `HEALTHCHECKS_CIRCUIT_URL` есть** → сторож **выключен**, и причина стоит в баннере с ИМЕНЕМ ожидаемого ключа. Это не «фолбэк не сработал» — это ровно та конфигурация, которую мы чиним, и молчаливо съедать её нельзя: голый ключ на многоинстансовом ящике и есть коллизия.
3. **Ответил БЕЗЫМЯННЫЙ `local.json`** (ящик с одним инстансом) → голый `HEALTHCHECKS_CIRCUIT_URL`, поведение **байт в байт как сегодня**. Ящик без `instances/` не должен заметить этой правки вообще.
4. **Миграция без окна молчания:** именованный конфиг, есть и суффиксный, и голый → выигрывает суффиксный, голый назван в баннере ОДНОЙ строкой как проигнорированный. Это даёт john порядок без дыры: ключи кладутся ЗАРАНЕЕ, старый код (загруженный в живой процесс) продолжает читать голый, новый после рестарта читает суффиксный, голый удаляется потом на досуге.

**Плюс один отказ сверх этого, и он — сердце правки:** сегодня код отказывает, если значение совпало с `HEALTHCHECKS_URL` (монитор ящика). Обобщить: **отказ, если значение циркулярного ключа совпало со значением ЛЮБОГО другого ключа этого же файла секретов** — по имени обоих ключей, без значения. Именно это ловит человеческую руку, вставившую один и тот же URL под два инстанса; существующий отказ становится частным случаем общего, а не отдельной веткой.

**Имя ключа не переименовываю в cronitor-нейтральное** (ваш необязательный пункт). Довод: ключ ЯЩИКА остаётся `HEALTHCHECKS_URL` и этой постановкой не трогается, а вся читаемость темы держится на том, что два монитора — пара одной формы. Разведи их по префиксам — и через полгода никто не прочтёт их как двух сторожей одного ящика. Сервис пингеру и правда безразличен (голый GET); историчность имени дешевле потери пары.

Скоуп:

1. **Разрешение ключа по имени инстанса** — правило 1–4 выше, целиком. Имя инстанса берётся ОТТУДА ЖЕ, откуда демон уже знает, какой конфиг ему ответил (`instanceName` резолвера машинного конфига), а не из нового флага: то, какой это инстанс, — факт ящика, и второго ответа на него быть не должно.
2. **Нормализация имени в суффикс** — UPPER_SNAKE, `-` → `_`. Имя, из которого не получается легального имени ключа, — **отказ по имени** (баннер, сторож выключен), а не молчаливая замена символов.
3. **Обобщённый отказ на совпадение значения** — с любым другим ключом того же файла, в строке только ИМЕНА ключей. Существующий отказ на `HEALTHCHECKS_URL` становится его частным случаем (и остаётся названным отдельной формулировкой, если так яснее оператору).
4. **Доки тем же коммитом**: шапка `watchdog.ts` (почему суффикс, а не файл на инстанс — довод «коллизия через файлы неотказуема»), `docs/box-setup.md` §7a (порядок для john, включая миграцию без окна молчания), `packages/agent-protocol/README.md`, `docs/protocol-reference.md`.
