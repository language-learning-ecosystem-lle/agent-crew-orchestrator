# Постановка `dev-core`: промпт подъёма печатает непишущей роли форму почты, которая под её песочницей отказывает с первой команды

**Первым предметом после решения john 30.08 («ЖИВЁТ, TERRA/MAX, ЧИНИТЕ ПРОМПТ», тред `038-pilot-codex-live-run`, доставка полем `delivers` ~14:03Z).** Тред заведён сессией `curator` (не чатной рукой) — второго дома этому предмету заводить не надо.

## 1. Дефект — одной строкой

Промпт подъёма печатает роли строку чтения почты **без `--no-fetch` и без `--repo`**. Для роли, поднимаемой под `launch.agent.toolsHeldBy: "sandbox-read-only"`, эта строка не работает **по построению**: `--ref` с префиксом `origin/` тянет обновление конфига (`fetchRef`, `packages/agent-protocol/src/fs/git.ts`), а сети и записи у такой роли нет — `exit 2` на первой же команде. Единственная работа роли — чтение треда — умирает раньше, чем начинается.

## 2. Первоисточник замера — лента, дата, номер треда

Тред `038-pilot-codex-live-run`, письмо `2026-08-30T13-52-34Z-curator.md`, §2 и §6. Два прогона одной и той же постановки, оба 30.08:

| | прогон 9 (`gpt-5.6-terra`/`max`) | прогон 9-бис (та же модель) |
|---|---|---|
| окно | `13:46:44Z → 13:47:34Z`, 50 с, `completed`, `exitCode 0` | `13:49:49Z → 13:50:48Z`, 59 с, `completed`, `exitCode 0` |
| команд за прогон | **одна** — форма из ПРОМПТА → `exit 2` | две: форма промпта → `exit 2`, затем форма карточки → `exit 0` |
| результат | лента не прочитана вовсе, ноль из пяти пунктов постановки | лента прочитана (155 812 символов), пять пунктов из пяти |
| журнал | `.orchestrator/sessions/2026-08-30T13-46-43Z-pilot-codex-038-pilot-codex-live-run.jsonl` | `.orchestrator/sessions/2026-08-30T13-49-49Z-pilot-codex-038-pilot-codex-live-run.jsonl` |

Разницу между ними дала **не модель**: в 9-бис постановка назвала рабочую форму руками, отдельным блоком. Раньше, на `gpt-5.4-mini`/`low` (прогон 8), тот же отказ стоил **трети прогона** — роль после `exit 2` догадалась открыть свою карточку и вышла вторым заходом. На сильной модели цена **выросла до прогона целиком**: `gpt-5.6-terra` пошла строго по промпту, получила отказ и честно остановилась, как велит постановка. Это и есть цена дефекта, и она измерена дважды, а не выведена.

Оговорка, чтобы её не потеряли: «терра не пошла в обход» — **не диагноз о модели** и в постановку не входит. Входит другое: пока промпт печатает неверную форму, стенд упирается в него раньше, чем в исполнителя.

## 3. Где это в коде — перегреплено по содержанию, не по номерам строк

- `packages/agent-protocol/src/orchestrator/launch.ts`, функция `mailCall` — собирает строку из `[command, subcommand, --root, --ref, args]` и ничего больше;
- значение префикса — `mailCommand` в `agent-protocol.json` (`node --import tsx packages/agent-protocol/src/cli.ts`), приехало с v25 (PR #131, тот же тред `038`);
- рабочая форма, которой у промпта нет, объявлена в карточке роли (`docs/roles/pilot-codex.md`, §«Что роль делает», п. 3) и там же обоснована пофлажно: `--no-fetch` — потому что иначе `fetchRef` даёт отказ, а не устаревание; `--repo <рабочее дерево роли>` — потому что без него репозиторий конфига выводится из каталога `--root`, то есть **из чекаута почты, а не из рабочего дерева роли** (`configFrom` → `repoOf(root)` в `cli.ts`); на этом контуре оба дерева случайно дают один `origin/main`, но роль не обязана это знать, а карточка не объявляет механизмов, которых нет.

## 4. Что требуется

**Строка чтения почты в промпте подъёма роли, у которой объявлено `launch.agent.toolsHeldBy: "sandbox-read-only"`, печатается с `--no-fetch` и с `--repo <рабочее дерево этой роли>`.**

Три ограничения, и они несущие:

1. **Оба значения ВЫВОДЯТСЯ из того, что конфиг уже объявляет** — `toolsHeldBy` (v20, тред `026`) и рабочее дерево роли (`workdir.worktrees/<role id>`). Новых ключей, полей и версии схемы этот предмет не покупает: ровно та же логика, которой v25 уже вывела «непишущей роли названа её концовка». Понадобился новый ключ — значит, разошлись с постановкой, и это повод вернуться в тред, а не расширять схему молча;
2. **Роль без этого поля получает сегодняшнюю строку без единого изменения** — это регрессия, которую надо закрыть тестом явно: `claude-code`-роли (`curator`, `dev-core`, `reviewer-pr`) ходят в сеть, и `--no-fetch` им не нужен и вреден;
3. **Карточка роли — не предмет этого треда.** Она уже несёт верную форму; чинится промпт, чтобы роль не зависела от того, догадается ли она открыть карточку после отказа.

## 5. Проверяемость

**Юниты** (`packages/agent-protocol/src/orchestrator/launch.test.ts` — там уже лежит набор v25):

- промпт роли с `toolsHeldBy: "sandbox-read-only"` содержит `--no-fetch` и `--repo` с путём рабочего дерева ИМЕННО ЭТОЙ роли;
- значение `--repo` взято из объявленного рабочего дерева, а не собрано из `--root` (тест ставит два разных пути и смотрит, какой приехал);
- промпт роли БЕЗ этого поля не изменился ни на символ против сегодняшнего (регрессия п. 4.2);
- роль, у которой поле объявлено, а рабочее дерево в конфиге НЕ объявлено: строка печатается без выдуманного пути — отсутствующий факт остаётся отсутствующим, как это уже сделано для `command`/`root`/`ref` в `mailCall`.

**Живая приёмка — моя рука, не dev-core, и без неё предмет не закрывается.** Прогон `orchestrator run --role pilot-codex --thread <тред> --model gpt-5.6-terra --effort max` с постановкой **дословно той формы, что в прогонах 6–8** — то есть БЕЗ блока «Форма чтения», которым 9-бис обошла дефект руками. Принимается по одному числу: «команд до первой успешной печати ленты» = **1** (было 2 в 9-бис и «лента не прочитана» в 9), и пять пунктов из пяти. Это единственная проверка, которая отличает починку от правки текста промпта.

**Что сознательно НЕ покрывается:**

- поведение под другими песочницами и другими вендорами — измерен только codex под `--sandbox read-only`; переносить вывод на будущие профили нечем;
- свежесть почты у непишущей роли: она печатает тред таким, каким его оставил на диске демон. Это возраст чекаута (`behind`), отдельная величина, и к этому дефекту отношения не имеет;
- цена прогона в токенах: она замерена (`input 62111` на 9-бис против `76745` на прогоне 8), но приёмкой этого предмета не является — число зависит от длины ленты, а она растёт.
