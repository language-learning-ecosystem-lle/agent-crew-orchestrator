# agent-protocol

Файловый протокол координации автономных агентов поверх git: роли и права,
операции над тредами и реестром, вахта/пробуждение/уведомления, инициализация
на новом проекте.

**Статус: фаза P0 (спайк), тред `012-agent-protocol-package`.** Пакета как кода
ещё нет — есть доказательство модели исполнения (`spike/`). Каркас, конфиг
ролей как данные, операции-как-API и исполнительный слой — фазы P1–P5.

## Дисциплина выносимости

Пакет живёт в этом монорепо, но **проектируется как чужой**: он уедет в
отдельный репозиторий и будет переиспользоваться на других проектах. Отсюда
жёсткие правила с первого коммита:

- нейтральное имя (`agent-protocol`, не `lle-*`);
- **ноль знания о проекте**: ни одного импорта из `apps/*`, ни упоминания
  предметной области — всё проектное приходит через конфиг СНАРУЖИ пакета;
- транспорт уведомлений (Telegram и пр.) — **отдельный пакет**, ядро о нём не
  знает: ядро порождает события, доставка их — подключаемый плагин;
- бэкенд хранилища — за интерфейсом: `git-local` (агенты, CI) и `github-api`
  (писатель без чекаута) нужны с первого дня, у обоих есть живые потребители;
- переезд должен быть механическим (`git subtree split` + замена
  workspace-зависимости на версию из реестра).

## `spike/` — P0

`headless-cycle.sh` доказывает, что headless-агент (`claude -p`) проходит
полный цикл протокола на изолированном стенде: читает тред, дописывает секцию,
перегенерирует реестр, коммитит и пушит, выходит кодом. Результат и выводы —
`spike/RESULT.md`. Спайк работает только в песочнице `$TMPDIR` и не касается
боевого контура.
